# Control flow — Advanced

In Rust almost everything is an **expression**. That's where the typing rules for `if`, blocks and loops come from, along with the way control flow composes.

## Blocks are expressions

A block `{ ... }` has the value of its last expression, as long as that expression doesn't end in `;`. A `;` turns the expression into a statement, and the block ends up with the value `()`:

```rust
fn main() {
    let x = {
        let a = 3;
        let b = 4;
        a * a + b * b // no `;`: the value of the block
    };
    println!("{x}");
}
```

```rust,compile_fail
fn main() {
    let x: i32 = {
        let a = 3;
        a * a; // `;` makes the block return ()
    }; // error E0308: expected i32, found ()
}
```

## The types of `if`, `loop` and `while`

- `if` without `else` has type `()`, so its branch must return `()`.
- `while` and `for` always have type `()`, because they might never run.
- `loop` has the type of the value in `break`. If it has no `break`, its type is `!` and it never finishes.
- `break`, `continue` and `return` have type `!`, so they can appear wherever a value is expected:

```rust
fn main() {
    let values = ["3", "x", "7"];
    let mut sum = 0;
    for v in values {
        let n: i32 = match v.parse() {
            Ok(n) => n,
            Err(_) => continue, // `!` fits i32
        };
        sum += n;
    }
    println!("{sum}");
}
```

## Breaking out of a labeled block

Since Rust 1.65, `break` also works on an ordinary labeled block, not just on loops. That way you can exit early from a sequence of checks without writing a separate function:

```rust
fn main() {
    let input = "42";
    let message = 'validation: {
        if input.is_empty() {
            break 'validation "empty";
        }
        if input.parse::<u32>().is_err() {
            break 'validation "not a number";
        }
        "valid"
    };
    println!("{message}");
}
```

## Let chains (2024 edition)

Since Rust 1.88, in the 2024 edition, you can combine `if let` and ordinary conditions with `&&`. Variables bound earlier can be used in the conditions that follow:

```rust
fn main() {
    let config: Option<&str> = Some("8080");
    if let Some(text) = config
        && let Ok(port) = text.parse::<u16>()
        && port >= 1024
    {
        println!("valid port: {port}");
    }
}
```

Without let chains, this would have taken three levels of nested `if`.

## How `for` is translated

`for` isn't a separate construct. The compiler turns it into a `loop` that asks an iterator for the next element:

```rust
fn main() {
    let v = vec![10, 20, 30];

    // for x in &v { println!("{x}"); } becomes roughly:
    let mut iter = IntoIterator::into_iter(&v);
    loop {
        match iter.next() {
            Some(x) => println!("{x}"),
            None => break,
        }
    }
}
```

As a result, `for` works on any type that implements `IntoIterator`, including your own types (see the Closures and iterators chapter).

## Guards in `match`

A `match` can have extra conditions (`if`) on each branch. The exhaustiveness check doesn't take guards into account, so you still need a final branch:

```rust
fn main() {
    let n = -4;
    let description = match n {
        0 => "zero",
        x if x < 0 && x % 2 == 0 => "negative even",
        x if x < 0 => "negative odd",
        _ => "positive",
    };
    println!("{description}");
}
```

> **Key takeaway:** blocks, `if`, `match` and `loop` produce values. `;` changes the type to `()`. `break`/`continue`/`return` have type `!`. `for` is really a `loop` over an iterator.

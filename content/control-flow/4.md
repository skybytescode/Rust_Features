# Control flow — Expert

Cum ajunge control flow-ul în MIR și în codul mașină, plus regulile subtile despre durata de viață a valorilor temporare, schimbate în ediția 2024.

## În MIR există doar blocuri și salturi

`if`, `while`, `for`, `match` și `?` dispar înainte de generarea codului. MIR (Mid-level IR) are doar **blocuri de bază** unite prin terminatori: `goto`, `switchInt` (salt după o valoare întreagă), `return`, `call`, `drop`. De exemplu, `while cond { corp }` devine:

```rust
fn main() {
    let mut i = 0;
    // while i < 3 { i += 1; } este tradus ca:
    loop {
        if i < 3 {
            i += 1;
        } else {
            break;
        }
    }
    println!("{i}");
}
```

Poți vedea MIR-ul oricărui program în Rust Playground: butonul „...” de lângă „Run”, apoi **MIR**. Sau local cu `rustc -Z unpretty=mir` (doar pe nightly).

## Cum e compilat un `match`

Compilatorul transformă pattern-urile într-un **arbore de decizie**, apoi LLVM alege implementarea. Pentru valori dense (de exemplu `0..=10`), alege de obicei un **jump table**: un singur salt indexat. Pentru valori rare, alege comparații în cascadă sau căutare binară. Ordinea ramurilor contează doar semantic (prima care se potrivește câștigă), nu și pentru performanță, cu o excepție: ramurile cu guard se evaluează în ordine.

## Bounds checks și bucle

`v[i]` verifică limitele la fiecare acces. Cu iteratori, verificarea dispare, pentru că iteratorul știe singur unde se termină. Cu indecși, LLVM poate elimina verificarea doar dacă demonstrează că `i < v.len()`:

```rust
pub fn suma_index(v: &[u64]) -> u64 {
    let mut s = 0;
    for i in 0..v.len() {
        s += v[i]; // LLVM vede `i < v.len()` și elimină verificarea
    }
    s
}

pub fn suma_doua(a: &[u64], b: &[u64]) -> u64 {
    let mut s = 0;
    for i in 0..a.len() {
        s += a[i] * b[i]; // `b[i]` păstrează verificarea: nimic nu garantează `b.len() >= a.len()`
    }
    s
}

pub fn suma_doua_rapid(a: &[u64], b: &[u64]) -> u64 {
    let b = &b[..a.len()]; // o singură verificare, înainte de buclă
    let mut s = 0;
    for i in 0..a.len() {
        s += a[i] * b[i]; // acum ambele verificări pot fi eliminate
    }
    s
}

fn main() {
    let a = [1, 2, 3];
    println!("{} {} {}", suma_index(&a), suma_doua(&a, &a), suma_doua_rapid(&a, &a));
}
```

Varianta cu `a.iter().zip(b)` este cea idiomatică: are aceeași performanță și nu depinde de optimizator.

## Indicii pentru optimizator

- `#[cold]` pe o funcție îi spune compilatorului că apelurile ei sunt rare, așa că ramurile care duc la ea sunt mutate din calea principală. `panic!` folosește intern acest mecanism.
- `std::hint::black_box(x)` împiedică optimizatorul să „vadă prin” o valoare. E util în benchmark-uri.
- `std::hint::unreachable_unchecked()` declară o ramură imposibilă. Dacă ajungi totuși acolo, este **comportament nedefinit**, deci folosește-o doar cu o garanție dovedită.

```rust
#[cold]
#[inline(never)]
fn eroare_rara(cod: u32) -> ! {
    panic!("eroare internă {cod}");
}

fn imparte(a: u32, b: u32) -> u32 {
    if b == 0 {
        eroare_rara(1); // ramura marcată rece
    }
    a / b
}

fn main() {
    println!("{}", imparte(10, std::hint::black_box(2)));
}
```

## Durata temporarelor: ce s-a schimbat în ediția 2024

Valorile temporare create în condiția unui `if let` trăiau, înainte, până la sfârșitul **întregului** `if let`, inclusiv în ramura `else`. Asta producea panic-uri neașteptate cu `RefCell` sau `Mutex`. În ediția 2024, temporarele din condiție sunt distruse **înainte** de `else`:

```rust
use std::cell::RefCell;

fn main() {
    let cache = RefCell::new(None::<u32>);

    if let Some(v) = *cache.borrow() {
        println!("din cache: {v}");
    } else {
        // 2021: panic „already borrowed”, borrow() încă era activ aici
        // 2024: borrow() a fost eliberat înainte de else
        *cache.borrow_mut() = Some(42);
    }
    println!("{:?}", cache.borrow());
}
```

Tot în ediția 2024, temporarele din **expresia finală a unui bloc** sunt distruse înaintea variabilelor locale ale blocului. Înainte, codul de mai jos nu compila: temporarul `c.borrow()` trăia mai mult decât `c`, deci încerca să împrumute o valoare deja distrusă.

```rust
use std::cell::RefCell;

fn lungime() -> usize {
    let c = RefCell::new(String::from("salut"));
    c.borrow().len() // 2024: temporarul `Ref` e distrus înaintea lui `c`
}

fn main() {
    println!("{}", lungime());
}
```

`cargo fix --edition` marchează automat locurile unde comportamentul se schimbă la migrare.

> **De reținut:** în MIR tot control flow-ul devine blocuri de bază și salturi. Iteratorii elimină bounds checks fără ajutorul optimizatorului. Ediția 2024 scurtează durata temporarelor din `if let` și din expresiile finale ale blocurilor.

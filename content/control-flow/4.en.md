# Control flow — Expert

How control flow ends up in MIR and in machine code, plus the subtle rules about how long temporary values live, which changed in the 2024 edition.

## MIR has only blocks and jumps

`if`, `while`, `for`, `match` and `?` disappear before code generation. MIR (Mid-level IR) has only **basic blocks** connected by terminators: `goto`, `switchInt` (a jump based on an integer value), `return`, `call`, `drop`. For example, `while cond { body }` becomes:

```rust
fn main() {
    let mut i = 0;
    // while i < 3 { i += 1; } is translated as:
    loop {
        if i < 3 {
            i += 1;
        } else {
            break;
        }
    }
    println!("{i}");
}
```

You can see the MIR of any program in Rust Playground: the "..." button next to "Run", then **MIR**. Or locally with `rustc -Z unpretty=mir` (nightly only).

## How a `match` is compiled

The compiler turns the patterns into a **decision tree**, and LLVM then chooses the implementation. For dense values (for example `0..=10`), it usually picks a **jump table**: a single indexed jump. For sparse values, it picks cascading comparisons or binary search. The order of the branches matters only semantically (the first one that matches wins), not for performance, with one exception: branches with guards are evaluated in order.

## Bounds checks and loops

`v[i]` checks the bounds on every access. With iterators, the check disappears, because the iterator knows on its own where it ends. With indexes, LLVM can remove the check only if it proves that `i < v.len()`:

```rust
pub fn sum_index(v: &[u64]) -> u64 {
    let mut s = 0;
    for i in 0..v.len() {
        s += v[i]; // LLVM sees `i < v.len()` and removes the check
    }
    s
}

pub fn sum_two(a: &[u64], b: &[u64]) -> u64 {
    let mut s = 0;
    for i in 0..a.len() {
        s += a[i] * b[i]; // `b[i]` keeps its check: nothing guarantees `b.len() >= a.len()`
    }
    s
}

pub fn sum_two_fast(a: &[u64], b: &[u64]) -> u64 {
    let b = &b[..a.len()]; // a single check, before the loop
    let mut s = 0;
    for i in 0..a.len() {
        s += a[i] * b[i]; // now both checks can be removed
    }
    s
}

fn main() {
    let a = [1, 2, 3];
    println!("{} {} {}", sum_index(&a), sum_two(&a, &a), sum_two_fast(&a, &a));
}
```

The `a.iter().zip(b)` version is the idiomatic one: it has the same performance and doesn't depend on the optimizer.

## Hints for the optimizer

- `#[cold]` on a function tells the compiler that calls to it are rare, so the branches leading to it are moved off the main path. `panic!` uses this mechanism internally.
- `std::hint::black_box(x)` prevents the optimizer from "seeing through" a value. It's useful in benchmarks.
- `std::hint::unreachable_unchecked()` declares a branch impossible. If you do reach it, that's **undefined behavior**, so use it only with a proven guarantee.

```rust
#[cold]
#[inline(never)]
fn rare_error(code: u32) -> ! {
    panic!("internal error {code}");
}

fn divide(a: u32, b: u32) -> u32 {
    if b == 0 {
        rare_error(1); // the branch marked cold
    }
    a / b
}

fn main() {
    println!("{}", divide(10, std::hint::black_box(2)));
}
```

## How long temporaries live: what changed in the 2024 edition

Temporary values created in the condition of an `if let` used to live until the end of the **entire** `if let`, including the `else` branch. That caused unexpected panics with `RefCell` or `Mutex`. In the 2024 edition, temporaries from the condition are destroyed **before** the `else`:

```rust
use std::cell::RefCell;

fn main() {
    let cache = RefCell::new(None::<u32>);

    if let Some(v) = *cache.borrow() {
        println!("from cache: {v}");
    } else {
        // 2021: panic "already borrowed", borrow() was still alive here
        // 2024: borrow() was released before the else
        *cache.borrow_mut() = Some(42);
    }
    println!("{:?}", cache.borrow());
}
```

Also in the 2024 edition, temporaries in the **tail expression of a block** are destroyed before the block's local variables. Previously the code below didn't compile: the temporary `c.borrow()` lived longer than `c`, so it tried to borrow a value that had already been destroyed.

```rust
use std::cell::RefCell;

fn length() -> usize {
    let c = RefCell::new(String::from("hello"));
    c.borrow().len() // 2024: the `Ref` temporary is destroyed before `c`
}

fn main() {
    println!("{}", length());
}
```

`cargo fix --edition` automatically flags the places where behavior changes during migration.

> **Key takeaway:** in MIR all control flow becomes basic blocks and jumps. Iterators remove bounds checks without help from the optimizer. The 2024 edition shortens the lifetime of temporaries in `if let` and in block tail expressions.

# Modules and Cargo — Advanced

How the compiler resolves paths, what's in the prelude, how editions work, plus build scripts, conditional compilation and profiles.

## Absolute and relative paths

| Start of the path | Starts from |
|---|---|
| `crate::` | the root of the current crate |
| `super::` | the parent module |
| `self::` | the current module |
| `crate_name::` | an external crate (dependency) |

```rust
mod network {
    pub fn address() -> &'static str { "127.0.0.1" }

    pub mod http {
        pub fn url() -> String {
            format!("http://{}:{}", super::address(), crate::config::PORT)
        }
    }
}

mod config {
    pub const PORT: u16 = 8080;
}

fn main() {
    println!("{}", network::http::url());
}
```

## The prelude

Some names are available without `use`, because they're in the **prelude**: `Option`, `Some`, `None`, `Result`, `Ok`, `Err`, `Vec`, `String`, `Box`, the traits `Clone`, `Copy`, `Iterator`, `IntoIterator`, `From`, `Into`, `Drop`, `Fn*` and others. Each edition can add names: 2021 added `TryFrom`, `TryInto` and `FromIterator`, and 2024 added `Future` and `IntoFuture`.

## Editions

An **edition** (2015, 2018, 2021, 2024) changes surface rules of the language: new keywords, the prelude, the lifetime of temporaries. It doesn't change compatibility between crates, though. A 2024-edition crate can use a 2015 dependency without any problem.

Migration is mostly automatic:

```bash
cargo fix --edition      # adapts the code to the next edition
# then you change `edition` in Cargo.toml
```

## Conditional compilation

`cfg` includes or excludes code at compile time, depending on the platform, features or your own options:

```rust
#[cfg(target_os = "linux")]
fn platform() -> &'static str { "Linux" }

#[cfg(target_os = "windows")]
fn platform() -> &'static str { "Windows" }

#[cfg(not(any(target_os = "linux", target_os = "windows")))]
fn platform() -> &'static str { "another platform" }

fn main() {
    println!("{}", platform());
    if cfg!(debug_assertions) {
        println!("debug build");
    }
    println!("{}-bit pointers", if cfg!(target_pointer_width = "64") { 64 } else { 32 });
}
```

`#[cfg(...)]` removes the code completely, so excluded code isn't even type-checked. `cfg!(...)` is a `bool` expression: both branches must compile.

## Build scripts

A `build.rs` file at the root of the package runs **before** compilation. You use it to generate code, compile C code or detect system libraries. It talks to Cargo through lines printed to stdout:

```rust,ignore
// build.rs
fn main() {
    // rebuild only when the file changes
    println!("cargo::rerun-if-changed=schema.txt");

    // define a custom cfg, used with #[cfg(has_schema)]
    println!("cargo::rustc-check-cfg=cfg(has_schema)");
    println!("cargo::rustc-cfg=has_schema");

    // generate code in OUT_DIR, then included with include!
    let out = std::env::var("OUT_DIR").unwrap();
    std::fs::write(format!("{out}/generated.rs"), "pub const VERSION: u32 = 3;").unwrap();
}
```

```rust,ignore
// src/main.rs
include!(concat!(env!("OUT_DIR"), "/generated.rs"));
```

## `dev-dependencies` and `build-dependencies`

```toml
[dependencies]          # for the main code
serde = "1"

[dev-dependencies]      # only for tests, examples and benchmarks
proptest = "1"

[build-dependencies]    # only for build.rs
cc = "1"
```

## Profiles

Profiles control the compilation options:

```toml
[profile.release]
opt-level = 3         # 0–3, "s" or "z" (size)
lto = "thin"          # link-time optimization
codegen-units = 1     # slower to compile, better code
panic = "abort"       # no unwinding: smaller binary
strip = true          # removes debug symbols

[profile.dev.package."*"]
opt-level = 2         # dependencies optimized even in debug
```

The last block is a useful trick for games and number crunching: your own code stays fast to compile, and the heavy dependencies run fast.

> **Key takeaway:** `crate::`, `super::` and `self::` give clear paths. Editions change only the surface of the language and are compatible with each other. `#[cfg]` removes code, while `cfg!` only tests it. `build.rs` runs before compilation, and profiles control optimization.

# Module și Cargo — Avansat

Cum rezolvă compilatorul căile, ce e în prelude, cum funcționează edițiile, plus build scripts, compilarea condiționată și profilurile.

## Căi absolute și relative

| Începutul căii | Pornește de la |
|---|---|
| `crate::` | rădăcina crate-ului curent |
| `super::` | modulul părinte |
| `self::` | modulul curent |
| `nume_crate::` | un crate extern (dependență) |

```rust
mod retea {
    pub fn adresa() -> &'static str { "127.0.0.1" }

    pub mod http {
        pub fn url() -> String {
            format!("http://{}:{}", super::adresa(), crate::config::PORT)
        }
    }
}

mod config {
    pub const PORT: u16 = 8080;
}

fn main() {
    println!("{}", retea::http::url());
}
```

## Prelude

Unele nume sunt disponibile fără `use`, pentru că se află în **prelude**: `Option`, `Some`, `None`, `Result`, `Ok`, `Err`, `Vec`, `String`, `Box`, trait-urile `Clone`, `Copy`, `Iterator`, `IntoIterator`, `From`, `Into`, `Drop`, `Fn*` și altele. Fiecare ediție poate adăuga nume: 2021 a adăugat `TryFrom`, `TryInto` și `FromIterator`, iar 2024 a adăugat `Future` și `IntoFuture`.

## Ediții

O **ediție** (2015, 2018, 2021, 2024) schimbă reguli de suprafață ale limbajului: cuvinte cheie noi, prelude, durata temporarelor. Nu schimbă însă compatibilitatea dintre crate-uri. Un crate din ediția 2024 poate folosi fără probleme o dependență din 2015.

Migrarea e în mare parte automată:

```bash
cargo fix --edition      # adaptează codul la ediția următoare
# apoi schimbi `edition` în Cargo.toml
```

## Compilare condiționată

`cfg` include sau exclude cod la compilare, după platformă, features sau opțiuni proprii:

```rust
#[cfg(target_os = "linux")]
fn platforma() -> &'static str { "Linux" }

#[cfg(target_os = "windows")]
fn platforma() -> &'static str { "Windows" }

#[cfg(not(any(target_os = "linux", target_os = "windows")))]
fn platforma() -> &'static str { "altă platformă" }

fn main() {
    println!("{}", platforma());
    if cfg!(debug_assertions) {
        println!("build de debug");
    }
    println!("pointer de {} biți", if cfg!(target_pointer_width = "64") { 64 } else { 32 });
}
```

`#[cfg(...)]` elimină codul complet, deci codul exclus nici măcar nu e verificat de tipuri. `cfg!(...)` este o expresie `bool`: ambele ramuri trebuie să compileze.

## Build scripts

Un fișier `build.rs` la rădăcina pachetului rulează **înainte** de compilare. Îl folosești ca să generezi cod, să compilezi cod C sau să detectezi biblioteci de sistem. Comunică cu Cargo prin linii afișate pe stdout:

```rust,ignore
// build.rs
fn main() {
    // recompilează doar când se schimbă fișierul
    println!("cargo::rerun-if-changed=schema.txt");

    // definește un cfg propriu, folosit cu #[cfg(are_schema)]
    println!("cargo::rustc-check-cfg=cfg(are_schema)");
    println!("cargo::rustc-cfg=are_schema");

    // generează cod în OUT_DIR, inclus apoi cu include!
    let out = std::env::var("OUT_DIR").unwrap();
    std::fs::write(format!("{out}/generat.rs"), "pub const VERSIUNE: u32 = 3;").unwrap();
}
```

```rust,ignore
// src/main.rs
include!(concat!(env!("OUT_DIR"), "/generat.rs"));
```

## `dev-dependencies` și `build-dependencies`

```toml
[dependencies]          # pentru codul principal
serde = "1"

[dev-dependencies]      # doar pentru teste, exemple și benchmark-uri
proptest = "1"

[build-dependencies]    # doar pentru build.rs
cc = "1"
```

## Profiluri

Profilurile controlează opțiunile de compilare:

```toml
[profile.release]
opt-level = 3         # 0–3, "s" sau "z" (dimensiune)
lto = "thin"          # optimizare la linkare
codegen-units = 1     # mai lent la compilare, cod mai bun
panic = "abort"       # fără unwinding: binar mai mic
strip = true          # elimină simbolurile de debug

[profile.dev.package."*"]
opt-level = 2         # dependențele optimizate și în debug
```

Ultimul bloc e un truc util pentru jocuri și calcule: codul tău rămâne rapid de compilat, iar dependențele grele rulează rapid.

> **De reținut:** `crate::`, `super::` și `self::` dau căi clare. Edițiile schimbă doar suprafața limbajului și sunt compatibile între ele. `#[cfg]` elimină cod, pe când `cfg!` doar îl testează. `build.rs` rulează înainte de compilare, iar profilurile controlează optimizarea.

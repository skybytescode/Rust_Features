# Module și Cargo — Practician

Cum organizezi un proiect real: bibliotecă plus binar, niveluri de vizibilitate, re-exporturi, versiuni și workspace-uri.

## Bibliotecă și binar în același proiect

Un pachet poate conține o bibliotecă (`src/lib.rs`) și unul sau mai multe binare. Logica stă în bibliotecă, iar `main.rs` doar o folosește. Structura asta face codul ușor de testat și de refolosit:

```text
calculator/
├── Cargo.toml
└── src/
    ├── lib.rs          // pub fn evalueaza(...)
    ├── main.rs         // use calculator::evalueaza;
    └── bin/
        └── repl.rs     // un al doilea binar: cargo run --bin repl
```

## Niveluri de vizibilitate

| Sintaxă | Vizibil în |
|---|---|
| (nimic) | modulul curent și submodulele lui |
| `pub(super)` | modulul părinte |
| `pub(crate)` | tot crate-ul, dar nu și în afara lui |
| `pub` | oriunde, inclusiv în alte crate-uri |

```rust
mod banca {
    pub struct Cont {
        pub titular: String,     // public
        pub(crate) id: u32,      // vizibil în tot crate-ul
        sold: i64,               // privat
    }

    impl Cont {
        pub fn new(titular: &str) -> Self {
            Cont { titular: titular.into(), id: 1, sold: 0 }
        }
        pub fn sold(&self) -> i64 {
            self.sold
        }
    }
}

fn main() {
    let c = banca::Cont::new("Ana");
    println!("{} #{} sold {}", c.titular, c.id, c.sold());
    // c.sold = 1_000_000; // eroare: câmpul e privat
}
```

## Re-exporturi cu `pub use`

Structura internă a fișierelor nu trebuie să fie și structura API-ului public. Cu `pub use`, expui elementele acolo unde e comod pentru utilizator:

```rust
mod intern {
    pub mod formate {
        pub mod json {
            pub fn serializeaza() -> &'static str { "{}" }
        }
    }
}

// utilizatorul scrie `serializeaza()`, nu `intern::formate::json::serializeaza()`
pub use intern::formate::json::serializeaza;

fn main() {
    println!("{}", serializeaza());
}
```

## Versiuni și `Cargo.lock`

Cargo folosește **versionare semantică** (SemVer): `MAJOR.MINOR.PATCH`. În `Cargo.toml`, `serde = "1.0.200"` înseamnă „orice versiune compatibilă”, adică `>=1.0.200, <2.0.0`:

| Scris | Acceptă |
|---|---|
| `"1.2.3"` sau `"^1.2.3"` | `>=1.2.3, <2.0.0` |
| `"0.4.1"` | `>=0.4.1, <0.5.0` (sub 1.0, minorul contează ca major) |
| `"~1.2.3"` | `>=1.2.3, <1.3.0` |
| `"=1.2.3"` | exact 1.2.3 |

`Cargo.lock` reține versiunile **exacte** alese, ca build-ul să fie reproductibil. Pune-l în git. Asta e recomandarea actuală atât pentru aplicații, cât și pentru biblioteci. `cargo update` îl actualizează în limitele din `Cargo.toml`.

## Features: funcționalitate opțională

```toml
[features]
default = ["json"]
json = ["dep:serde_json"]
compresie = []

[dependencies]
serde_json = { version = "1", optional = true }
```

În cod, compilezi condiționat cu `cfg`:

```rust
#[cfg(feature = "compresie")]
fn comprima(date: &[u8]) -> Vec<u8> {
    date.to_vec() // implementare reală aici
}

fn main() {
    #[cfg(feature = "compresie")]
    println!("{:?}", comprima(b"abc"));

    #[cfg(not(feature = "compresie"))]
    println!("compilat fără compresie");
}
```

## Workspace-uri

Un **workspace** grupează mai multe pachete care împart același `Cargo.lock` și același director `target/`:

```toml
# Cargo.toml de la rădăcină
[workspace]
members = ["core", "cli", "server"]
resolver = "3"

[workspace.dependencies]
serde = { version = "1", features = ["derive"] }
```

```toml
# cli/Cargo.toml
[dependencies]
core = { path = "../core" }
serde = { workspace = true }   # aceeași versiune peste tot
```

> **De reținut:** pune logica în `lib.rs`, iar în `main.rs` doar folosește-o. `pub(crate)` e nivelul de vizibilitate cel mai util pentru detaliile interne. `pub use` construiește un API public curat. Pune `Cargo.lock` în git, folosește features pentru părțile opționale și workspace-uri pentru mai multe pachete.

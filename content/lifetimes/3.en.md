# Lifetimes — Advanced

Lifetimes are types, and between types there are **subtyping** relationships. That's where variance, `T: 'a` constraints, HRTBs and the capture rules for `impl Trait` come from.

## Subtyping: a longer lifetime can be used as a shorter one

If `'long` includes `'short`, then `&'long T` can be used anywhere `&'short T` is required. That's why you can pass a `&'static str` to a function that asks for `&'a str`:

```rust
fn longer<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() >= b.len() { a } else { b }
}

fn main() {
    let local = String::from("local");
    let r = longer("static, from the binary", &local); // 'static shrinks to the lifetime of `local`
    println!("{r}");
}
```

## Variance

**Variance** says how subtyping propagates through compound types:

| Type | With respect to `'a` | With respect to `T` |
|---|---|---|
| `&'a T` | covariant | covariant |
| `&'a mut T` | covariant | **invariant** |
| `Box<T>`, `Vec<T>` | — | covariant |
| `Cell<T>`, `RefCell<T>` | — | **invariant** |
| `fn(T) -> U` | — | **contravariant** in `T`, covariant in `U` |

Why is `&mut T` invariant in `T`? If it were covariant, you could sneak a short reference into a place that promises a long one:

```rust,compile_fail
fn add<'a>(v: &mut Vec<&'a str>, s: &'a str) {
    v.push(s);
}

fn main() {
    let mut permanent: Vec<&'static str> = vec!["one"];
    {
        let temporary = String::from("two");
        add(&mut permanent, &temporary); // error: `temporary` would have to be 'static
    }
    println!("{permanent:?}"); // otherwise we'd be reading freed memory here
}
```

## `T: 'a` constraints

`T: 'a` means "every reference inside `T` lives at least as long as `'a`". A struct that holds `&'a T` requires it implicitly: the compiler infers it and you don't write it.

```rust
struct Reference<'a, T> {
    value: &'a T, // implies T: 'a
}

fn build<'a, T: std::fmt::Debug>(x: &'a T) -> Reference<'a, T> {
    Reference { value: x }
}

fn main() {
    let n = vec![1, 2];
    println!("{:?}", build(&n).value);
}
```

## Higher-ranked trait bounds: `for<'a>`

Sometimes a function takes a closure that must work for **any** lifetime, not for one particular lifetime chosen by the caller. The syntax is `for<'a>`:

```rust
fn apply_to_all<F>(texts: &[String], f: F) -> Vec<usize>
where
    F: for<'a> Fn(&'a str) -> &'a str, // for any 'a
{
    texts.iter().map(|t| f(t).len()).collect()
}

fn main() {
    let texts = vec!["  rust  ".to_string(), " is  ".to_string()];
    println!("{:?}", apply_to_all(&texts, str::trim));
}
```

`Fn(&str) -> &str` is actually shorthand for `for<'a> Fn(&'a str) -> &'a str`. The elision rules apply here too.

## `impl Trait` and lifetime capture (2024 edition)

An `impl Trait` return type can use the function's generic parameters. The question is which ones it **captures**. In the 2024 edition, it captures **all** parameters in scope by default, including lifetimes. That's almost always what you want:

```rust
fn long_words(text: &str, minimum: usize) -> impl Iterator<Item = &str> {
    // the iterator borrows `text`; in 2024 it is captured automatically
    text.split_whitespace().filter(move |w| w.len() >= minimum)
}

fn main() {
    let t = String::from("an example of a long iterator");
    println!("{:?}", long_words(&t, 4).collect::<Vec<_>>());
}
```

When you want to capture **less**, for example so the result doesn't depend on a borrowed argument, you use `use<...>` (*precise capturing*, Rust 1.82):

```rust
fn lengths<'a>(texts: &'a [String]) -> impl Iterator<Item = usize> + use<> {
    let l: Vec<usize> = texts.iter().map(|t| t.len()).collect();
    l.into_iter() // no longer borrows `texts`
}

fn main() {
    let mut texts = vec!["ab".to_string(), "cde".to_string()];
    let it = lengths(&texts);
    texts.clear(); // allowed: `it` doesn't capture the borrow
    println!("{:?}", it.collect::<Vec<_>>());
}
```

## Temporary lifetime extension

A temporary whose borrow is bound directly by a `let` lives until the end of the block, not just until the `;`:

```rust
fn main() {
    let s = &String::from("extended temporary"); // the temporary lives as long as `s`
    let t = &[1, 2, 3].map(|x| x * 2);           // same here
    println!("{s} {t:?}");
}
```

Extension happens only in certain syntactic forms (`&expr`, structs and tuples with `&expr`, blocks). It doesn't apply to function arguments: `let x = f(&String::new());` doesn't extend the temporary.

> **Key takeaway:** lifetimes have subtyping. `&mut T` and `Cell<T>` are invariant so they can't let short references slip in. `for<'a>` requires "for any lifetime". `impl Trait` captures everything in 2024, and `use<>` narrows the capture.

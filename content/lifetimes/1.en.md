# Lifetimes — Fundamentals

A **lifetime** is the span during which a reference is valid. The compiler checks all of them, so there's never a reference to a value that has already been destroyed.

## The problem: references left "dangling"

```rust,compile_fail
fn main() {
    let reference;
    {
        let text = String::from("hello");
        reference = &text;
    } // `text` is destroyed here
    println!("{reference}"); // error E0597: `text` does not live long enough
}
```

In C, a program like this would compile and read freed memory (a *dangling pointer*). In Rust, the compiler sees that `reference` is used after `text` is gone.

The fix is simple: the value must live at least as long as the reference.

```rust
fn main() {
    let text = String::from("hello");
    let reference = &text;
    println!("{reference}");
}
```

## Most of the time you write nothing

The compiler infers lifetimes on its own in the vast majority of cases:

```rust
fn first_word(s: &str) -> &str {
    s.split(' ').next().unwrap_or("")
}

fn main() {
    let sentence = String::from("Rust is fast");
    println!("{}", first_word(&sentence));
}
```

The result obviously has the same lifetime as `s`: it's a piece of it.

## When you need to help the compiler

If a function takes **two** references and returns one, the compiler doesn't know which one the result comes from:

```rust,compile_fail
fn longer(a: &str, b: &str) -> &str { // error E0106: missing lifetime parameter
    if a.len() > b.len() { a } else { b }
}

fn main() {
    println!("{}", longer("abc", "de"));
}
```

You tell it through a **lifetime parameter**, written with an apostrophe: `'a`:

```rust
fn longer<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() > b.len() { a } else { b }
}

fn main() {
    let x = String::from("quite long");
    let y = String::from("short");
    println!("{}", longer(&x, &y));
}
```

The signature reads: "the result lives at least as long as **the shorter** of `a` and `b`".

## The annotation changes nothing at runtime

`'a` doesn't make a value live longer. It is only a **description** of the relationships between references, which the compiler checks. If the description doesn't match reality, you get a compile error.

## `'static`

`'static` means "valid for the entire duration of the program". Text literals have this lifetime, because they are stored directly in the binary:

```rust
fn main() {
    let message: &'static str = "I live in the binary";
    println!("{message}");
}
```

> **Key takeaway:** a lifetime describes how long a reference is valid. The compiler usually infers it on its own. You write it (`'a`) when a function returns a reference and it isn't clear which parameter it comes from.

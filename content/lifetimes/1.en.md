# Lifetimes — Fundamente

Un **lifetime** (durată de viață) este intervalul în care o referință e validă. Compilatorul le verifică pe toate, ca să nu existe niciodată o referință către o valoare deja distrusă.

## Problema: referințe care rămân „în aer”

```rust,compile_fail
fn main() {
    let referinta;
    {
        let text = String::from("salut");
        referinta = &text;
    } // `text` e distrus aici
    println!("{referinta}"); // eroare E0597: `text` nu trăiește destul
}
```

În C, un astfel de program ar compila și ar citi memorie eliberată (*dangling pointer*). În Rust, compilatorul vede că `referinta` e folosită după ce `text` a dispărut.

Corectura e simplă: valoarea trebuie să trăiască cel puțin cât referința.

```rust
fn main() {
    let text = String::from("salut");
    let referinta = &text;
    println!("{referinta}");
}
```

## De cele mai multe ori nu scrii nimic

Compilatorul deduce singur lifetimes în marea majoritate a cazurilor:

```rust
fn primul_cuvant(s: &str) -> &str {
    s.split(' ').next().unwrap_or("")
}

fn main() {
    let propozitie = String::from("Rust este rapid");
    println!("{}", primul_cuvant(&propozitie));
}
```

Rezultatul are evident aceeași durată de viață ca `s`: e o bucată din el.

## Când trebuie să ajuți compilatorul

Dacă o funcție primește **două** referințe și returnează una, compilatorul nu știe din care provine rezultatul:

```rust,compile_fail
fn mai_lung(a: &str, b: &str) -> &str { // eroare E0106: lipsește parametrul de lifetime
    if a.len() > b.len() { a } else { b }
}

fn main() {
    println!("{}", mai_lung("abc", "de"));
}
```

Îi spui printr-un **parametru de lifetime**, scris cu apostrof: `'a`:

```rust
fn mai_lung<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() > b.len() { a } else { b }
}

fn main() {
    let x = String::from("lung de tot");
    let y = String::from("scurt");
    println!("{}", mai_lung(&x, &y));
}
```

Semnătura se citește: „rezultatul trăiește cel puțin cât **cea mai scurtă** dintre `a` și `b`”.

## Adnotarea nu schimbă nimic la runtime

`'a` nu face ca o valoare să trăiască mai mult. E doar o **descriere** a relațiilor dintre referințe, pe care compilatorul o verifică. Dacă descrierea nu se potrivește cu realitatea, primești o eroare de compilare.

## `'static`

`'static` înseamnă „valid pe toată durata programului”. Literalii de text au acest lifetime, pentru că sunt stocați direct în binar:

```rust
fn main() {
    let mesaj: &'static str = "sunt în binar";
    println!("{mesaj}");
}
```

> **De reținut:** un lifetime descrie cât timp e validă o referință. Compilatorul îl deduce de obicei singur. Îl scrii (`'a`) când o funcție returnează o referință și nu e clar din ce parametru provine.

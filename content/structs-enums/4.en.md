# Structs and enums — Expert

What an enum looks like in memory, which layout guarantees you get with each `repr`, plus unions and dynamically sized types.

## The layout of an enum: tag + payload

An enum with data takes, as a rule, as much as **its largest variant** plus a **tag** (the discriminant), rounded up to the alignment:

```rust
#[allow(dead_code)]
enum Message {
    Empty,
    Number(u32),
    Text([u8; 16]),
}

fn main() {
    println!("Message: {} bytes", size_of::<Message>()); // 20: 16 + tag, rounded to 4
    println!("Option<u64>: {}", size_of::<Option<u64>>()); // 16: tag + padding + 8
    println!("Option<Box<u64>>: {}", size_of::<Option<Box<u64>>>()); // 8: niche
    println!("Result<u32, ()>: {}", size_of::<Result<u32, ()>>()); // 8
}
```

When the payload has forbidden values (a *niche*: a null pointer, a `bool` above 1, a `char` above `0x10FFFF`), the compiler encodes the tag directly in them and the enum takes no extra space. See also the Expert level of Variables and types.

The compiler can even use padding or the fields of other variants for the tag. In short, the layout of a `repr(Rust)` enum **is not specified**. If you need a fixed layout, choose a `repr`.

## `repr` on enums

| Attribute | Layout |
|---|---|
| default (`repr(Rust)`) | unspecified; the compiler optimizes freely |
| `#[repr(u8)]`, `#[repr(i32)]`… | tag of the given type; for variants with data, a defined layout (a union of `repr(C)` structs, each starting with the tag) |
| `#[repr(C)]` | compatible with a C `enum`, and for variants with data, with `struct { tag; union { ... } }` |

```rust
#[allow(dead_code)]
#[repr(u8)]
enum Command {
    Stop = 0,
    Move { x: i16, y: i16 } = 1,
}

fn main() {
    let c = Command::Move { x: 3, y: -4 };
    // With repr(u8), the first byte is guaranteed to be the tag.
    // SAFETY: Command is repr(u8), so it starts with an initialized u8.
    let tag = unsafe { *(&c as *const Command as *const u8) };
    println!("tag = {tag}, size = {}", size_of::<Command>());
}
```

## `mem::discriminant`

Compares the variant of two values without comparing their data:

```rust
use std::mem::discriminant;

#[allow(dead_code)]
enum Event {
    Click { x: i32, y: i32 },
    Key(char),
}

fn main() {
    let a = Event::Click { x: 1, y: 2 };
    let b = Event::Click { x: 50, y: 60 };
    let c = Event::Key('q');
    println!("{}", discriminant(&a) == discriminant(&b)); // true
    println!("{}", discriminant(&a) == discriminant(&c)); // false
}
```

## Unions

A `union` stores all fields **at the same address**, with no tag. You don't know which field is valid, so reading any field requires `unsafe`. Unions exist mainly for FFI and for implementing types such as `MaybeUninit`:

```rust
#[repr(C)]
union Bits {
    f: f32,
    u: u32,
}

fn main() {
    let b = Bits { f: 1.0 };
    // SAFETY: f32 and u32 have the same size and every bit pattern is a valid u32
    let bits = unsafe { b.u };
    println!("{bits:#010x}"); // 0x3f800000
    println!("{}", 1.0_f32.to_bits() == bits); // the safe way
}
```

Union fields can't have destructors. They must be `Copy` or wrapped in `ManuallyDrop`.

## Dynamically sized types (DST)

`str`, `[T]` and `dyn Trait` don't have a size known at compile time. You can't hold them directly in a variable, only behind a pointer. That pointer is **fat**: it has two words, the address plus the length or the vtable pointer.

A struct can have a DST as its **last** field, and then it becomes a DST itself:

```rust
struct Packet {
    version: u8,
    data: [u8], // DST: the last field
}

fn main() {
    println!("&[u8]:   {} bytes", size_of::<&[u8]>());   // 16: pointer + length
    println!("&str:    {} bytes", size_of::<&str>());    // 16
    println!("&Packet: {} bytes", size_of::<&Packet>()); // 16: it's fat too
    println!("&dyn Fn(): {} bytes", size_of::<&dyn Fn()>()); // 16: pointer + vtable
}
```

Such a struct is usually created by "unsizing" a generic variant (`Packet<[u8; N]>` → `Packet<[u8]>`) or with `unsafe`.

## Zero-sized types and types with no values

- A struct with no fields (`struct Marker;`) has size 0. It takes no space in other structs, and a `Vec` of ZSTs allocates nothing.
- An enum **with no variants** (`enum Never {}`) has no possible values. It is the stable equivalent of `!`, and `std::convert::Infallible` is exactly such an enum. Since Rust 1.82, a `Result<T, Infallible>` can be destructured directly, without an `Err` branch:

```rust
use std::convert::Infallible;

fn always_ok() -> Result<u32, Infallible> {
    Ok(7)
}

fn main() {
    let Ok(n) = always_ok(); // the compiler knows Err(Infallible) can't exist
    println!("{n}, size of the Result: {}", size_of::<Result<u32, Infallible>>());
}
```

> **Key takeaway:** an enum takes as much as its largest variant plus a tag, unless there's a niche. The `repr(Rust)` layout is free, while `repr(u8)` / `repr(C)` fix it. A `union` has no tag, and DSTs live only behind fat pointers.

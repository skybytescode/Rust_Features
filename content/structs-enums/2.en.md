# Structs and enums — Practitioner

How to make your types behave like the ones in the standard library: printing them, comparing them, copying them and protecting their invariants.

## `#[derive]`: ready-made behavior

Many standard traits can be implemented automatically:

```rust
#[derive(Debug, Clone, PartialEq, Default)]
struct Settings {
    volume: u8,
    language: String,
    notifications: bool,
}

fn main() {
    let default = Settings::default();       // every field gets its default value
    let mut mine = default.clone();
    mine.volume = 80;

    println!("{default:?}");                 // Debug
    println!("{mine:#?}");                   // Debug, pretty-printed over several lines
    println!("equal? {}", default == mine);  // PartialEq
}
```

| Trait | What it gives you |
|---|---|
| `Debug` | printing with `{:?}`, for debugging |
| `Clone` | `.clone()` |
| `Copy` | implicit copying (only if all fields are `Copy`) |
| `PartialEq`, `Eq` | `==` and `!=` |
| `PartialOrd`, `Ord` | `<`, `>`, sorting |
| `Hash` | use as a key in a `HashMap` |
| `Default` | `T::default()` |

## Private fields and constructors

Fields are **private** by default: outside the module where the struct is defined you can't read them directly. A `new` constructor guarantees that every instance is valid:

```rust
mod temperature {
    pub struct Celsius {
        degrees: f64, // private: can't be set directly from outside
    }

    impl Celsius {
        pub fn new(degrees: f64) -> Option<Celsius> {
            if degrees < -273.15 {
                None // below absolute zero: invalid
            } else {
                Some(Celsius { degrees })
            }
        }

        pub fn degrees(&self) -> f64 {
            self.degrees
        }
    }
}

fn main() {
    use temperature::Celsius;
    println!("{:?}", Celsius::new(21.5).map(|t| t.degrees()));
    println!("{}", Celsius::new(-300.0).is_none());
}
```

## Enums instead of combinations of `bool`

A type with several `bool`s can end up in meaningless states. An enum describes exactly the possible states:

```rust
// Problematic: what do loaded = true and error = true mean at the same time?
#[allow(dead_code)]
struct BadDownload {
    loaded: bool,
    error: bool,
    percent: u8,
}

// Better: one state at a time, each with its own data
#[derive(Debug)]
enum Download {
    Pending,
    InProgress { percent: u8 },
    Done { bytes: u64 },
    Failed(String),
}

fn main() {
    let states = [
        Download::Pending,
        Download::InProgress { percent: 40 },
        Download::Done { bytes: 1024 },
        Download::Failed("timeout".into()),
    ];
    for s in &states {
        println!("{s:?}");
    }
}
```

## Methods on enums

Enums can have methods, just like structs:

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
enum TrafficLight {
    Red,
    Yellow,
    Green,
}

impl TrafficLight {
    fn next(self) -> TrafficLight {
        match self {
            TrafficLight::Red => TrafficLight::Green,
            TrafficLight::Green => TrafficLight::Yellow,
            TrafficLight::Yellow => TrafficLight::Red,
        }
    }

    fn can_go(self) -> bool {
        self == TrafficLight::Green
    }
}

fn main() {
    let mut light = TrafficLight::Red;
    for _ in 0..4 {
        println!("{light:?}: can go? {}", light.can_go());
        light = light.next();
    }
}
```

## Useful methods on `Option`

Instead of a `match` everywhere, `Option` has methods for the common cases:

```rust
fn main() {
    let port: Option<u16> = None;
    println!("{}", port.unwrap_or(8080));          // default value

    let name: Option<&str> = Some("ana");
    println!("{:?}", name.map(|n| n.to_uppercase())); // transform if present

    let age: Option<u32> = Some(17);
    println!("{:?}", age.filter(|&a| a >= 18));       // keep only if it meets the condition

    if let Some(n) = name {
        println!("hello, {n}");
    }
}
```

> **Key takeaway:** `#[derive]` gives you `Debug`, `Clone`, `PartialEq` and other traits for free. Private fields plus a constructor guarantee that instances are valid. An enum describes the possible states more safely than a combination of `bool`s.

# Structs and enums — Advanced

Design patterns that use the type system to make invalid states impossible to construct.

## Generic structs

A struct can be generic over one or more types. You can implement methods for all types or only for some:

```rust
#[derive(Debug)]
struct Pair<T> {
    a: T,
    b: T,
}

impl<T: PartialOrd> Pair<T> {
    fn max(&self) -> &T {
        if self.a >= self.b { &self.a } else { &self.b }
    }
}

impl Pair<f64> {
    fn mean(&self) -> f64 {
        (self.a + self.b) / 2.0
    }
}

fn main() {
    let ints = Pair { a: 3, b: 9 };
    let floats = Pair { a: 1.5, b: 2.5 };
    println!("{} {} {}", ints.max(), floats.max(), floats.mean());
    // ints.mean() doesn't exist: the method is defined only for Pair<f64>
}
```

## The builder pattern

When a type has many optional fields, a **builder** is clearer than a constructor with ten parameters:

```rust
#[derive(Debug)]
struct Request {
    url: String,
    method: String,
    timeout_s: u32,
    retries: u8,
}

struct RequestBuilder {
    request: Request,
}

impl RequestBuilder {
    fn new(url: &str) -> Self {
        RequestBuilder {
            request: Request { url: url.into(), method: "GET".into(), timeout_s: 30, retries: 0 },
        }
    }
    fn method(mut self, m: &str) -> Self { self.request.method = m.into(); self }
    fn timeout(mut self, s: u32) -> Self { self.request.timeout_s = s; self }
    fn retries(mut self, n: u8) -> Self { self.request.retries = n; self }
    fn build(self) -> Request { self.request }
}

fn main() {
    let r = RequestBuilder::new("https://example.com").method("POST").timeout(5).build();
    println!("{r:?}");
}
```

Each method takes `self` by value and returns it, so the calls can be chained without `mut` at the call site.

## Typestate: the state encoded in the type

You can make certain operations available **only** in certain states, checked at compile time. Each state is a separate type:

```rust,compile_fail
struct Disconnected;
struct Connected;

struct Connection<State> {
    address: String,
    _state: State,
}

impl Connection<Disconnected> {
    fn new(address: &str) -> Self {
        Connection { address: address.into(), _state: Disconnected }
    }
    fn connect(self) -> Connection<Connected> {
        Connection { address: self.address, _state: Connected }
    }
}

impl Connection<Connected> {
    fn send(&self, message: &str) {
        println!("to {}: {message}", self.address);
    }
}

fn main() {
    let c = Connection::new("server:80");
    c.send("hello"); // error E0599: `send` doesn't exist for Connection<Disconnected>
}
```

With `let c = Connection::new("server:80").connect();`, the call compiles. Since `connect` consumes `self`, the old "disconnected" connection can no longer be used afterwards.

## Explicit discriminants

An enum without data can have explicit numeric values, and `as` converts them to integers:

```rust
#[derive(Debug, Clone, Copy)]
#[repr(u16)]
enum HttpCode {
    Ok = 200,
    NotFound = 404,
    Error = 500,
}

impl TryFrom<u16> for HttpCode {
    type Error = u16;
    fn try_from(code: u16) -> Result<Self, u16> {
        match code {
            200 => Ok(HttpCode::Ok),
            404 => Ok(HttpCode::NotFound),
            500 => Ok(HttpCode::Error),
            other => Err(other),
        }
    }
}

fn main() {
    println!("{}", HttpCode::NotFound as u16);
    println!("{:?} {:?}", HttpCode::try_from(500), HttpCode::try_from(418));
}
```

The reverse conversion, from integer to enum, can't be done with `as`, because not every number is a valid variant. That's why you need `TryFrom`.

## `#[non_exhaustive]`: room for future variants

In a library, adding a new variant breaks every exhaustive `match` written by users. With `#[non_exhaustive]`, code **in other crates** is required to have a `_` branch, so you can add variants without a breaking change:

```rust
#[non_exhaustive]
#[derive(Debug)]
pub enum Error {
    Network,
    Permission,
}

fn main() {
    // In the crate that defines the enum, an exhaustive match is allowed.
    // In another crate, `_ => ...` would be mandatory.
    let e = Error::Network;
    match e {
        Error::Network => println!("network"),
        Error::Permission => println!("permission"),
    }
}
```

The attribute also works on structs: it prevents creating them with the `Struct { ... }` syntax from other crates and lets you add fields.

> **Key takeaway:** generics with a specialized `impl` add methods only for some types. The builder and typestate patterns move checks to compile time. `#[repr(u16)]` fixes the discriminants, and `#[non_exhaustive]` leaves you room to evolve.

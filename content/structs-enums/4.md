# Structs și enums — Expert

Cum arată un enum în memorie, ce garanții de layout primești cu fiecare `repr`, plus uniunile și tipurile de mărime dinamică.

## Layout-ul unui enum: tag + payload

Un enum cu date ocupă, de regulă, cât **cea mai mare variantă** plus un **tag** (discriminantul), rotunjit la aliniere:

```rust
#[allow(dead_code)]
enum Mesaj {
    Gol,
    Numar(u32),
    Text([u8; 16]),
}

fn main() {
    println!("Mesaj: {} octeți", size_of::<Mesaj>()); // 20: 16 + tag, rotunjit la 4
    println!("Option<u64>: {}", size_of::<Option<u64>>()); // 16: tag + padding + 8
    println!("Option<Box<u64>>: {}", size_of::<Option<Box<u64>>>()); // 8: nișă
    println!("Result<u32, ()>: {}", size_of::<Result<u32, ()>>()); // 8
}
```

Când payload-ul are valori interzise (o *nișă*: pointer nul, `bool` peste 1, `char` peste `0x10FFFF`), compilatorul codifică tag-ul direct în ele și enum-ul nu mai ocupă nimic în plus. Vezi și nivelul Expert din Variabile și tipuri.

Compilatorul poate folosi chiar și padding-ul sau câmpurile altor variante pentru tag. Concret, layout-ul unui enum `repr(Rust)` **nu e specificat**. Dacă ai nevoie de un layout fix, alege un `repr`.

## `repr` pe enums

| Atribut | Layout |
|---|---|
| implicit (`repr(Rust)`) | nespecificat; compilatorul optimizează liber |
| `#[repr(u8)]`, `#[repr(i32)]`… | tag de tipul dat; pentru variante cu date, layout definit (un union de structuri `repr(C)`, fiecare cu tag-ul în față) |
| `#[repr(C)]` | compatibil cu un `enum` din C, iar pentru variante cu date, cu `struct { tag; union { ... } }` |

```rust
#[allow(dead_code)]
#[repr(u8)]
enum Comanda {
    Stop = 0,
    Muta { x: i16, y: i16 } = 1,
}

fn main() {
    let c = Comanda::Muta { x: 3, y: -4 };
    // Cu repr(u8), primul octet este garantat tag-ul.
    // SAFETY: Comanda e repr(u8), deci începe cu un u8 inițializat.
    let tag = unsafe { *(&c as *const Comanda as *const u8) };
    println!("tag = {tag}, mărime = {}", size_of::<Comanda>());
}
```

## `mem::discriminant`

Compari varianta a două valori, fără să le compari și datele:

```rust
use std::mem::discriminant;

#[allow(dead_code)]
enum Eveniment {
    Click { x: i32, y: i32 },
    Tasta(char),
}

fn main() {
    let a = Eveniment::Click { x: 1, y: 2 };
    let b = Eveniment::Click { x: 50, y: 60 };
    let c = Eveniment::Tasta('q');
    println!("{}", discriminant(&a) == discriminant(&b)); // true
    println!("{}", discriminant(&a) == discriminant(&c)); // false
}
```

## Uniuni

Un `union` stochează toate câmpurile **la aceeași adresă**, fără tag. Nu știi care câmp e valid, deci citirea oricărui câmp cere `unsafe`. Uniunile există mai ales pentru FFI și pentru implementarea unor tipuri ca `MaybeUninit`:

```rust
#[repr(C)]
union Biti {
    f: f32,
    u: u32,
}

fn main() {
    let b = Biti { f: 1.0 };
    // SAFETY: f32 și u32 au aceeași mărime și orice model de biți e un u32 valid
    let biti = unsafe { b.u };
    println!("{biti:#010x}"); // 0x3f800000
    println!("{}", 1.0_f32.to_bits() == biti); // varianta sigură
}
```

Câmpurile unui union nu pot avea destructori. Ele trebuie să fie `Copy` sau învelite în `ManuallyDrop`.

## Tipuri de mărime dinamică (DST)

`str`, `[T]` și `dyn Trait` nu au o mărime cunoscută la compilare. Nu le poți ține direct într-o variabilă, ci doar în spatele unui pointer. Acel pointer este **fat**: are două cuvinte, adresa plus lungimea sau pointerul la vtable.

Un struct poate avea un DST ca **ultim** câmp, iar atunci devine el însuși un DST:

```rust
struct Pachet {
    versiune: u8,
    date: [u8], // DST: ultimul câmp
}

fn main() {
    println!("&[u8]:   {} octeți", size_of::<&[u8]>());   // 16: pointer + lungime
    println!("&str:    {} octeți", size_of::<&str>());    // 16
    println!("&Pachet: {} octeți", size_of::<&Pachet>()); // 16: și el e fat
    println!("&dyn Fn(): {} octeți", size_of::<&dyn Fn()>()); // 16: pointer + vtable
}
```

Un astfel de struct se creează de obicei prin „unsizing” dintr-o variantă generică (`Pachet<[u8; N]>` → `Pachet<[u8]>`) sau cu `unsafe`.

## Tipuri de mărime zero și tipuri fără valori

- Un struct fără câmpuri (`struct Marcaj;`) are mărimea 0. Nu ocupă loc în alte structuri, iar un `Vec` de ZST nu alocă nimic.
- Un enum **fără variante** (`enum Niciodata {}`) nu are nicio valoare posibilă. E echivalentul stabil al lui `!`, iar `std::convert::Infallible` este exact un astfel de enum. Din Rust 1.82, un `Result<T, Infallible>` poate fi destructurat direct, fără ramura `Err`:

```rust
use std::convert::Infallible;

fn mereu_ok() -> Result<u32, Infallible> {
    Ok(7)
}

fn main() {
    let Ok(n) = mereu_ok(); // compilatorul știe că Err(Infallible) nu poate exista
    println!("{n}, mărimea Result: {}", size_of::<Result<u32, Infallible>>());
}
```

> **De reținut:** un enum ocupă cât cea mai mare variantă plus tag, dacă nu există o nișă. Layout-ul `repr(Rust)` e liber, iar `repr(u8)` / `repr(C)` îl fixează. `union` nu are tag, iar DST-urile trăiesc doar în spatele pointerilor fat.

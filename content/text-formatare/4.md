# Text și formatare — Expert

Cum compilează compilatorul un `format!`, ce este `fmt::Arguments`, ce invariant protejează `String` și cât costă de fapt formatarea.

## Șirul de formatare e analizat la compilare

`format!`, `println!` și `write!` se bazează pe `format_args!`, un macro implementat direct în compilator. El analizează șirul de formatare **la compilare**: verifică numărul argumentelor, trait-urile cerute (`Display`, `Debug`, `LowerHex`…) și numele folosite. La runtime nu se mai interpretează nimic. Rămâne doar o structură statică, cu bucățile de text și cu referințe către argumente.

Captarea directă a variabilelor (`{nume}`, din Rust 1.58) acceptă **doar identificatori**, nu expresii:

```rust,compile_fail
fn main() {
    let v = vec![1, 2, 3];
    println!("{v.len()}"); // eroare: în acolade poate sta doar un nume
}
```

Pentru expresii, folosești un argument: `println!("{}", v.len())`.

## `fmt::Arguments`: formatare fără alocare

`format_args!` produce un `fmt::Arguments`: textul „gata de scris”, care nu alocă nimic. Îl poți transmite mai departe, iar formatarea efectivă are loc abia la destinație:

```rust
use std::fmt;

fn jurnal(nivel: &str, mesaj: fmt::Arguments) {
    // o singură trecere de formatare, direct în stderr, fără String intermediar
    eprintln!("[{nivel}] {mesaj}");
}

macro_rules! info {
    ($($arg:tt)*) => { jurnal("INFO", format_args!($($arg)*)) };
}

fn main() {
    let utilizator = "ana";
    info!("{utilizator} s-a conectat de {} ori", 3);
    let a = format_args!("{} + {}", 1, 2).to_string(); // la nevoie, devine String
    println!("{a}");
}
```

Crate-urile de logging, ca `log` și `tracing`, folosesc aceeași tehnică. Dacă nivelul e dezactivat, argumentele nici măcar nu sunt formatate.

## `fmt::Write` vs. `io::Write`

| Trait | Scrie | Erori | Implementat de |
|---|---|---|---|
| `std::fmt::Write` | text (`&str`) | `fmt::Error`, fără detalii | `String`, `Formatter` |
| `std::io::Write` | octeți (`&[u8]`) | `io::Error` | `File`, `Stdout`, `Vec<u8>`, socket-uri |

Ambele au metoda `write_fmt`, pe care o apelează macro-ul `write!`. De aceea `write!` merge pe ambele tipuri de destinație.

## Invariantul lui `String`

Un `String` e un `Vec<u8>` cu o promisiune: octeții sunt **UTF-8 valid**. Toate metodele safe păstrează promisiunea. Metodele `unsafe` o lasă în grija ta:

```rust
fn main() {
    let octeti = vec![0x52, 0x75, 0x73, 0x74];
    let s = String::from_utf8(octeti).unwrap(); // verifică: O(n)
    println!("{s}");

    let tot_ascii = b"sigur ASCII".to_vec();
    // SAFETY: octeții sunt ASCII, deci UTF-8 valid
    let rapid = unsafe { String::from_utf8_unchecked(tot_ascii) }; // fără verificare
    println!("{rapid}");
}
```

Un `str` cu UTF-8 invalid este **comportament nedefinit**, chiar dacă nu îl afișezi. Metode ca `chars()` presupun că secvențele sunt corecte și pot citi dincolo de capătul buffer-ului.

## Costul formatării

- `format!` alocă un `String` nou. Într-o buclă fierbinte, preferă `write!` într-un buffer refolosit.
- `Display` pentru numere e optimizat (tabele de cifre, algoritmii Grisu și Dragon pentru `f64`), dar e tot mai lent decât copierea unui `&str`.
- `println!` blochează `stdout` la fiecare apel. Pentru multe linii, ia lacătul o singură dată:

```rust
use std::io::Write;

fn main() {
    let stdout = std::io::stdout();
    let mut out = stdout.lock(); // un singur lacăt pentru toată bucla
    for i in 0..5 {
        writeln!(out, "linia {i}").unwrap();
    }
}
```

## Layout-ul tipurilor de text

```rust
fn main() {
    println!("&str:    {} octeți", size_of::<&str>());       // 16: pointer + lungime
    println!("String:  {} octeți", size_of::<String>());     // 24: pointer + capacitate + lungime
    println!("Box<str>: {} octeți", size_of::<Box<str>>());  // 16: fără capacitate
    println!("char:    {} octeți", size_of::<char>());       // 4

    let s: Box<str> = "text fix".into(); // fără capacitate în plus: util pentru date care nu mai cresc
    println!("{s}");
}
```

Biblioteca standard nu are *small string optimization*: orice `String` nevid alocă pe heap. Crate-uri ca `compact_str` sau `smol_str` păstrează textele scurte direct pe stivă, în cei 24 de octeți ai structurii.

> **De reținut:** șirul de formatare e verificat și analizat la compilare de `format_args!`. `fmt::Arguments` permite formatare fără alocări intermediare. Un `str` trebuie să fie mereu UTF-8 valid, altfel e UB. Pentru performanță, refolosește buffer-ele și blochează `stdout` o singură dată.

# Text and formatting — Expert

How the compiler compiles a `format!`, what `fmt::Arguments` is, which invariant `String` protects, and what formatting actually costs.

## The format string is parsed at compile time

`format!`, `println!` and `write!` are built on `format_args!`, a macro implemented directly in the compiler. It parses the format string **at compile time**: it checks the number of arguments, the required traits (`Display`, `Debug`, `LowerHex`…) and the names used. Nothing is interpreted at runtime. All that's left is a static structure, with the pieces of text and references to the arguments.

Direct variable capture (`{name}`, since Rust 1.58) accepts **only identifiers**, not expressions:

```rust,compile_fail
fn main() {
    let v = vec![1, 2, 3];
    println!("{v.len()}"); // error: only a name can go inside the braces
}
```

For expressions, you use an argument: `println!("{}", v.len())`.

## `fmt::Arguments`: formatting without allocation

`format_args!` produces an `fmt::Arguments`: the text "ready to be written", which allocates nothing. You can pass it along, and the actual formatting happens only at the destination:

```rust
use std::fmt;

fn log(level: &str, message: fmt::Arguments) {
    // a single formatting pass, straight to stderr, with no intermediate String
    eprintln!("[{level}] {message}");
}

macro_rules! info {
    ($($arg:tt)*) => { log("INFO", format_args!($($arg)*)) };
}

fn main() {
    let user = "ana";
    info!("{user} logged in {} times", 3);
    let a = format_args!("{} + {}", 1, 2).to_string(); // becomes a String when needed
    println!("{a}");
}
```

Logging crates such as `log` and `tracing` use the same technique. If the level is disabled, the arguments aren't even formatted.

## `fmt::Write` vs. `io::Write`

| Trait | Writes | Errors | Implemented by |
|---|---|---|---|
| `std::fmt::Write` | text (`&str`) | `fmt::Error`, no details | `String`, `Formatter` |
| `std::io::Write` | bytes (`&[u8]`) | `io::Error` | `File`, `Stdout`, `Vec<u8>`, sockets |

Both have a `write_fmt` method, which the `write!` macro calls. That's why `write!` works with both kinds of destination.

## The `String` invariant

A `String` is a `Vec<u8>` with a promise: the bytes are **valid UTF-8**. Every safe method keeps the promise. The `unsafe` methods leave it up to you:

```rust
fn main() {
    let bytes = vec![0x52, 0x75, 0x73, 0x74];
    let s = String::from_utf8(bytes).unwrap(); // checks: O(n)
    println!("{s}");

    let all_ascii = b"surely ASCII".to_vec();
    // SAFETY: the bytes are ASCII, hence valid UTF-8
    let fast = unsafe { String::from_utf8_unchecked(all_ascii) }; // no check
    println!("{fast}");
}
```

A `str` with invalid UTF-8 is **undefined behavior**, even if you never print it. Methods like `chars()` assume the sequences are correct and can read past the end of the buffer.

## The cost of formatting

- `format!` allocates a new `String`. In a hot loop, prefer `write!` into a reused buffer.
- `Display` for numbers is optimized (digit tables, the Grisu and Dragon algorithms for `f64`), but it's still slower than copying a `&str`.
- `println!` locks `stdout` on every call. For many lines, take the lock once:

```rust
use std::io::Write;

fn main() {
    let stdout = std::io::stdout();
    let mut out = stdout.lock(); // a single lock for the whole loop
    for i in 0..5 {
        writeln!(out, "line {i}").unwrap();
    }
}
```

## The layout of text types

```rust
fn main() {
    println!("&str:    {} bytes", size_of::<&str>());       // 16: pointer + length
    println!("String:  {} bytes", size_of::<String>());     // 24: pointer + capacity + length
    println!("Box<str>: {} bytes", size_of::<Box<str>>());  // 16: no capacity
    println!("char:    {} bytes", size_of::<char>());       // 4

    let s: Box<str> = "fixed text".into(); // no extra capacity: useful for data that no longer grows
    println!("{s}");
}
```

The standard library has no *small string optimization*: every non-empty `String` allocates on the heap. Crates like `compact_str` or `smol_str` keep short texts directly on the stack, in the struct's 24 bytes.

> **Key takeaway:** the format string is checked and parsed at compile time by `format_args!`. `fmt::Arguments` enables formatting without intermediate allocations. A `str` must always be valid UTF-8, otherwise it's UB. For performance, reuse buffers and lock `stdout` once.

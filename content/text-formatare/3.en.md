# Text and formatting — Advanced

How to write a `Display` that respects the requested width and precision, the UTF-8 rules for indexing, and which text types exist beyond `String`.

## A `Display` that respects formatting options

A `Display` written with `write!` ignores the width and alignment the caller asks for. `Formatter` gives you access to them:

```rust
use std::fmt;

struct Color(u8, u8, u8);

impl fmt::Display for Color {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        let text = if f.alternate() {
            format!("rgb({}, {}, {})", self.0, self.1, self.2) // for {:#}
        } else {
            format!("#{:02x}{:02x}{:02x}", self.0, self.1, self.2)
        };
        f.pad(&text) // applies the requested width, alignment and fill
    }
}

fn main() {
    let c = Color(255, 128, 0);
    println!("[{c}]");
    println!("[{c:>12}]");
    println!("[{c:-^12}]");
    println!("[{c:#}]");
}
```

For numbers, `f.precision()`, `f.width()` and `f.sign_plus()` give you the remaining options. `f.pad_integral` applies the rules for numbers (sign, prefix, zeros).

## Where a `str` can be sliced

A `str` is UTF-8, and a character takes 1–4 bytes. You can slice only at a **character boundary**, otherwise you get a panic:

```rust,should_panic
fn main() {
    let s = "naïve";
    println!("{}", &s[0..2]);                 // "na": OK
    println!("{}", s.is_char_boundary(3));    // false: "ï" takes bytes 2–3
    println!("{}", &s[0..3]);                 // panic: 3 isn't a character boundary
}
```

Methods that work with positions (`find`, `char_indices`) always return valid boundaries, so you can use them directly for slicing:

```rust
fn first_n(s: &str, n: usize) -> &str {
    match s.char_indices().nth(n) {
        Some((pos, _)) => &s[..pos],
        None => s,
    }
}

fn main() {
    println!("{}", first_n("Zürich", 3));
    println!("{}", first_n("ok", 10));
}
```

## Characters vs. what the user sees

A `char` is a *Unicode scalar value*, not necessarily a visible "letter". Some symbols are made of several `char`s:

```rust
fn main() {
    let combined = "e\u{0301}";    // "e" + combining accent = é
    let flag = "🇷🇴";               // two regional indicator symbols
    let family = "👨‍👩‍👧";            // three people joined by ZWJ

    for s in [combined, flag, family] {
        println!("{s}: {} chars, {} bytes", s.chars().count(), s.len());
    }
}
```

For "characters as a human sees them" (*grapheme clusters*) you use the `unicode-segmentation` crate. The standard library doesn't include them.

## Case-insensitive comparisons

```rust
fn main() {
    let a = "RUST";
    let b = "rust";
    println!("{}", a.eq_ignore_ascii_case(b));             // ASCII only, fast
    println!("{}", a.to_lowercase() == b.to_lowercase());  // Unicode, allocates
    println!("{}", "STRASSE".to_lowercase());
}
```

`to_lowercase` follows the Unicode rules, so the length of the text can change. For example, "ß" becomes "SS" with `to_uppercase`.

## Other text types

| Type | Contains | Where it shows up |
|---|---|---|
| `String` / `&str` | valid UTF-8 | ordinary text |
| `Vec<u8>` / `&[u8]` | any bytes | binary data, protocols |
| `OsString` / `&OsStr` | the operating system's native text | arguments, environment variables |
| `PathBuf` / `&Path` | file paths | the file system |
| `CString` / `&CStr` | bytes terminated by `\0` | FFI with C |

```rust
use std::path::Path;

fn main() {
    let bytes: &[u8] = b"ASCII \x00 binary";  // a byte literal
    println!("{bytes:?}");

    let invalid = [0x66, 0x6f, 0xff, 0x6f];
    println!("{:?}", std::str::from_utf8(&invalid).is_err());
    println!("{}", String::from_utf8_lossy(&invalid)); // replaces with �

    let path = Path::new("/home/ana/photos/holiday.jpg");
    println!("{:?} {:?}", path.file_stem(), path.extension());
}
```

> **Key takeaway:** `f.pad` makes your `Display` respect width and alignment. Slice a `str` only at character boundaries, obtained from `char_indices` or `find`. A `char` isn't necessarily a visible letter. For bytes, paths and system text there are dedicated types.

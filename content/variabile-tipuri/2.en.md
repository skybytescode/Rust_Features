# Variables and types — Practitioner

The basic types look simple, but a few small decisions, such as which numeric type to use or how to convert between them, have a big impact on how correct your program is.

## Which numeric type to choose

- `i32` for "ordinary" integers, if you have no particular reason to pick something else;
- `usize` for indexes, lengths and element counts. That's what the standard library returns (`len()`), and indexing requires `usize`;
- `u8` for bytes and binary data;
- `f64` for floating-point numbers: it is as fast as `f32` on modern processors and much more precise;
- `i64` / `u64` when values can exceed ~2 billion (timestamps, amounts, IDs).

## Rust does no implicit conversions

Not even between two integer types. You must convert explicitly:

```rust,compile_fail
fn main() {
    let a: i32 = 10;
    let b: i64 = 20;
    let sum = a + b; // error E0308: mismatched types
    println!("{sum}");
}
```

There are three ways to convert:

```rust
fn main() {
    let a: i32 = 10;
    let b: i64 = 20;

    // 1. `From` / `into`: only conversions that lose no information
    let sum = i64::from(a) + b;

    // 2. `TryFrom` / `try_into`: conversions that can fail
    let big: i64 = 5_000_000_000;
    let r: Result<i32, _> = big.try_into();
    println!("{sum}, fits in i32? {}", r.is_ok());

    // 3. `as`: forced conversion, can silently truncate
    println!("{}", 300_i32 as u8); // 44
}
```

Use `From` whenever you can, `TryFrom` when the value might not fit, and `as` only when you are sure you want the truncation.

## Overflow does not go unnoticed

What happens when a `u8` goes past 255?

- in **debug**, the program stops with a panic: `attempt to add with overflow`;
- in **release**, the value "wraps around" to 0.

To avoid depending on the build mode, choose the behavior explicitly:

```rust
fn main() {
    let x: u8 = 250;
    println!("{:?}", x.checked_add(10));    // None: overflowed
    println!("{}", x.wrapping_add(10));     // 4: wraps around
    println!("{}", x.saturating_add(10));   // 255: stops at the maximum
    println!("{:?}", x.overflowing_add(10)); // (4, true): result + flag
}
```

## Parsing a number from text

`parse` needs to know which type to convert to. You tell it through the variable's type or with the *turbofish* syntax `::<>`:

```rust
fn main() {
    let a: i32 = "42".parse().unwrap();
    let b = "3.5".parse::<f64>().unwrap();
    match "abc".parse::<u32>() {
        Ok(n) => println!("number: {n}"),
        Err(e) => println!("error: {e}"),
    }
    println!("{a} {b}");
}
```

## Floating-point numbers are not exact

`f64` follows the IEEE 754 standard and cannot represent many decimal numbers exactly:

```rust
fn main() {
    let x: f64 = 0.1 + 0.2;
    println!("{x}");          // 0.30000000000000004
    println!("{}", x == 0.3); // false

    let almost_equal = (x - 0.3).abs() < 1e-10;
    println!("{almost_equal}");
}
```

Don't compare floating-point numbers with `==` after calculations, and use integers for money (for example, cents instead of dollars).

## Shadowing for transformations

Shadowing is idiomatic when you transform a value in steps and no longer need the old form:

```rust
fn main() {
    let input = " 42 ";
    let input = input.trim();
    let input: u32 = input.parse().unwrap();
    println!("{}", input + 1);
}
```

Without shadowing you would have to invent names like `input_str`, `input_trimmed` and `input_num`.

## `const` or `static`

| | `const` | `static` |
|---|---|---|
| What it is | a value copied wherever it is used | a single memory location for the whole program |
| Fixed address | no | yes |
| When to use it | almost always | when you need a unique address or a large value you don't want to copy |

```rust
const MAX_PLAYERS: usize = 4;
static WELCOME: &str = "Welcome!";

fn main() {
    println!("{WELCOME} At most {MAX_PLAYERS} players.");
}
```

> **Key takeaway:** conversions are always explicit. Prefer `From`/`TryFrom` over `as`, handle overflow explicitly with `checked_*`/`saturating_*`, and don't compare `f64` with `==`.

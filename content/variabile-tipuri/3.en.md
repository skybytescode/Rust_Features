# Variables and types — Advanced

How the compiler infers types, what exactly `as` does, and which "special" types exist beyond numbers and text.

## Type inference works in both directions

The compiler doesn't infer a type only from the assigned value, but also from **later uses** of the variable:

```rust
fn main() {
    let mut v = Vec::new();  // Vec<?>: still unknown
    v.push(1_u16);           // this makes it Vec<u16>
    println!("{v:?}");

    let x = 5;               // still unknown...
    let y: u64 = x * 2;      // ...so `x` becomes u64
    println!("{y}");
}
```

Only when there is no hint at all does an integer literal fall back to `i32`, and a floating-point literal to `f64`.

Sometimes you only need to tell the compiler part of the type. `_` means "infer the rest":

```rust
fn main() {
    let words = "a b c".split(' ').collect::<Vec<_>>();
    println!("{words:?}");
}
```

## What exactly `as` does

`as` never panics. It has precise rules for each combination:

| Conversion | Rule | Example |
|---|---|---|
| integer → smaller integer | keeps the low bits (truncation) | `300_i32 as u8 == 44` |
| signed → unsigned | reinterprets the bits | `-1_i32 as u32 == 4294967295` |
| float → integer | **saturates** at the limits, NaN becomes 0 | `300.7_f32 as u8 == 255` |
| integer → float | rounds to the nearest value | `u64::MAX as f32` |

```rust
fn main() {
    assert_eq!(300_i32 as u8, 44);
    assert_eq!(-1_i32 as u32, u32::MAX);
    assert_eq!(300.7_f32 as u8, 255);
    assert_eq!(-5.0_f64 as u8, 0);
    assert_eq!(f64::NAN as i32, 0);
    println!("every conversion behaves as described in the table");
}
```

Saturation in float-to-integer conversions has existed since Rust 1.45. Before that, out-of-range conversions were undefined behavior.

## Types without "interesting" values

**Unit `()`** is the type with a single value, also written `()`. Functions that "return nothing" and statements ending in `;` return it.

**Never `!`** is the type of expressions that never finish: `panic!`, `loop {}` without `break`, `return`, `continue`. Since it produces no value, it fits any type:

```rust
fn main() {
    let text = "17";
    let n: u32 = match text.parse() {
        Ok(n) => n,
        Err(_) => panic!("not a number"), // `!` fits u32
    };
    println!("{n}");
}
```

## `let ... else`

When a variable can be obtained only if a pattern matches, `let-else` either declares it or leaves the function. The `else` branch must have type `!`:

```rust
fn first_digit(text: &str) -> Option<u32> {
    let Some(c) = text.chars().next() else {
        return None;
    };
    c.to_digit(10)
}

fn main() {
    println!("{:?} {:?}", first_digit("7ab"), first_digit(""));
}
```

## `char` is not a byte

A `char` takes 4 bytes and represents a **Unicode scalar value**. A `String` is stored as UTF-8, where a character takes between 1 and 4 bytes:

```rust
fn main() {
    let s = "naïve 🦀";
    println!("bytes: {}", s.len());              // 11
    println!("characters: {}", s.chars().count()); // 7
    println!("size of a char: {}", size_of::<char>()); // 4
}
```

That's why `s[0]` doesn't compile on a `String`: indexing by byte could cut a character in half.

## Type alias vs. newtype

An **alias** only gives the same type another name. The compiler won't protect you if you mix them up:

```rust
type Meters = f64;
type Seconds = f64;

fn main() {
    let d: Meters = 100.0;
    let t: Seconds = 9.58;
    let wrong = d + t; // compiles, even though it makes no sense
    println!("{wrong}");
}
```

A **newtype** is a struct with a single field. It is a genuinely new type, with no runtime cost:

```rust,compile_fail
struct Meters(f64);
struct Seconds(f64);

fn main() {
    let d = Meters(100.0);
    let t = Seconds(9.58);
    let wrong = d.0 + t; // error: cannot add Seconds to f64
}
```

## Mutable global state

`static mut` exists, but it is almost always the wrong choice: every access requires `unsafe`, and in the 2024 edition references to a `static mut` are denied by default. Use types that synchronize access:

```rust
use std::sync::atomic::{AtomicU32, Ordering};
use std::sync::LazyLock;

static COUNTER: AtomicU32 = AtomicU32::new(0);
static CONFIG: LazyLock<String> = LazyLock::new(|| "initialized on first use".to_string());

fn main() {
    COUNTER.fetch_add(1, Ordering::Relaxed);
    println!("{} — {}", COUNTER.load(Ordering::Relaxed), *CONFIG);
}
```

> **Key takeaway:** type inference uses the whole context. `as` has fixed rules that truncate or saturate but never panic. `!` and `()` are real types, and newtypes give you type safety for free.

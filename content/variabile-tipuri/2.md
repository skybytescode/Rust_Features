# Variabile și tipuri — Practician

Tipurile de bază par simple, dar câteva decizii mici, ca alegerea tipului numeric sau modul de conversie, influențează mult corectitudinea programului.

## Ce tip numeric alegi

- `i32` pentru numere întregi „obișnuite”, dacă nu ai un motiv anume;
- `usize` pentru indecși, lungimi și numărări de elemente. Așa le returnează biblioteca standard (`len()`), iar indexarea cere `usize`;
- `u8` pentru octeți și date binare;
- `f64` pentru numere reale: e la fel de rapid ca `f32` pe procesoarele moderne și mult mai precis;
- `i64` / `u64` când valorile pot depăși ~2 miliarde (timestamp-uri, sume, ID-uri).

## Rust nu face conversii implicite

Nici măcar între două tipuri întregi. Trebuie să convertești explicit:

```rust,compile_fail
fn main() {
    let a: i32 = 10;
    let b: i64 = 20;
    let suma = a + b; // eroare E0308: tipuri diferite
    println!("{suma}");
}
```

Ai trei moduri de a converti:

```rust
fn main() {
    let a: i32 = 10;
    let b: i64 = 20;

    // 1. `From` / `into`: doar conversii care nu pierd informație
    let suma = i64::from(a) + b;

    // 2. `TryFrom` / `try_into`: conversii care pot eșua
    let mare: i64 = 5_000_000_000;
    let r: Result<i32, _> = mare.try_into();
    println!("{suma}, încape în i32? {}", r.is_ok());

    // 3. `as`: conversie forțată, poate trunchia în tăcere
    println!("{}", 300_i32 as u8); // 44
}
```

Folosește `From` când se poate, `TryFrom` când valoarea poate să nu încapă și `as` doar când știi sigur că vrei trunchierea.

## Overflow-ul nu trece neobservat

Ce se întâmplă când un `u8` trece de 255?

- în **debug**, programul se oprește cu panic: `attempt to add with overflow`;
- în **release**, valoarea „se întoarce” la 0 (wrapping).

Ca să nu depinzi de modul de compilare, alege explicit comportamentul:

```rust
fn main() {
    let x: u8 = 250;
    println!("{:?}", x.checked_add(10));    // None: a depășit
    println!("{}", x.wrapping_add(10));     // 4: se întoarce
    println!("{}", x.saturating_add(10));   // 255: se oprește la maxim
    println!("{:?}", x.overflowing_add(10)); // (4, true): rezultat + semnal
}
```

## Citirea unui număr din text

`parse` trebuie să știe în ce tip convertește. I-l spui prin tipul variabilei sau cu sintaxa *turbofish* `::<>`:

```rust
fn main() {
    let a: i32 = "42".parse().unwrap();
    let b = "3.5".parse::<f64>().unwrap();
    match "abc".parse::<u32>() {
        Ok(n) => println!("număr: {n}"),
        Err(e) => println!("eroare: {e}"),
    }
    println!("{a} {b}");
}
```

## Numerele reale nu sunt exacte

`f64` urmează standardul IEEE 754 și nu poate reprezenta exact multe numere zecimale:

```rust
fn main() {
    let x: f64 = 0.1 + 0.2;
    println!("{x}");          // 0.30000000000000004
    println!("{}", x == 0.3); // false

    let aproape_egal = (x - 0.3).abs() < 1e-10;
    println!("{aproape_egal}");
}
```

Nu compara numere reale cu `==` după calcule, iar pentru bani folosește întregi (de exemplu, bani în loc de lei).

## Shadowing pentru transformări

Shadowing-ul e idiomatic când transformi o valoare în pași și nu mai ai nevoie de forma veche:

```rust
fn main() {
    let input = " 42 ";
    let input = input.trim();
    let input: u32 = input.parse().unwrap();
    println!("{}", input + 1);
}
```

Fără shadowing ar trebui să inventezi nume ca `input_str`, `input_trim` și `input_num`.

## `const` sau `static`

| | `const` | `static` |
|---|---|---|
| Ce este | o valoare copiată la fiecare folosire | o singură locație în memorie, pe toată durata programului |
| Adresă fixă | nu | da |
| Când îl folosești | aproape întotdeauna | când ai nevoie de o adresă unică sau de o valoare mare pe care nu vrei s-o copiezi |

```rust
const MAX_JUCATORI: usize = 4;
static SALUT: &str = "Bun venit!";

fn main() {
    println!("{SALUT} Maxim {MAX_JUCATORI} jucători.");
}
```

> **De reținut:** conversiile sunt întotdeauna explicite. Preferă `From`/`TryFrom` în locul lui `as`, tratează overflow-ul explicit cu `checked_*`/`saturating_*` și nu compara `f64` cu `==`.

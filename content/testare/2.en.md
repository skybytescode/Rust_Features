# Testing — Practitioner

Expected panics, tests that return `Result`, ignored tests and the three kinds of tests: unit, integration and documentation tests.

## Expected panics: `#[should_panic]`

When the correct behavior is a panic, you mark the test with `#[should_panic]`. With `expected` you also check part of the message:

```rust
pub struct Percent(u8);

impl Percent {
    pub fn new(v: u8) -> Percent {
        if v > 100 {
            panic!("the percentage must be at most 100, got {v}");
        }
        Percent(v)
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    #[should_panic(expected = "at most 100")]
    fn rejects_above_100() {
        Percent::new(150);
    }

    #[test]
    fn accepts_100() {
        assert_eq!(Percent::new(100).0, 100);
    }
}
```

## Tests that return `Result`

A test can return `Result<(), E>`. That way you can use `?`, and an `Err` makes the test fail:

```rust
fn parse_age(s: &str) -> Result<u8, std::num::ParseIntError> {
    s.trim().parse()
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn parses_with_spaces() -> Result<(), Box<dyn std::error::Error>> {
        let v = parse_age(" 42 ")?;
        assert_eq!(v, 42);
        Ok(())
    }

    #[test]
    fn error_on_text() {
        assert!(parse_age("abc").is_err());
    }
}
```

## Ignored tests

Slow tests or tests that need external resources can be marked `#[ignore]`:

```rust
#[test]
#[ignore = "takes a few minutes"]
fn full_performance_test() {
    // ...
}

#[test]
fn quick_test() {
    assert_eq!(1 + 1, 2);
}
```

```bash
cargo test                    # skips the ignored ones
cargo test -- --ignored       # only the ignored ones
cargo test -- --include-ignored  # all of them
```

## Integration tests

**Unit** tests live next to the code and can test private functions. **Integration** tests live in the `tests/` directory and use the library exactly like an external user would, that is only through the public API:

```text
calculator/
├── src/
│   └── lib.rs
└── tests/
    ├── operations.rs      // each file is a separate test crate
    └── common/
        └── mod.rs         // shared helper code (not run as a test)
```

```rust,ignore
// tests/operations.rs
use calculator::evaluate;

#[test]
fn simple_addition() {
    assert_eq!(evaluate("2 + 3"), Ok(5));
}
```

```bash
cargo test --test operations   # only one integration file
```

Integration tests work only for crates with a library (`src/lib.rs`). One more reason to put the logic in the library and keep `main.rs` thin.

## Documentation tests

The code blocks in a library's `///` comments are compiled and run by `cargo test`. The examples in the documentation can't go stale without you finding out:

````rust,ignore
/// Divides two integers.
///
/// ```
/// assert_eq!(calculator::divide(10, 2), Some(5));
/// assert_eq!(calculator::divide(1, 0), None);
/// ```
pub fn divide(a: i32, b: i32) -> Option<i32> {
    if b == 0 { None } else { Some(a / b) }
}
````

Lines starting with `# ` are hidden in the generated documentation, but they are compiled. They're useful for `use` statements or setup that would clutter the example.

## Helper functions for tests

Repetitive test code moves into ordinary functions in the `tests` module:

```rust
#[derive(Debug, PartialEq)]
pub struct User {
    pub name: String,
    pub admin: bool,
}

pub fn can_delete(u: &User) -> bool {
    u.admin
}

#[cfg(test)]
mod tests {
    use super::*;

    fn user(name: &str, admin: bool) -> User {
        User { name: name.into(), admin }
    }

    #[test]
    fn admin_can_delete() {
        assert!(can_delete(&user("ana", true)));
    }

    #[test]
    fn regular_user_cannot() {
        assert!(!can_delete(&user("mike", false)));
    }
}
```

> **Key takeaway:** `#[should_panic(expected = "...")]` tests panics, and tests that return `Result` can use `?`. `#[ignore]` sets slow tests aside. Unit tests live in `mod tests`, integration tests in `tests/`, and documentation tests in `///`.

# Testare — Practician

Panic-uri așteptate, teste care returnează `Result`, teste ignorate și cele trei tipuri de teste: unitare, de integrare și din documentație.

## Panic-uri așteptate: `#[should_panic]`

Când comportamentul corect este un panic, marchezi testul cu `#[should_panic]`. Cu `expected` verifici și o parte din mesaj:

```rust
pub struct Procent(u8);

impl Procent {
    pub fn new(v: u8) -> Procent {
        if v > 100 {
            panic!("procentul trebuie să fie cel mult 100, primit {v}");
        }
        Procent(v)
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    #[should_panic(expected = "cel mult 100")]
    fn respinge_peste_100() {
        Procent::new(150);
    }

    #[test]
    fn accepta_100() {
        assert_eq!(Procent::new(100).0, 100);
    }
}
```

## Teste care returnează `Result`

Un test poate returna `Result<(), E>`. Așa poți folosi `?`, iar un `Err` face testul să pice:

```rust
fn parseaza_varsta(s: &str) -> Result<u8, std::num::ParseIntError> {
    s.trim().parse()
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn parseaza_cu_spatii() -> Result<(), Box<dyn std::error::Error>> {
        let v = parseaza_varsta(" 42 ")?;
        assert_eq!(v, 42);
        Ok(())
    }

    #[test]
    fn eroare_pe_text() {
        assert!(parseaza_varsta("abc").is_err());
    }
}
```

## Teste ignorate

Testele lente sau care au nevoie de resurse externe pot fi marcate `#[ignore]`:

```rust
#[test]
#[ignore = "durează câteva minute"]
fn test_complet_de_performanta() {
    // ...
}

#[test]
fn test_rapid() {
    assert_eq!(1 + 1, 2);
}
```

```bash
cargo test                    # sare peste cele ignorate
cargo test -- --ignored       # doar cele ignorate
cargo test -- --include-ignored  # toate
```

## Teste de integrare

Testele **unitare** stau lângă cod și pot testa funcții private. Testele **de integrare** stau în directorul `tests/` și folosesc biblioteca exact ca un utilizator extern, adică doar prin API-ul public:

```text
calculator/
├── src/
│   └── lib.rs
└── tests/
    ├── operatii.rs        // fiecare fișier e un crate de test separat
    └── comun/
        └── mod.rs         // cod ajutător partajat (nu e rulat ca test)
```

```rust,ignore
// tests/operatii.rs
use calculator::evalueaza;

#[test]
fn adunare_simpla() {
    assert_eq!(evalueaza("2 + 3"), Ok(5));
}
```

```bash
cargo test --test operatii   # doar un fișier de integrare
```

Testele de integrare funcționează doar pentru crate-urile cu bibliotecă (`src/lib.rs`). Încă un motiv să pui logica în bibliotecă și să păstrezi `main.rs` subțire.

## Teste în documentație

Blocurile de cod din comentariile `///` ale unei biblioteci sunt compilate și rulate de `cargo test`. Exemplele din documentație nu se pot învechi fără să afli:

````rust,ignore
/// Împarte două numere întregi.
///
/// ```
/// assert_eq!(calculator::imparte(10, 2), Some(5));
/// assert_eq!(calculator::imparte(1, 0), None);
/// ```
pub fn imparte(a: i32, b: i32) -> Option<i32> {
    if b == 0 { None } else { Some(a / b) }
}
````

Liniile care încep cu `# ` sunt ascunse în documentația generată, dar sunt compilate. Sunt utile pentru `use` sau pentru pregătiri care ar încărca exemplul.

## Funcții ajutătoare pentru teste

Codul repetitiv din teste se mută în funcții obișnuite din modulul `tests`:

```rust
#[derive(Debug, PartialEq)]
pub struct Utilizator {
    pub nume: String,
    pub admin: bool,
}

pub fn poate_sterge(u: &Utilizator) -> bool {
    u.admin
}

#[cfg(test)]
mod tests {
    use super::*;

    fn utilizator(nume: &str, admin: bool) -> Utilizator {
        Utilizator { nume: nume.into(), admin }
    }

    #[test]
    fn adminul_poate_sterge() {
        assert!(poate_sterge(&utilizator("ana", true)));
    }

    #[test]
    fn utilizatorul_obisnuit_nu_poate() {
        assert!(!poate_sterge(&utilizator("mihai", false)));
    }
}
```

> **De reținut:** `#[should_panic(expected = "...")]` testează panic-urile, iar testele care returnează `Result` pot folosi `?`. `#[ignore]` lasă deoparte testele lente. Testele unitare stau în `mod tests`, cele de integrare în `tests/`, iar cele din documentație în `///`.

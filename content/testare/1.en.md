# Testing — Fundamentals

Rust has testing built into the language and into Cargo. You don't need any external libraries to get started: you write a function marked `#[test]` and run `cargo test`.

## Your first test

```rust
fn add(a: i32, b: i32) -> i32 {
    a + b
}

#[test]
fn adds_two_numbers() {
    assert_eq!(add(2, 3), 5);
}

#[test]
fn adds_negative_numbers() {
    assert_eq!(add(-4, 1), -3);
}
```

```bash
cargo test
```

```text
running 2 tests
test adds_two_numbers ... ok
test adds_negative_numbers ... ok

test result: ok. 2 passed; 0 failed
```

In Rust Playground, the "Run" button runs the tests automatically when the program has no `main` function.

## The assertion macros

| Macro | The test fails if |
|---|---|
| `assert!(cond)` | `cond` is `false` |
| `assert_eq!(a, b)` | `a != b`; prints both values |
| `assert_ne!(a, b)` | `a == b` |

All of them accept an extra message, with formatting:

```rust
fn is_even(n: u32) -> bool {
    n % 2 == 0
}

#[test]
fn checks_even_numbers() {
    for n in [0, 2, 10, 100] {
        assert!(is_even(n), "{n} should be even");
    }
}
```

## What happens when a test fails

A test fails when it **panics**. `assert_eq!` shows you exactly which values were compared:

```rust,should_panic
fn double(x: i32) -> i32 {
    x * 3 // bug!
}

#[test]
fn double_works() {
    assert_eq!(double(4), 8);
}
```

```text
---- double_works stdout ----
assertion `left == right` failed
  left: 12
 right: 8
```

The other tests keep running: one failing test doesn't stop the rest.

## The test module

The convention is to put tests in a `tests` module, at the end of the same file, marked with `#[cfg(test)]`. That way the test code is compiled **only** for `cargo test`, not into the final program:

```rust
pub fn greet(name: &str) -> String {
    format!("Hello, {name}!")
}

#[cfg(test)]
mod tests {
    use super::*; // brings everything from the parent module into scope

    #[test]
    fn greeting_contains_the_name() {
        let s = greet("Ana");
        assert!(s.contains("Ana"));
    }

    #[test]
    fn exact_greeting() {
        assert_eq!(greet("Mike"), "Hello, Mike!");
    }
}
```

## Running selectively

```bash
cargo test greet            # only the tests whose name contains "greet"
cargo test -- --nocapture   # also shows println! output from tests
```

By default, what a test prints with `println!` is hidden, except for tests that fail.

> **Key takeaway:** a test is a `#[test]` function that fails on panic. `assert!`, `assert_eq!` and `assert_ne!` are the basic tools. Tests live in a `mod tests` marked `#[cfg(test)]` and run with `cargo test`.

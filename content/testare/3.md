# Testare — Avansat

Cum faci codul testabil, testarea bazată pe proprietăți, snapshot-urile, benchmark-urile și testele asincrone.

## Cod testabil: dependențe prin trait-uri

Codul care citește direct ceasul, rețeaua sau fișierele e greu de testat. Dacă primește dependențele printr-un trait, în teste poți folosi o implementare falsă:

```rust
pub trait Ceas {
    fn ora(&self) -> u32;
}

pub struct CeasSistem;
impl Ceas for CeasSistem {
    fn ora(&self) -> u32 {
        12 // în realitate: ora curentă din sistem
    }
}

pub fn salut(ceas: &impl Ceas) -> &'static str {
    match ceas.ora() {
        5..=11 => "Bună dimineața",
        12..=17 => "Bună ziua",
        _ => "Bună seara",
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    struct CeasFix(u32);
    impl Ceas for CeasFix {
        fn ora(&self) -> u32 { self.0 }
    }

    #[test]
    fn dimineata() {
        assert_eq!(salut(&CeasFix(8)), "Bună dimineața");
    }

    #[test]
    fn seara() {
        assert_eq!(salut(&CeasFix(22)), "Bună seara");
    }

    #[test]
    fn limitele_intervalelor() {
        for (ora, asteptat) in [(11, "Bună dimineața"), (12, "Bună ziua"), (17, "Bună ziua"), (18, "Bună seara")] {
            assert_eq!(salut(&CeasFix(ora)), asteptat, "ora {ora}");
        }
    }
}
```

Crate-ul `mockall` generează automat astfel de implementări false, cu așteptări despre apeluri.

## Testarea bazată pe proprietăți

În loc să alegi tu exemplele, descrii o **proprietate** care trebuie să fie adevărată pentru orice intrare. Biblioteca generează sute de intrări aleatoare. Când găsește un contraexemplu, îl **micșorează** la cel mai simplu caz care pică:

```rust,ignore
// Cargo.toml: [dev-dependencies] proptest = "1"
use proptest::prelude::*;

fn inverseaza(s: &str) -> String {
    s.chars().rev().collect()
}

proptest! {
    #[test]
    fn dubla_inversare_e_identitate(s in ".*") {
        prop_assert_eq!(inverseaza(&inverseaza(&s)), s);
    }

    #[test]
    fn sortarea_pastreaza_lungimea(mut v in prop::collection::vec(any::<i32>(), 0..100)) {
        let n = v.len();
        v.sort();
        prop_assert_eq!(v.len(), n);
        prop_assert!(v.windows(2).all(|w| w[0] <= w[1]));
    }
}
```

Proprietăți bune de testat: dus-întors (`decode(encode(x)) == x`), invarianți (sortat, fără duplicate), comparația cu o implementare simplă și evident corectă.

## Teste table-driven fără biblioteci

Pentru multe cazuri similare, o listă de perechi intrare/așteptat e simplă și lizibilă:

```rust
fn roman(mut n: u32) -> String {
    let tabel = [(1000, "M"), (900, "CM"), (500, "D"), (400, "CD"), (100, "C"), (90, "XC"),
                 (50, "L"), (40, "XL"), (10, "X"), (9, "IX"), (5, "V"), (4, "IV"), (1, "I")];
    let mut s = String::new();
    for (valoare, simbol) in tabel {
        while n >= valoare {
            s.push_str(simbol);
            n -= valoare;
        }
    }
    s
}

#[test]
fn cifre_romane() {
    let cazuri = [(1, "I"), (4, "IV"), (9, "IX"), (14, "XIV"), (1994, "MCMXCIV"), (2026, "MMXXVI")];
    for (n, asteptat) in cazuri {
        assert_eq!(roman(n), asteptat, "pentru {n}");
    }
}
```

## Snapshot testing

Pentru ieșiri mari (JSON, HTML, mesaje de eroare), crate-ul `insta` salvează rezultatul într-un fișier la prima rulare și îl compară la următoarele. `cargo insta review` îți arată diferențele și te lasă să le accepți.

## Teste asincrone

Cu tokio, `#[tokio::test]` pornește un runtime pentru fiecare test:

```rust,ignore
#[tokio::test]
async fn raspunde_rapid() {
    let r = tokio::time::timeout(std::time::Duration::from_secs(1), async { 42 }).await;
    assert_eq!(r, Ok(42));
}
```

## Benchmark-uri

Pe stable, standardul este crate-ul **criterion**. Rulează funcția de multe ori, analizează statistic rezultatele și raportează schimbările față de rularea anterioară:

```rust,ignore
// benches/fib.rs   (Cargo.toml: [[bench]] name = "fib", harness = false)
use criterion::{criterion_group, criterion_main, Criterion};
use std::hint::black_box;

fn fib(n: u64) -> u64 {
    if n < 2 { n } else { fib(n - 1) + fib(n - 2) }
}

fn bench(c: &mut Criterion) {
    c.bench_function("fib 20", |b| b.iter(|| fib(black_box(20))));
}

criterion_group!(benches, bench);
criterion_main!(benches);
```

`black_box` împiedică optimizatorul să calculeze rezultatul la compilare. Fără el, ai putea măsura o funcție care nu face nimic.

> **De reținut:** injectează dependențele prin trait-uri ca să le poți înlocui în teste. `proptest` găsește singur contraexemple și le micșorează. Tabelele de cazuri sunt simple și clare. `#[tokio::test]` testează codul async, iar `criterion` măsoară corect performanța.

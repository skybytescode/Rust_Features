# Macros — Practitioner

How to write useful `macro_rules!` macros: syntax fragments, repetitions, multiple rules and name hygiene.

## Fragment types

After `$name:` you write what kind of syntax you accept:

| Fragment | Matches | Example |
|---|---|---|
| `expr` | an expression | `2 + x`, `f(1)` |
| `ident` | an identifier | `counter`, `Point` |
| `ty` | a type | `Vec<u8>`, `&str` |
| `pat` | a pattern | `Some(x)`, `1..=5` |
| `literal` | a literal | `42`, `"text"` |
| `block` | a block `{ ... }` | `{ a + b }` |
| `stmt` | a statement | `let x = 1` |
| `tt` | a single *token tree* (anything) | `+`, `(a b c)` |
| `path` | a path | `std::mem::swap` |

```rust
macro_rules! make_function {
    ($name:ident, $ty:ty, $value:expr) => {
        fn $name() -> $ty {
            $value
        }
    };
}

make_function!(answer, u32, 42);
make_function!(greeting, &'static str, "hello");

fn main() {
    println!("{} {}", answer(), greeting());
}
```

## Repetitions: `$(...),*`

`$( ... ),*` means "zero or more repetitions, separated by commas". `+` requires at least one, and `?` means zero or one:

```rust
macro_rules! sum {
    ($($x:expr),+ $(,)?) => {   // `$(,)?` also accepts a trailing comma
        0 $(+ $x)+
    };
}

macro_rules! hashmap {
    ($($key:expr => $value:expr),* $(,)?) => {{
        let mut m = std::collections::HashMap::new();
        $( m.insert($key, $value); )*
        m
    }};
}

fn main() {
    println!("{}", sum!(1, 2, 3, 4));
    let capitals = hashmap! {
        "Italy" => "Rome",
        "France" => "Paris",
    };
    println!("{:?}", capitals.get("France"));
}
```

Notice the double braces `{{ ... }}`: the outer ones delimit the body of the rule, and the inner ones create a block, so the macro can be used as an expression.

## Multiple rules

Rules are tried **in order**, and the first one that matches wins:

```rust
macro_rules! log {
    (error: $($arg:tt)*) => {
        eprintln!("[ERROR] {}", format!($($arg)*))
    };
    (info: $($arg:tt)*) => {
        println!("[INFO] {}", format!($($arg)*))
    };
    ($($arg:tt)*) => {
        println!("[LOG] {}", format!($($arg)*))
    };
}

fn main() {
    let user = "ana";
    log!(info: "{user} logged in");
    log!(error: "wrong password {} times", 3);
    log!("a plain message");
}
```

`$($arg:tt)*` captures "everything else", so it can be passed on to `format!`.

## Hygiene: the macro's variables don't mix with yours

Variables defined **inside** a macro don't clash with those in the caller's code:

```rust
macro_rules! double {
    ($e:expr) => {{
        let x = $e; // this `x` belongs to the macro
        x * 2
    }};
}

fn main() {
    let x = 10;
    println!("{}", double!(x + 1)); // 22: the outer `x` is untouched
    println!("{x}");
}
```

## Multiple evaluation: a trap

If you use `$e` several times, the expression is **evaluated several times**:

```rust
macro_rules! square_wrong {
    ($e:expr) => {
        $e * $e
    };
}

macro_rules! square_right {
    ($e:expr) => {{
        let v = $e;
        v * v
    }};
}

fn main() {
    let mut n = 0;
    let mut next = || { n += 1; n };
    println!("{}", square_wrong!(next())); // 1 * 2 = 2, not 1
    println!("{}", square_right!(next())); // 3 * 3 = 9
}
```

## Exporting a macro

A macro defined in a library becomes visible in other crates with `#[macro_export]`. Users then import it like any item: `use library::macro_name;`.

> **Key takeaway:** fragments (`expr`, `ident`, `ty`, `tt`…) describe what the macro accepts, `$(...),*` expresses repetitions, and rules are tried in order. Variables in a macro are hygienic. Bind `$e` to a variable so you don't evaluate it several times.

# Macros — Advanced

Techniques for complex declarative macros and an introduction to procedural macros: `derive`, attribute and function-like.

## Recursion and "tt munchers"

A macro can call itself. A **tt muncher** consumes its input piece by piece, one token tree at a time, and calls itself again with the rest:

```rust
macro_rules! count {
    () => { 0usize };
    ($first:tt $($rest:tt)*) => { 1usize + count!($($rest)*) };
}

macro_rules! max {
    ($x:expr) => { $x };
    ($x:expr, $($rest:expr),+) => {{
        let a = $x;
        let b = max!($($rest),+);
        if a > b { a } else { b }
    }};
}

fn main() {
    println!("{}", count!(a b c d e)); // 5
    println!("{}", max!(3, 9, 2, 7));  // 9
}
```

Each level of recursion is a new expansion. The default limit is 128, and `#![recursion_limit = "256"]` raises it.

## Internal accumulators

A common convention is an "internal" rule, marked with `@`, that accumulates the result before emitting it:

```rust
macro_rules! reverse {
    // the entry point
    ($($x:expr),*) => { reverse!(@acc [] $($x),*) };
    // done: emit the accumulator
    (@acc [$($acc:expr),*]) => { [$($acc),*] };
    // move the first element to the front of the accumulator
    (@acc [$($acc:expr),*] $first:expr $(, $rest:expr)*) => {
        reverse!(@acc [$first $(, $acc)*] $($rest),*)
    };
}

fn main() {
    println!("{:?}", reverse!(1, 2, 3, 4));
}
```

## `$crate`: correct paths from any crate

In an exported macro, use `$crate::` for items from your own library. The path stays correct no matter how the user renames the crate:

```rust
pub mod util {
    pub fn format(s: &str) -> String {
        format!("<<{s}>>")
    }
}

#[macro_export]
macro_rules! highlight {
    ($s:expr) => {
        $crate::util::format($s)
    };
}

fn main() {
    println!("{}", highlight!("important"));
}
```

## Generating repetitive code

A very common use case is implementing the same trait for several types:

```rust
trait Description {
    fn description() -> &'static str;
}

macro_rules! impl_description {
    ($($ty:ty => $text:literal),* $(,)?) => {
        $(
            impl Description for $ty {
                fn description() -> &'static str { $text }
            }
        )*
    };
}

impl_description! {
    u8 => "8-bit integer",
    f64 => "double-precision float",
    bool => "boolean value",
}

fn main() {
    println!("{} / {}", u8::description(), bool::description());
}
```

The standard library uses the same technique to implement traits on every numeric type.

## Procedural macros

A **procedural macro** is a Rust function that receives code as a `TokenStream` and returns other code. There are three kinds:

| Kind | Usage | Well-known example |
|---|---|---|
| derive | `#[derive(MyTrait)]` on a struct / enum | `serde::Serialize` |
| attribute | `#[my_attribute]` on any item | `#[tokio::main]` |
| function-like | `my_macro!(...)` | `sqlx::query!` |

They must live in a separate crate, of type `proc-macro`:

```toml
# my_macros/Cargo.toml
[lib]
proc-macro = true

[dependencies]
syn = "2"
quote = "1"
```

A derive that generates a `type_name()` method:

```rust,ignore
// my_macros/src/lib.rs
use proc_macro::TokenStream;
use quote::quote;
use syn::{parse_macro_input, DeriveInput};

#[proc_macro_derive(TypeName)]
pub fn derive_type_name(input: TokenStream) -> TokenStream {
    let ast = parse_macro_input!(input as DeriveInput); // parses the struct
    let name = &ast.ident;
    let text = name.to_string();
    quote! {
        impl #name {
            pub fn type_name() -> &'static str { #text }
        }
    }
    .into()
}
```

```rust,ignore
// in the crate that uses it
use my_macros::TypeName;

#[derive(TypeName)]
struct Order;

fn main() {
    println!("{}", Order::type_name()); // "Order"
}
```

**`syn`** parses the tokens into a syntax tree, and **`quote!`** builds new code, with `#variable` for interpolation.

## When not to use macros

Macros make the code harder to read, the error messages harder to understand, and editor autocompletion less useful. Use them only when a function, a generic or a trait can't do the same thing: a variable number of arguments, generating items (`impl`, `fn`, `struct`), domain-specific syntax.

> **Key takeaway:** recursive macros and tt munchers process their input step by step. `@internal` rules accumulate results, and `$crate::` gives robust paths. Procedural macros (derive, attribute, function-like) live in a `proc-macro` crate and usually use `syn` and `quote`.

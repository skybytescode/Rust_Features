# Conversions and dynamic types — Fundamentals

In Rust, conversions between types are **explicit**: the compiler won't turn an `i32` into an `f64` or a number into text on its own. Here you'll see the most used tools: `as`, `From` / `Into`, `parse` and `to_string`.

## `as` for numbers

`as` converts between primitive numeric types:

```rust
fn main() {
    let integer: i32 = 7;
    let real = integer as f64 / 2.0;      // 3.5
    let rounded = 3.99_f64 as i32;        // 3: the fractional part is cut off
    let small = 300_i32 as u8;            // 44: the extra bits are lost
    let letter = 65_u8 as char;           // 'A'
    let code = 'A' as u32;                // 65
    println!("{real} {rounded} {small} {letter} {code}");
}
```

`as` never fails, but it can silently lose information, as with `300 → 44`. For conversions that can fail there are safer options, at the next level.

## `From` and `Into`

`From` describes a conversion that **always succeeds**. If you have `From`, you automatically get `Into`, in the other direction:

```rust
fn main() {
    let s1 = String::from("hello");      // &str → String
    let s2: String = "hello".into();     // the same conversion, through Into
    let big = i64::from(42_i32);         // i32 → i64: nothing is lost
    let v = Vec::from([1, 2, 3]);        // array → Vec
    let real: f64 = 3_i32.into();        // i32 → f64
    println!("{s1} {s2} {big} {v:?} {real}");
}
```

With `into()`, the target type must be clear from the context, for example from a `: String` annotation.

## From text to number and back

```rust
fn main() {
    let n: u32 = "42".parse().unwrap();
    let x = "3.5".parse::<f64>().unwrap();
    let ok: bool = "true".parse().unwrap();

    let text = n.to_string();
    let other = format!("{x:.1}");
    println!("{} {x} {ok} {text} {other}", n * 2);

    match "abc".parse::<i32>() {
        Ok(v) => println!("number {v}"),
        Err(e) => println!("not a number: {e}"),
    }
}
```

`parse` can fail, so it returns a `Result`. `to_string` works on any type that implements `Display`.

## Conversions between `Option` and `Result`

```rust
fn main() {
    let maybe: Option<u8> = Some(3);
    let result: Result<u8, &str> = maybe.ok_or("missing");   // Option → Result
    let back: Option<u8> = result.ok();                      // Result → Option
    println!("{result:?} {back:?}");

    let empty: Option<u8> = None;
    println!("{:?}", empty.ok_or("missing"));
}
```

## What doesn't convert on its own

Not even two integer types combine automatically:

```rust,compile_fail
fn main() {
    let a: i32 = 5;
    let b: i64 = 10;
    let c = a + b; // error E0308: i32 and i64 are different types
}
```

The fix is an explicit conversion: `i64::from(a) + b`.

> **Key takeaway:** conversions are explicit. `as` converts numbers, but can lose information. `From` / `Into` are for conversions that always succeed, and `parse` and `to_string` bridge text and values.

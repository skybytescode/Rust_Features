# Conversii și tipuri dinamice — Expert

Unde exact au loc coercițiile, cum interacționează deref cu rezolvarea metodelor, cum e implementat `TypeId` și de ce unele implementări de `From` sunt imposibile.

## Locurile de coerciție

Coercițiile au loc doar în **locuri de coerciție** (*coercion sites*), unde compilatorul cunoaște deja tipul așteptat:

- argumentele unei funcții sau metode;
- `let` cu tip explicit, `static` și `const`;
- câmpurile din expresii de construcție (`Struct { camp: valoare }`);
- valoarea returnată de o funcție;
- elementele unui array, când tipul array-ului e cunoscut.

Când tipul așteptat **nu** e cunoscut, ci trebuie dedus, nu se aplică nicio coerciție. Cel mai des întâlnit caz e un parametru generic cu o constrângere de trait:

```rust,compile_fail
trait Suma {
    fn suma(&self) -> i32;
}

impl Suma for &[i32] {
    fn suma(&self) -> i32 { self.iter().sum() }
}

fn total<T: Suma>(x: T) -> i32 { x.suma() }

fn main() {
    let a: &[i32] = &[1, 2, 3];
    println!("{}", total(a));          // OK
    println!("{}", total(&[1, 2, 3])); // eroare E0277: T e dedus ca &[i32; 3], fără coerciție
}
```

Ca să compileze, faci coerciția explicit, la apel: `total(&[1, 2, 3][..])` sau `total(&[1, 2, 3] as &[i32])`.

## Unsizing pentru tipurile tale

`Box<T>` → `Box<dyn Trait>` funcționează datorită trait-ului instabil `CoerceUnsized`, implementat pentru `Box`, `Rc`, `Arc`, `&T` și ceilalți pointeri standard. Pe stable nu-l poți implementa pentru propriul smart pointer. Poți însă face unsizing pe un struct care are ca **ultim** câmp un tip generic:

```rust
struct Eticheta<T: ?Sized> {
    id: u32,
    valoare: T,
}

fn main() {
    let concret: Box<Eticheta<[u8; 4]>> = Box::new(Eticheta { id: 1, valoare: [1, 2, 3, 4] });
    let dinamic: Box<Eticheta<[u8]>> = concret; // unsizing pe ultimul câmp
    println!("{} {:?} {}", dinamic.id, &dinamic.valoare, dinamic.valoare.len());
}
```

## Deref și rezolvarea metodelor

La `x.metoda()`, compilatorul aplică pe rând `*x`, `**x` și așa mai departe, prin `Deref`, până găsește metoda. Ordinea poate surprinde când mai multe straturi au metode cu același nume:

```rust
use std::rc::Rc;

fn main() {
    let a = Rc::new(vec![1, 2, 3]);
    let b = a.clone();               // Rc::clone: doar incrementează contorul
    let c = (*a).clone();            // Vec::clone: copiază datele
    println!("{} {}", Rc::strong_count(&a), c.len());
    let _ = b;
}
```

Din acest motiv, convenția recomandată e `Rc::clone(&a)` în loc de `a.clone()`: e explicit că se clonează pointerul, nu datele.

## `TypeId` și de ce `Any` cere `'static`

`TypeId::of::<T>()` e un identificator de 128 de biți, calculat de compilator dintr-un hash al tipului complet. `downcast_ref` compară `TypeId`-ul valorii cu cel cerut:

```rust
use std::any::{Any, TypeId};

fn main() {
    println!("{}", size_of::<TypeId>()); // 16 octeți
    println!("{}", TypeId::of::<Vec<u8>>() == TypeId::of::<Vec<u8>>());
    println!("{}", TypeId::of::<Vec<u8>>() == TypeId::of::<Vec<i8>>());

    let x: &dyn Any = &5_u32;
    println!("{}", x.type_id() == TypeId::of::<u32>());
}
```

Lifetimes sunt șterse înainte de generarea codului, deci `&'a str` și `&'static str` ar avea același `TypeId`. Dacă `Any` ar accepta tipuri cu lifetimes ne-`'static`, ai putea face downcast de la un `&'scurt T` la un `&'static T` și ai citi memorie eliberată. Constrângerea `T: 'static` închide această gaură.

## Downcasting pe propriile trait-uri

Un `dyn TraitulMeu` nu poate fi transformat direct înapoi în tipul concret. Tehnica standard e o metodă `as_any`. Din Rust 1.86 există însă și upcasting-ul direct `&dyn TraitulMeu` → `&dyn Any`, dacă `Any` e supertrait:

```rust
use std::any::Any;

trait Componenta: Any {
    fn nume(&self) -> &'static str;
}

struct Buton { eticheta: String }
struct Imagine;

impl Componenta for Buton { fn nume(&self) -> &'static str { "buton" } }
impl Componenta for Imagine { fn nume(&self) -> &'static str { "imagine" } }

fn main() {
    let ui: Vec<Box<dyn Componenta>> = vec![Box::new(Buton { eticheta: "OK".into() }), Box::new(Imagine)];
    for c in &ui {
        let ca_any: &dyn Any = c.as_ref(); // upcasting: dyn Componenta → dyn Any
        match ca_any.downcast_ref::<Buton>() {
            Some(b) => println!("{}: {}", c.nume(), b.eticheta),
            None => println!("{}", c.nume()),
        }
    }
}
```

## Implementări de `From` imposibile

`impl<T> From<T> for T` (reflexivă) și `impl<T, U: From<T>> Into<U> for T` sunt implementări blanket din biblioteca standard. Ele exclud anumite implementări care par rezonabile:

```rust,compile_fail
struct Cutie<T>(T);

// pare natural: orice valoare poate intra într-o cutie...
impl<T, U: Into<T>> From<U> for Cutie<T> {
    fn from(u: U) -> Self { Cutie(u.into()) }
}
// eroare E0119: pentru U = Cutie<T>, intră în conflict cu `impl<T> From<T> for T`

fn main() {}
```

Soluția obișnuită e o metodă proprie (`Cutie::new(x.into())`) sau o implementare concretă pentru fiecare tip sursă.

> **De reținut:** coercițiile apar doar unde tipul așteptat e cunoscut. Deref se aplică în lanț, inclusiv la rezolvarea metodelor, de unde vine convenția `Rc::clone(&x)`. `TypeId` e un hash de 128 de biți al tipului, iar `Any` cere `'static` pentru că lifetimes sunt șterse. Implementările blanket din `std` interzic unele `From`-uri generice.

# Conversions and dynamic types — Practitioner

How to implement conversions for your own types and how to write functions that accept several kinds of arguments.

## `From` for your types

```rust
#[derive(Debug)]
struct Celsius(f64);

#[derive(Debug)]
struct Fahrenheit(f64);

impl From<Celsius> for Fahrenheit {
    fn from(c: Celsius) -> Self {
        Fahrenheit(c.0 * 9.0 / 5.0 + 32.0)
    }
}

fn main() {
    let f = Fahrenheit::from(Celsius(100.0));
    let g: Fahrenheit = Celsius(-40.0).into(); // Into comes for free
    println!("{f:?} {g:?}");
}
```

Always implement `From`, never `Into` directly: the standard library's blanket implementation gives you `Into` automatically.

## `TryFrom` for conversions that can fail

```rust
use std::convert::TryFrom;

#[derive(Debug)]
struct Percent(u8);

impl TryFrom<i32> for Percent {
    type Error = String;

    fn try_from(v: i32) -> Result<Self, Self::Error> {
        if (0..=100).contains(&v) {
            Ok(Percent(v as u8))
        } else {
            Err(format!("{v} isn't between 0 and 100"))
        }
    }
}

fn main() {
    println!("{:?}", Percent::try_from(42));
    let r: Result<Percent, _> = 150.try_into();
    println!("{r:?}");

    // The standard library has TryFrom between all integer types:
    println!("{:?}", u8::try_from(300_i32));
    println!("{:?}", u8::try_from(200_i32));
}
```

## `FromStr`: your own type, compatible with `parse`

```rust
use std::str::FromStr;

#[derive(Debug)]
struct Point {
    x: i32,
    y: i32,
}

impl FromStr for Point {
    type Err = String;

    fn from_str(s: &str) -> Result<Self, Self::Err> {
        let (x, y) = s
            .trim_matches(|c| c == '(' || c == ')')
            .split_once(',')
            .ok_or("missing comma")?;
        let x = x.trim().parse().map_err(|_| "invalid x")?;
        let y = y.trim().parse().map_err(|_| "invalid y")?;
        Ok(Point { x, y })
    }
}

fn main() {
    let p: Point = "(3, -4)".parse().unwrap();
    println!("{p:?}");
    println!("{:?}", "(3 -4)".parse::<Point>());
}
```

## `Display` gives you `to_string`

Every type with `Display` automatically gets `to_string()`:

```rust
use std::fmt;

struct Version(u32, u32, u32);

impl fmt::Display for Version {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "v{}.{}.{}", self.0, self.1, self.2)
    }
}

fn main() {
    let text: String = Version(1, 4, 2).to_string();
    println!("{text}");
}
```

## Flexible parameters with `AsRef` and `Into`

`AsRef<T>` means "I can be cheaply viewed as a `&T`". It's ideal for functions that only read:

```rust
use std::path::Path;

fn has_extension(path: impl AsRef<Path>, ext: &str) -> bool {
    path.as_ref().extension().is_some_and(|e| e == ext)
}

fn count_letters(text: impl AsRef<str>) -> usize {
    text.as_ref().chars().filter(|c| c.is_alphabetic()).count()
}

fn main() {
    println!("{}", has_extension("photo.jpg", "jpg"));                // &str
    println!("{}", has_extension(String::from("doc.pdf"), "jpg"));    // String
    println!("{}", has_extension(Path::new("/tmp/a.jpg"), "jpg"));    // &Path
    println!("{} {}", count_letters("ab1c"), count_letters(String::from("xyz")));
}
```

`Into<T>` suits functions that **keep** the value, for example in a struct:

```rust
struct User {
    name: String,
}

impl User {
    fn new(name: impl Into<String>) -> Self {
        User { name: name.into() } // allocates only if needed
    }
}

fn main() {
    let a = User::new("Ana");                 // &str → String
    let b = User::new(String::from("John"));  // String: moved, no copy
    println!("{} {}", a.name, b.name);
}
```

| Your function… | Takes |
|---|---|
| only reads | `&str` / `&[T]`, or `impl AsRef<...>` for flexibility |
| keeps the value | `impl Into<String>` or `String` directly |
| may fail to convert | `impl TryInto<...>` |

> **Key takeaway:** implement `From`, and `Into` comes automatically. `TryFrom` is for conversions that can fail, and `FromStr` makes the type work with `parse`. `AsRef` suits read-only parameters, `Into` suits values you keep.

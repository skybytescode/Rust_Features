# Conversions and dynamic types — Advanced

The conversions the compiler performs on its own (coercions), the difference between `AsRef` and `Borrow`, and dynamic types: `Any` and downcasting.

## Coercions: allowed implicit conversions

Although Rust does no implicit numeric conversions, a few conversions **between pointer types** are automatic, in certain places: function arguments, `let` with an explicit type, returned values.

```rust
use std::fmt::Display;

fn length(s: &str) -> usize { s.len() }
fn sum(v: &[i32]) -> i32 { v.iter().sum() }
fn show(x: &dyn Display) -> String { x.to_string() }

fn main() {
    let text = String::from("hello");
    let boxed: Box<String> = Box::new(String::from("boxed"));

    // 1. Deref coercion: &String → &str, &Box<String> → &String → &str
    println!("{} {}", length(&text), length(&boxed));

    // 2. Unsizing: &[i32; 3] → &[i32], &i32 → &dyn Display
    println!("{} {}", sum(&[1, 2, 3]), show(&42));

    // 3. &mut T → &T
    let mut v = vec![1, 2];
    let r: &Vec<i32> = &mut v;
    println!("{r:?}");

    // 4. Box<T> → Box<dyn Trait>
    let shapes: Vec<Box<dyn Display>> = vec![Box::new(1), Box::new("two"), Box::new(3.0)];
    for s in &shapes {
        print!("{s} ");
    }
    println!();
}
```

Deref coercion applies **in a chain**, as many times as needed, until the types match. That's why `&Box<String>` reaches `&str` without any conversion written.

## The rules of `as`, by category

| From | To | Behavior |
|---|---|---|
| integer | integer | truncation or sign extension |
| float | integer | saturates, and NaN becomes 0 |
| integer / float | float | the nearest value |
| `bool` / `char` | integer | `false = 0`, `true = 1` / the Unicode code |
| `u8` | `char` | only from `u8`; for `u32` you use `char::from_u32` |
| enum without data | integer | the discriminant |
| `&T` / `*const T` | `*const T` / `*const U` / `usize` | pointer conversions |

```rust
#[derive(Clone, Copy)]
enum Direction { North = 1, South = 2 }

fn main() {
    println!("{}", Direction::South as i32);
    println!("{:?}", char::from_u32(0x1F980));    // Some('🦀')
    println!("{:?}", char::from_u32(0xD800));     // None: a surrogate, not a valid character
    let x = 5;
    let address = &x as *const i32 as usize;      // pointer → number
    println!("{}", address % std::mem::align_of::<i32>() == 0);
    let _ = Direction::North;
}
```

## `AsRef` vs. `Borrow`

Both traits give a `&T` "view" of a value, but they promise different things:

- `AsRef<T>`: a cheap conversion, with no other guarantees. `String: AsRef<[u8]>`, `String: AsRef<Path>`, `String: AsRef<str>`.
- `Borrow<T>`: additionally, `Hash`, `Eq` and `Ord` give **the same** result on the original value and on the view. That's why `HashMap::get` requires `Borrow`, not `AsRef`. Otherwise, looking up a key through its borrowed form could produce a different hash.

```rust
use std::borrow::Borrow;
use std::collections::HashMap;

fn lookup<Q>(m: &HashMap<String, u32>, key: &Q) -> Option<u32>
where
    String: Borrow<Q>,
    Q: std::hash::Hash + Eq + ?Sized,
{
    m.get(key).copied()
}

fn main() {
    let mut m = HashMap::new();
    m.insert("ana".to_string(), 30);
    println!("{:?}", lookup(&m, "ana"));               // with &str
    println!("{:?}", lookup(&m, &"ana".to_string()));  // with &String
}
```

## Dynamic types: `Any`

`std::any::Any` lets you ask "what concrete type is behind this `dyn`?" at runtime:

```rust
use std::any::{Any, type_name_of_val};

fn describe(value: &dyn Any) -> String {
    if let Some(n) = value.downcast_ref::<i32>() {
        format!("an i32: {n}")
    } else if let Some(s) = value.downcast_ref::<String>() {
        format!("a String of {} characters", s.len())
    } else {
        "an unknown type".to_string()
    }
}

fn main() {
    let list: Vec<Box<dyn Any>> = vec![Box::new(7), Box::new(String::from("rust")), Box::new(2.5)];
    for v in &list {
        println!("{}", describe(v.as_ref()));
    }

    // a Box<dyn Any> can be turned back into the concrete type
    let b: Box<dyn Any> = Box::new(String::from("recovered"));
    match b.downcast::<String>() {
        Ok(s) => println!("{s}"),
        Err(_) => println!("another type"),
    }

    println!("{}", type_name_of_val(&list)); // the type's name, for debugging
}
```

`Any` works only for `'static` types. Use it sparingly: an `enum` or a trait with methods is almost always a better design than testing the type at runtime.

> **Key takeaway:** the automatic coercions are deref (in a chain), unsizing (`[T; N]` → `[T]`, `T` → `dyn Trait`) and `&mut` → `&`. `Borrow` guarantees identical `Hash` and `Eq`, while `AsRef` doesn't. `Any` + `downcast_ref` recover the concrete type at runtime, but only for `'static` types.

# Async/await — Expert

We build from scratch, using only the standard library, the pieces a runtime like tokio hides: a hand-written `Future`, a `Waker` and an executor.

## A hand-written future

A timer that becomes ready after a duration. On the first `poll` it starts a thread that, once the time has passed, calls `waker.wake()`:

```rust
use std::future::Future;
use std::pin::Pin;
use std::sync::{Arc, Mutex};
use std::task::{Context, Poll, Waker};
use std::thread;
use std::time::Duration;

struct State {
    ready: bool,
    waker: Option<Waker>,
}

pub struct Timer {
    state: Arc<Mutex<State>>,
}

impl Timer {
    pub fn new(duration: Duration) -> Self {
        let state = Arc::new(Mutex::new(State { ready: false, waker: None }));
        let s = Arc::clone(&state);
        thread::spawn(move || {
            thread::sleep(duration);
            let mut s = s.lock().unwrap();
            s.ready = true;
            if let Some(w) = s.waker.take() {
                w.wake(); // tells the executor it's worth polling us again
            }
        });
        Timer { state }
    }
}

impl Future for Timer {
    type Output = ();
    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<()> {
        let mut s = self.state.lock().unwrap();
        if s.ready {
            Poll::Ready(())
        } else {
            // Keep the most recent waker: the future may move between tasks.
            s.waker = Some(cx.waker().clone());
            Poll::Pending
        }
    }
}

fn main() {
    // We poll by hand, with a waker that does nothing: without an executor
    // that reacts to wake(), we have to retry ourselves.
    let mut timer = std::pin::pin!(Timer::new(Duration::from_millis(30)));
    let mut cx = Context::from_waker(Waker::noop());
    let mut polls = 1;
    while timer.as_mut().poll(&mut cx).is_pending() {
        polls += 1;
        thread::sleep(Duration::from_millis(10));
    }
    println!("ready after {} polls", if polls > 1 { "several" } else { "a single" });
}
```

The loop above "guesses" when to retry. A real executor sleeps until the waker wakes it up.

**The contract of a future:** when you return `Pending`, you must make sure the waker will eventually be called. Otherwise, the task stays stuck forever, with no error.

## A minimal executor

The simplest executor runs a single future on the current thread. Between `poll`s, the thread sleeps, and the waker wakes it:

```rust
use std::future::Future;
use std::pin::pin;
use std::sync::Arc;
use std::task::{Context, Poll, Wake, Waker};
use std::thread::{self, Thread};

struct WakeThread(Thread);

impl Wake for WakeThread {
    fn wake(self: Arc<Self>) {
        self.0.unpark();
    }
}

fn block_on<F: Future>(fut: F) -> F::Output {
    let mut fut = pin!(fut); // pinned on the stack
    let waker = Waker::from(Arc::new(WakeThread(thread::current())));
    let mut cx = Context::from_waker(&waker);
    loop {
        match fut.as_mut().poll(&mut cx) {
            Poll::Ready(v) => return v,
            Poll::Pending => thread::park(), // sleeps until wake()
        }
    }
}

async fn add(a: u32, b: u32) -> u32 {
    a + b
}

fn main() {
    let result = block_on(async {
        let x = add(2, 3).await;
        let y = add(x, 10).await;
        y * 2
    });
    println!("{result}");
}
```

`thread::park` can also return without an `unpark`. That isn't a problem, because the loop polls again, and an extra `poll` is always allowed.

## Executor + timer together, with several tasks

An executor with several tasks keeps a **queue**. Each task's waker puts it back in the queue:

```rust
use std::collections::VecDeque;
use std::future::Future;
use std::pin::Pin;
use std::sync::{Arc, Mutex};
use std::task::{Context, Poll, Wake, Waker};
use std::time::{Duration, Instant};

type TaskFuture = Pin<Box<dyn Future<Output = ()> + Send>>;

struct Task {
    fut: Mutex<Option<TaskFuture>>,
    queue: Arc<Mutex<VecDeque<Arc<Task>>>>,
}

impl Wake for Task {
    fn wake(self: Arc<Self>) {
        let queue = Arc::clone(&self.queue);
        queue.lock().unwrap().push_back(self);
    }
}

// Simplified timer: one thread per timer, as in the previous example
struct Timer { ready: Arc<Mutex<(bool, Option<Waker>)>> }

impl Timer {
    fn new(d: Duration) -> Self {
        let ready = Arc::new(Mutex::new((false, None::<Waker>)));
        let r = Arc::clone(&ready);
        std::thread::spawn(move || {
            std::thread::sleep(d);
            let mut s = r.lock().unwrap();
            s.0 = true;
            if let Some(w) = s.1.take() { w.wake(); }
        });
        Timer { ready }
    }
}

impl Future for Timer {
    type Output = ();
    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<()> {
        let mut s = self.ready.lock().unwrap();
        if s.0 { Poll::Ready(()) } else { s.1 = Some(cx.waker().clone()); Poll::Pending }
    }
}

fn main() {
    let queue: Arc<Mutex<VecDeque<Arc<Task>>>> = Arc::new(Mutex::new(VecDeque::new()));
    let start = Instant::now();

    for (id, ms) in [(1, 120), (2, 40), (3, 80)] {
        let fut: TaskFuture = Box::pin(async move {
            Timer::new(Duration::from_millis(ms)).await;
            println!("task {id} done after ~{ms} ms");
        });
        let t = Arc::new(Task { fut: Mutex::new(Some(fut)), queue: Arc::clone(&queue) });
        queue.lock().unwrap().push_back(t);
    }

    let mut remaining = 3;
    while remaining > 0 {
        let next = queue.lock().unwrap().pop_front();
        let Some(task) = next else {
            std::thread::sleep(Duration::from_millis(1)); // a real executor would use park/unpark
            continue;
        };
        let mut slot = task.fut.lock().unwrap();
        if let Some(mut fut) = slot.take() {
            let waker = Waker::from(Arc::clone(&task));
            let mut cx = Context::from_waker(&waker);
            if fut.as_mut().poll(&mut cx).is_pending() {
                *slot = Some(fut); // put it back; the waker will reschedule it
            } else {
                remaining -= 1;
            }
        }
    }
    println!("total: ~{} ms (not 240: the timers overlapped)", start.elapsed().as_millis() / 40 * 40);
}
```

Tokio does exactly this, but with a *reactor* that uses `epoll` / `kqueue` / IOCP instead of a thread per timer, with per-thread queues and *work stealing* between them.

## What a real runtime adds

- **I/O reactor**: registers sockets with the operating system and calls the waker when they become readable or writable;
- **timer wheel**: thousands of timers without thousands of threads;
- **work stealing**: idle threads "steal" tasks from the queues of busy ones;
- **cooperative budget**: forces a task that never returns `Pending` to yield from time to time.

> **Key takeaway:** a future returns `Pending` only after storing the waker, and `wake()` reschedules it. An executor is a loop that polls the tasks in its queue. `Wake` + `Arc` build a `Waker` without `unsafe`. Tokio adds an I/O reactor, efficient timers and work stealing.

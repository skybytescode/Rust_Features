# Async/await — Practitioner

Independent tasks, picking the first result, timeouts and the most common mistake: blocking the runtime.

## `tokio::spawn`: independent tasks

`spawn` starts a future as a separate **task**, which the runtime can run on any thread. You get a `JoinHandle`, as with threads:

```rust
use std::time::Duration;

#[tokio::main]
async fn main() {
    let mut tasks = Vec::new();
    for id in 1..=3 {
        tasks.push(tokio::spawn(async move {
            tokio::time::sleep(Duration::from_millis(50 * id)).await;
            id * 10
        }));
    }

    let mut total = 0;
    for t in tasks {
        total += t.await.unwrap(); // Err only if the task panicked
    }
    println!("total: {total}");
}
```

A task started with `spawn` must be `Send + 'static`, because it can run on another thread and outlive the current function. That's where the need for `move` and `Arc` comes from.

## `join!` vs. `spawn`

| | `join!` | `spawn` |
|---|---|---|
| Runs on | the current task (concurrently, not necessarily in parallel) | any runtime thread |
| Requires `Send + 'static` | no, it can borrow | yes |
| If you drop it | it stops | it keeps going in the background |

## `select!`: whichever finishes first

`select!` waits for several futures and continues with the **first** one to finish. The others are cancelled:

```rust
use std::time::Duration;

async fn slow_server() -> &'static str {
    tokio::time::sleep(Duration::from_millis(300)).await;
    "slow response"
}

async fn fast_server() -> &'static str {
    tokio::time::sleep(Duration::from_millis(50)).await;
    "fast response"
}

#[tokio::main]
async fn main() {
    tokio::select! {
        r = slow_server() => println!("first: {r}"),
        r = fast_server() => println!("first: {r}"),
    }
}
```

## Timeout

```rust
use std::time::Duration;
use tokio::time::timeout;

async fn long_operation() -> u32 {
    tokio::time::sleep(Duration::from_secs(10)).await;
    42
}

#[tokio::main]
async fn main() {
    match timeout(Duration::from_millis(100), long_operation()).await {
        Ok(v) => println!("result: {v}"),
        Err(_) => println!("timed out"),
    }
}
```

## Don't block the runtime

The runtime has few threads. If a task does a long computation or calls a **blocking** function (`std::thread::sleep`, `std::fs`, a synchronous HTTP client), it also blocks the other tasks on that thread. Use:

- the async versions: `tokio::time::sleep`, `tokio::fs`, `tokio::net`;
- `spawn_blocking` for blocking code or heavy computations.

```rust
#[tokio::main]
async fn main() {
    let result = tokio::task::spawn_blocking(|| {
        // runs on a separate thread, reserved for blocking operations
        (1..=5_000_000u64).filter(|n| n % 7 == 0).count()
    })
    .await
    .unwrap();
    println!("{result}");
}
```

## Async channels

Tokio has its own channels, which can be awaited with `.await`:

```rust
use tokio::sync::mpsc;

#[tokio::main]
async fn main() {
    let (tx, mut rx) = mpsc::channel(8); // capacity 8: `send` waits if it's full

    for id in 0..3 {
        let tx = tx.clone();
        tokio::spawn(async move {
            tx.send(format!("message from {id}")).await.unwrap();
        });
    }
    drop(tx);

    let mut messages = Vec::new();
    while let Some(m) = rx.recv().await {
        messages.push(m);
    }
    messages.sort();
    println!("{messages:?}");
}
```

## Mutexes in async

`std::sync::Mutex` is fine as long as you **don't** hold the lock across an `.await`. If you need to hold it across an `.await`, use `tokio::sync::Mutex`, whose `lock()` is awaited with `.await`:

```rust
use std::sync::Arc;
use tokio::sync::Mutex;

#[tokio::main]
async fn main() {
    let log = Arc::new(Mutex::new(Vec::new()));
    let mut tasks = Vec::new();
    for i in 0..3 {
        let l = Arc::clone(&log);
        tasks.push(tokio::spawn(async move {
            let mut g = l.lock().await;
            tokio::task::yield_now().await; // an .await while we hold the lock
            g.push(i);
        }));
    }
    for t in tasks {
        t.await.unwrap();
    }
    println!("{} entries", log.lock().await.len());
}
```

> **Key takeaway:** `spawn` starts independent tasks (`Send + 'static`), `join!` runs them concurrently in place, and `select!` takes the first result. Don't block the runtime: use the async APIs or `spawn_blocking`. For locks held across `.await`, use `tokio::sync::Mutex`.

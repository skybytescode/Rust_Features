# Async/await — Advanced

What a `Future` is, how `async fn` becomes a state machine, why `Pin` shows up, how cancellation works, and what async in traits and `async` closures bring.

## The `Future` trait

```rust,ignore
pub trait Future {
    type Output;
    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>;
}

pub enum Poll<T> {
    Ready(T),
    Pending,
}
```

The runtime calls `poll`. If the result is ready, the future returns `Ready(value)`. If it isn't, it returns `Pending` and **promises** to notify the runtime (through `cx.waker()`) when it's worth calling again. The runtime doesn't retry blindly: it waits for the signal.

## `async fn` becomes a state machine

The compiler turns every `async fn` into an anonymous enum. Each variant is an `.await` point, and the variables that live across that point are its fields:

```rust,ignore
async fn example() -> usize {
    let a = String::from("hello");
    step_one().await;         // state 1: keeps `a`
    let b = a.len();
    step_two().await;         // state 2: keeps `b`
    b
}
// ≈ enum ExampleFuture { Start, Await1 { a, f1 }, Await2 { b, f2 }, Done }
```

The size of the future is the size of its largest state. You can see the effect directly:

```rust
async fn small() -> u8 {
    tokio::task::yield_now().await;
    1
}

async fn large() -> u8 {
    let buffer = [0u8; 4096]; // lives across the .await, so it goes into the future
    tokio::task::yield_now().await;
    buffer[0]
}

#[tokio::main]
async fn main() {
    println!("small: {} bytes", size_of_val(&small()));
    println!("large: {} bytes", size_of_val(&large()));
    println!("{} {}", small().await, large().await);
}
```

A large future means large copies every time it moves. Large values that must live across an `.await` are better off in a `Box` or a `Vec`.

## Why `Pin`

A state can hold a **reference to another variable in the same state**: for example, `let r = &a; x.await; use(r);`. The future becomes *self-referential*. If it were moved in memory after the first `poll`, `r` would point to the old address. That's why `poll` takes `Pin<&mut Self>`: once pinned, the future can no longer be moved.

In practice: `Box::pin(fut)` or `std::pin::pin!(fut)` when you need a pinned future, for example so you can use it in a `select!` inside a loop.

## Cancellation by drop

A cancelled future doesn't get an exception. It is simply **destroyed** (`drop`) and never polled again. Execution stops at the last `.await` reached, and the variables' destructors run normally:

```rust
use std::time::Duration;

struct Guard(&'static str);
impl Drop for Guard {
    fn drop(&mut self) {
        println!("cleaning up: {}", self.0);
    }
}

async fn long_work() {
    let _g = Guard("temporary resource");
    println!("starting");
    tokio::time::sleep(Duration::from_secs(10)).await;
    println!("never reached");
}

#[tokio::main]
async fn main() {
    let r = tokio::time::timeout(Duration::from_millis(50), long_work()).await;
    println!("cancelled: {}", r.is_err());
}
```

The important consequence is **cancellation safety**: if a future is cancelled in a `select!` between two `.await`s, any intermediate state is lost. The tokio documentation marks the methods that are cancellation safe.

## `async fn` in traits

Since Rust 1.75, traits can have `async` methods:

```rust
trait Repository {
    async fn find(&self, id: u32) -> Option<String>;
}

struct InMemory;

impl Repository for InMemory {
    async fn find(&self, id: u32) -> Option<String> {
        tokio::task::yield_now().await;
        (id == 1).then(|| "Ana".to_string())
    }
}

#[tokio::main]
async fn main() {
    let r = InMemory;
    println!("{:?} {:?}", r.find(1).await, r.find(2).await);
}
```

Limitations: such a trait isn't dyn-compatible yet, and the caller can't require the returned future to be `Send`. For `dyn` or `Send` constraints, the `async-trait` crate (which uses `Box<dyn Future>`) is still useful.

## `async` closures

Since Rust 1.85, `async || { ... }` creates a closure whose futures can borrow from its captures. The corresponding traits are `AsyncFn`, `AsyncFnMut` and `AsyncFnOnce`:

```rust
async fn twice(f: impl AsyncFn(u32) -> u32) -> u32 {
    f(1).await + f(2).await
}

#[tokio::main]
async fn main() {
    let factor = 10;
    let multiply = async |x: u32| {
        tokio::task::yield_now().await;
        x * factor
    };
    println!("{}", twice(multiply).await);
}
```

> **Key takeaway:** a `Future` is polled with `poll` and signals through a `Waker` when it can continue. `async fn` becomes a state machine, and values that live across `.await` increase its size. `Pin` protects self-referential futures. Cancellation means drop. Async in traits and `async` closures are stable.

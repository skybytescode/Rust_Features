# Async/await — Fundamentals

**Asynchronous** programming lets you wait for several slow things at once (network, files, timers) without a thread for each one. While one operation waits, the program works on others.

## The problem

A server that downloads 1000 web pages spends almost all its time **waiting** for responses. With one thread per request you have 1000 threads, each with its own stack, most of them sleeping. Async solves this with a few threads that switch between tasks exactly when one has to wait.

## `async fn` and `.await`

An `async` function doesn't run immediately. It returns a **future**: a promise of a future value. With `.await` you ask for the result. While you wait, other tasks can run:

```rust
use std::time::Duration;

async fn download(page: &str) -> String {
    tokio::time::sleep(Duration::from_millis(100)).await; // simulates the network
    format!("contents of the {page} page")
}

#[tokio::main]
async fn main() {
    let result = download("home").await;
    println!("{result}");
}
```

## You need a runtime

Rust defines only the language (`async`, `.await`, the `Future` trait). For futures to actually run, you need a **runtime**: a library that decides which task runs and when. The most used one is **tokio**:

```toml
[dependencies]
tokio = { version = "1", features = ["full"] }
```

`#[tokio::main]` turns `main` into an ordinary function that starts the runtime and runs your future.

## Several operations in parallel

The real advantage shows when you wait for several things **at the same time**. `tokio::join!` runs them all and waits for them to finish:

```rust
use std::time::{Duration, Instant};

async fn download(page: &str, ms: u64) -> String {
    tokio::time::sleep(Duration::from_millis(ms)).await;
    format!("{page} ({ms} ms)")
}

#[tokio::main]
async fn main() {
    let start = Instant::now();

    let (a, b, c) = tokio::join!(
        download("news", 300),
        download("weather", 200),
        download("sports", 100),
    );

    println!("{a}\n{b}\n{c}");
    // ~300 ms in total, not 600: the three waits overlap
    println!("duration: ~{} ms", start.elapsed().as_millis() / 100 * 100);
}
```

## Futures are lazy

A future does **nothing** until it is awaited with `.await` or handed to a runtime:

```rust
async fn hello() {
    println!("hello from async");
}

#[tokio::main]
async fn main() {
    let f = hello(); // prints nothing yet
    println!("future created");
    f.await;         // only now does it run
}
```

The compiler warns you if you forget `.await`: "futures do nothing unless you `.await` or poll them".

## Async or threads?

| Your task | Choose |
|---|---|
| many operations that **wait** (network, web servers, databases) | async |
| heavy computations that **use the CPU** | threads (or `rayon`) |
| a small program, with a few operations | ordinary synchronous code |

> **Key takeaway:** `async fn` returns a future, and `.await` waits for the result without blocking other tasks. You need a runtime, usually tokio. `join!` runs several futures at once, and futures do nothing until awaited.

# Ownership and borrowing — Advanced

The borrow checker doesn't reason at the level of curly braces but at the level of **control flow**. Once you know how it thinks, you understand why some programs pass and others don't.

## Non-lexical lifetimes (NLL)

A borrow lasts until the **last use** of the reference, not until the end of the block.

```rust
fn main() {
    let mut v = vec![1, 2, 3];
    let first = &v[0];
    println!("{first}"); // last use of `first`
    v.push(4);           // OK: the shared borrow has already ended
    println!("{v:?}");
}
```

Before Rust 2018 this program was rejected. NLL moved the analysis onto the function's control-flow graph.

## Two-phase borrows

The following call seems to break the golden rule: `v.push` needs `&mut v`, and the argument `v.len()` needs `&v`.

```rust
fn main() {
    let mut v = vec![1, 2, 3];
    v.push(v.len());
    println!("{v:?}");
}
```

It compiles because the mutable borrow of the receiver is first only **reserved**. It becomes active only after the arguments are evaluated.

## Reborrowing

When you pass on a `&mut T`, the compiler doesn't move it but implicitly creates a shorter-lived **reborrow** `&mut *r`:

```rust
fn increment(x: &mut i32) {
    *x += 1;
}

fn main() {
    let mut n = 0;
    let r = &mut n;
    increment(r); // actually increment(&mut *r)
    increment(r); // `r` is still usable
    println!("{n}");
}
```

`&mut T` is not `Copy`. Without reborrowing, the first call would consume `r`.

## Disjoint borrows

The borrow checker tracks the **fields** of a struct separately, so you can mutably borrow two different fields at the same time:

```rust
struct Game {
    players: Vec<String>,
    score: u32,
}

fn main() {
    let mut game = Game { players: vec!["Ana".into()], score: 0 };
    let p = &mut game.players;
    let s = &mut game.score; // OK: a different field
    p.push("Mike".into());
    *s += 10;
    println!("{} players, score {}", game.players.len(), game.score);
}
```

This separation doesn't cross method calls, though: `game.players_mut()` borrows the whole `game`. For slice indexes, the compiler can't prove they are disjoint, so the standard library provides `split_at_mut`:

```rust
fn main() {
    let mut v = [1, 2, 3, 4];
    let (left, right) = v.split_at_mut(2);
    left[0] += right[0];
    println!("{v:?}");
}
```

## Partial moves

You can move a single field out of a struct. The remaining fields stay usable, but the struct as a whole doesn't:

```rust,compile_fail
struct Person {
    name: String,
    city: String,
}

fn main() {
    let p = Person { name: "Ana".into(), city: "Cluj".into() };
    let name = p.name;      // partial move
    println!("{}", p.city); // OK
    let copy = p;           // error: `p` has been partially moved
}
```

If the type implements `Drop`, even a partial move is not allowed, because `drop` needs the whole value.

## When static rules aren't enough

Some patterns, such as graphs or shared caches, can't be expressed with rules checked at compile time. Then the check moves to runtime through **interior mutability**: `Cell`, `RefCell`, `Mutex`. We cover them in the Smart pointers chapter.

> **Key takeaway:** borrows live as long as they are used, not as long as the block. The compiler tracks fields separately, but not indexes or method calls.

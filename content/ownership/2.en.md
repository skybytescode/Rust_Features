# Ownership and borrowing — Practitioner

In real code you don't move and clone values everywhere. Most of the time you **borrow** them through references.

## References: `&T` and `&mut T`

A reference gives you access to a value without taking ownership.

```rust
fn length(text: &String) -> usize {
    text.len()
}

fn add_exclamation(text: &mut String) {
    text.push('!');
}

fn main() {
    let mut s = String::from("hello");
    add_exclamation(&mut s);
    println!("{s} has {} characters", length(&s));
}
```

## The golden rule of borrowing

At any given time you can have **either**:

- any number of **shared** references (`&T`), **or**
- **exactly one** **mutable** reference (`&mut T`).

You can't have both at the same time. This rule eliminates a whole class of bugs at compile time: data races, invalidated iterators, changes "behind your back".

```rust,compile_fail
fn main() {
    let mut v = vec![1, 2, 3];
    let first = &v[0];    // shared borrow
    v.push(4);            // error E0502: mutable borrow while `first` is alive
    println!("{first}");
}
```

The error isn't pedantry: `push` may reallocate the vector, and `first` would end up pointing to freed memory.

## Idiomatic parameters: `&str` instead of `&String`

A function that only reads text should take `&str`. That way it accepts both `String` and literals:

```rust
fn greet(name: &str) {
    println!("Hello, {name}!");
}

fn main() {
    let owned = String::from("Ana");
    greet(&owned);  // &String converts automatically to &str
    greet("Mike");  // the literal is already &str
}
```

The same principle applies to `&[T]` instead of `&Vec<T>`.

## How to choose the parameter type

| The function needs to… | Use |
|---|---|
| only read the value | `&T` / `&str` / `&[T]` |
| modify the value | `&mut T` |
| keep it (e.g. in a struct) | `T`, by ownership |

## Common errors and how to fix them

**E0382: use after move.** You usually passed by value something you only wanted to borrow. Change the parameter to `&T` before reaching for `.clone()`.

**E0502 / E0499: overlapping borrows.** Shorten the borrow: read the value you need into a variable, then modify.

```rust
fn main() {
    let mut v = vec![1, 2, 3];
    let first = v[0]; // a copy of the i32, not a reference
    v.push(first * 10);
    println!("{v:?}");
}
```

**E0106 / E0515: returning a reference to a local variable.** The local value disappears when the function returns, so return the value itself:

```rust,compile_fail
fn create() -> &String {
    let s = String::from("hello");
    &s // `s` is freed at the end of the function
}

fn main() {
    create();
}
```

```rust
fn create() -> String {
    String::from("hello") // ownership moves to the caller
}

fn main() {
    println!("{}", create());
}
```

> **Key takeaway:** borrow by default, move only when the function must keep the value, and clone only when you really need two copies.

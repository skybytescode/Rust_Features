# Ownership și borrowing — Avansat

Borrow checker-ul nu raționează la nivel de acolade, ci la nivel de **flux de control**. Când știi cum gândește, înțelegi de ce unele programe trec și altele nu.

## Non-lexical lifetimes (NLL)

Un împrumut durează până la **ultima folosire** a referinței, nu până la sfârșitul blocului.

```rust
fn main() {
    let mut v = vec![1, 2, 3];
    let primul = &v[0];
    println!("{primul}"); // ultima folosire a lui `primul`
    v.push(4);            // OK: împrumutul partajat s-a încheiat deja
    println!("{v:?}");
}
```

Înainte de Rust 2018 programul acesta era respins. NLL a mutat analiza pe graful de control al funcției.

## Two-phase borrows

Apelul următor pare să încalce regula de aur: `v.push` cere `&mut v`, iar argumentul `v.len()` cere `&v`.

```rust
fn main() {
    let mut v = vec![1, 2, 3];
    v.push(v.len());
    println!("{v:?}");
}
```

Compilează, pentru că împrumutul mutabil al receptorului este mai întâi doar **rezervat**. Devine activ abia după evaluarea argumentelor.

## Reborrowing

Când dai mai departe un `&mut T`, compilatorul nu îl mută, ci creează implicit un **reborrow** `&mut *r`, cu durată mai scurtă:

```rust
fn incrementeaza(x: &mut i32) {
    *x += 1;
}

fn main() {
    let mut n = 0;
    let r = &mut n;
    incrementeaza(r); // de fapt incrementeaza(&mut *r)
    incrementeaza(r); // `r` este încă utilizabil
    println!("{n}");
}
```

`&mut T` nu este `Copy`. Fără reborrowing, primul apel ar consuma `r`.

## Împrumuturi disjuncte

Borrow checker-ul urmărește separat **câmpurile** unui struct, așa că poți împrumuta mutabil două câmpuri diferite în același timp:

```rust
struct Joc {
    jucatori: Vec<String>,
    scor: u32,
}

fn main() {
    let mut joc = Joc { jucatori: vec!["Ana".into()], scor: 0 };
    let j = &mut joc.jucatori;
    let s = &mut joc.scor; // OK: câmp diferit
    j.push("Mihai".into());
    *s += 10;
    println!("{} jucători, scor {}", joc.jucatori.len(), joc.scor);
}
```

Separarea nu trece însă prin apeluri de metode: `joc.jucatori_mut()` împrumută întregul `joc`. La indecși de slice, compilatorul nu poate demonstra că sunt disjuncți, așa că biblioteca standard oferă `split_at_mut`:

```rust
fn main() {
    let mut v = [1, 2, 3, 4];
    let (stanga, dreapta) = v.split_at_mut(2);
    stanga[0] += dreapta[0];
    println!("{v:?}");
}
```

## Move-uri parțiale

Poți muta un singur câmp dintr-un struct. Restul câmpurilor rămân utilizabile, dar structul ca întreg nu mai e:

```rust,compile_fail
struct Persoana {
    nume: String,
    oras: String,
}

fn main() {
    let p = Persoana { nume: "Ana".into(), oras: "Cluj".into() };
    let nume = p.nume;      // move parțial
    println!("{}", p.oras); // OK
    let copie = p;          // eroare: `p` a fost parțial mutat
}
```

Dacă tipul implementează `Drop`, nici move-ul parțial nu e permis, pentru că `drop` are nevoie de valoarea întreagă.

## Când regulile statice nu ajung

Unele modele, ca grafurile sau cache-urile partajate, nu pot fi exprimate cu reguli verificate la compilare. Atunci verificarea se mută la runtime prin **interior mutability**: `Cell`, `RefCell`, `Mutex`. Le tratăm în capitolul Smart pointers.

> **De reținut:** împrumuturile trăiesc cât sunt folosite, nu cât blocul. Compilatorul urmărește câmpurile separat, dar nu și indecșii sau apelurile de metodă.

# Functions — Practitioner

How to design your functions: what they take, what they return, and how to tie them to your own types through methods.

## Returning several values

A function returns a single value, but that value can be a tuple:

```rust
fn min_max(values: &[i32]) -> (i32, i32) {
    let mut min = values[0];
    let mut max = values[0];
    for &v in values {
        if v < min { min = v; }
        if v > max { max = v; }
    }
    (min, max)
}

fn main() {
    let (low, high) = min_max(&[4, -2, 9, 3]);
    println!("min {low}, max {high}");
}
```

If the values have a clear meaning, a struct with named fields is usually more readable than a tuple.

## When the result can be missing

The function above panics on an empty list. It's better to return an `Option`:

```rust
fn maximum(values: &[i32]) -> Option<i32> {
    let mut iter = values.iter();
    let mut max = *iter.next()?; // `?` returns None if the list is empty
    for &v in iter {
        if v > max { max = v; }
    }
    Some(max)
}

fn main() {
    println!("{:?} {:?}", maximum(&[3, 8, 1]), maximum(&[]));
}
```

`Option` and `Result` are explained in detail in the Error handling chapter.

## Methods and associated functions

Functions tied to a type go in an `impl` block:

- a **method** has `self`, `&self` or `&mut self` as its first parameter and is called with a dot: `account.deposit(50)`;
- an **associated function** has no `self` and is called with `::`, for example `Account::new()`. By convention, the constructor is called `new`.

```rust
struct Account {
    holder: String,
    balance: u64,
}

impl Account {
    fn new(holder: &str) -> Self {
        Account { holder: holder.to_string(), balance: 0 }
    }

    fn deposit(&mut self, amount: u64) {
        self.balance += amount;
    }

    fn balance(&self) -> u64 {
        self.balance
    }
}

fn main() {
    let mut account = Account::new("Ana");
    account.deposit(150);
    println!("{}: {}", account.holder, account.balance());
}
```

You choose the type of `self` by the same rules as for any parameter:

| The method | Uses |
|---|---|
| only reads | `&self` |
| modifies the object | `&mut self` |
| consumes the object (transforms or destroys it) | `self` |

## Documenting functions

Comments with `///` become documentation, generated with `cargo doc`. In a library, the code examples in the documentation of public functions are compiled and run as tests by `cargo test` (*doc tests*):

````rust
/// Computes the arithmetic mean.
///
/// Returns `None` if the list is empty.
///
/// ```
/// assert_eq!(mean(&[2.0, 4.0]), Some(3.0));
/// ```
fn mean(values: &[f64]) -> Option<f64> {
    if values.is_empty() {
        return None;
    }
    Some(values.iter().sum::<f64>() / values.len() as f64)
}

fn main() {
    println!("{:?}", mean(&[1.0, 2.0, 6.0]));
}
````

## Small functions with a single purpose

- Keep functions short. If you need a comment to explain what part of one does, move that part into a separate function with a clear name.
- For parameters, prefer the more general types (`&str`, `&[T]`) over the more restrictive ones (`&String`, `&Vec<T>`). See the Ownership chapter.
- Avoid many `bool` parameters: `send(true, false)` says nothing when you read it. An `enum` with clear names is better.

> **Key takeaway:** return a tuple or a struct for multiple values and an `Option` when the result can be missing. Methods take `self` / `&self` / `&mut self`, and associated functions such as `new` are called with `::`.

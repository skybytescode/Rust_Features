# Functions — Expert

What a function really is to the compiler: a unique zero-sized type, a symbol in the binary, a calling convention and a unit of inlining.

## Every function has its own type

The name of a function doesn't have the type `fn(i32) -> i32`. It has a unique, anonymous, zero-sized **function item type**. The conversion to a function pointer only happens when a type requires it:

```rust
fn double(x: i32) -> i32 { x * 2 }
fn triple(x: i32) -> i32 { x * 3 }

fn main() {
    let item = double;               // unique type: fn(i32) -> i32 {double}
    let ptr: fn(i32) -> i32 = double; // function pointer

    println!("item: {} bytes", size_of_val(&item)); // 0
    println!("ptr:  {} bytes", size_of_val(&ptr));  // 8 on 64 bits

    // `if` needs a common type, so the two items become pointers
    let f = if std::env::args().count() > 5 { double } else { triple };
    println!("{}", f(10));
}
```

Because the item is zero-sized and its type identifies it exactly, a generic `F: Fn(i32) -> i32` instantiated with `double` can be fully inlined. An `fn(i32) -> i32` goes through an indirect call, unless the optimizer manages to remove it.

## Monomorphization

A generic function is compiled **separately for each type** it is used with. The resulting code is fast, with no indirect calls, but the binary grows. A common technique in the standard library is a thin generic "shell" over a non-generic inner function:

```rust
use std::path::Path;

pub fn read<P: AsRef<Path>>(path: P) -> std::io::Result<String> {
    // only the conversion is generic; the rest is compiled once
    fn inner(path: &Path) -> std::io::Result<String> {
        std::fs::read_to_string(path)
    }
    inner(path.as_ref())
}

fn main() {
    println!("{}", read("/nonexistent/file").is_err());
}
```

`std::fs::read_to_string` is written exactly this way.

## Inlining across crates

A non-generic function can be inlined in another crate only if it is marked `#[inline]` or LTO is enabled. Generic functions are instantiated in the crate that uses them, so they can be inlined anyway.

| Attribute | Effect |
|---|---|
| `#[inline]` | makes the body available to other crates; only a suggestion |
| `#[inline(always)]` | a strong suggestion; still not guaranteed |
| `#[inline(never)]` | prevents inlining (useful for profiling and for cold paths) |

## Calling conventions (ABI)

`extern "Rust"`, the default, **has no stable ABI**: the way parameters are passed can change between compiler versions. To talk to C or another language, you declare `extern "C"` explicitly:

```rust
#[unsafe(no_mangle)]
pub extern "C" fn add(a: i32, b: i32) -> i32 {
    a + b
}

fn main() {
    // it can also be called from Rust, like any function
    println!("{}", add(2, 3));
}
```

`#[no_mangle]` keeps the exact symbol name in the binary. In the 2024 edition it must be written `#[unsafe(no_mangle)]`, because two symbols with the same name can cause undefined behavior at link time.

An ABI detail: large values returned by a function don't fit in registers. The caller reserves space on its own stack and passes a hidden pointer to it (*sret*), and the function writes the result directly there. That's why returning a large struct by value is usually cheap.

## Name mangling

To allow functions with the same name in different modules and distinct generic instances, the compiler encodes the full path and the generic parameters in the symbol. The default scheme is still the "legacy" one. The new **v0** scheme is enabled with `-C symbol-mangling-version=v0` and keeps more information, including generic types. Tools like `rustfilt` translate the symbols back.

## `#[track_caller]` and `#[must_use]`

`#[track_caller]` makes a panic report the location of the **caller**, not the one inside the function. That's how `unwrap()` works: the message shows your line, not a line in the standard library.

```rust,should_panic
#[track_caller]
fn check_positive(x: i32) -> i32 {
    if x <= 0 {
        panic!("expected a positive number, got {x}");
    }
    x
}

fn main() {
    println!("{}", check_positive(5));
    check_positive(-1); // the panic reports this line
}
```

`#[must_use]` produces a warning if the function's result is ignored. The standard library puts it on `Result`, on iterators and on many methods that return a new value instead of modifying something, for example `str::trim`.

> **Key takeaway:** each function has its own zero-sized type, and `fn(...)` is an ordinary pointer. Generics are monomorphized, `#[inline]` matters at crate boundaries, and `extern "C"` gives the only stable ABI.

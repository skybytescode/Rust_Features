# Functions — Advanced

Functions are values: you can store them in variables, pass them as arguments and return them. That opens the way to generics, closures and functions evaluated at compile time.

## Functions as values

A function can be passed anywhere a **function pointer** is expected, with the type `fn(param) -> ret`:

```rust
fn double(x: i32) -> i32 { x * 2 }
fn square(x: i32) -> i32 { x * x }

fn apply_twice(f: fn(i32) -> i32, x: i32) -> i32 {
    f(f(x))
}

fn main() {
    let operations: [(&str, fn(i32) -> i32); 2] = [("double", double), ("square", square)];
    for (name, op) in operations {
        println!("{name}: {}", apply_twice(op, 3));
    }
}
```

Closures that capture nothing can also be converted to `fn`. Those that do capture can't, and for them you use generics with `Fn` (see the Closures and iterators chapter).

## Generic functions

A generic function is written once and works for any type that meets the constraints (trait bounds):

```rust
fn largest<T: PartialOrd + Copy>(values: &[T]) -> Option<T> {
    let mut max = *values.first()?;
    for &v in values {
        if v > max { max = v; }
    }
    Some(max)
}

fn main() {
    println!("{:?}", largest(&[3, 9, 2]));
    println!("{:?}", largest(&[1.5, -0.5]));
    println!("{:?}", largest(&['a', 'z', 'm']));
}
```

## `impl Trait` in arguments and in the return type

- In **arguments**, `impl Trait` is shorthand for a generic parameter: `fn f(x: impl Display)` means `fn f<T: Display>(x: T)`.
- In the **return type**, `impl Trait` hides the concrete type. It is the only way to return a closure or a composed iterator without `Box`.

```rust
use std::fmt::Display;

fn show(x: impl Display) {
    println!("[{x}]");
}

fn even_numbers(limit: u32) -> impl Iterator<Item = u32> {
    (0..limit).filter(|n| n % 2 == 0)
}

fn main() {
    show(42);
    show("text");
    let v: Vec<_> = even_numbers(10).collect();
    println!("{v:?}");
}
```

## Functions that never return

A function with return type `!` never returns to its caller: it panics, exits the process or runs forever. A call to it fits any type:

```rust
fn fatal_error(message: &str) -> ! {
    eprintln!("error: {message}");
    std::process::exit(1)
}

fn main() {
    let port: u16 = match "8080".parse() {
        Ok(p) => p,
        Err(_) => fatal_error("invalid port"),
    };
    println!("{port}");
}
```

## `const fn`

A `const fn` can also be called at compile time, in `const`, `static` or array lengths:

```rust
const fn kib(n: usize) -> usize {
    n * 1024
}

const BUFFER: usize = kib(4);

fn main() {
    let buffer = [0u8; BUFFER]; // the length is computed at compile time
    println!("{} bytes; at runtime: {}", buffer.len(), kib(2));
}
```

The restriction: in the body of a `const fn` you can only use operations the compiler can evaluate. That list grows with each release.

## Recursion

Rust allows recursion, but **doesn't guarantee** tail-call optimization. Deep recursion can overflow the stack, so for large depths turn the algorithm into a loop:

```rust
fn fibonacci(n: u32) -> u64 {
    let (mut a, mut b) = (0u64, 1u64);
    for _ in 0..n {
        (a, b) = (b, a + b);
    }
    a
}

fn main() {
    println!("{}", fibonacci(90));
}
```

> **Key takeaway:** functions are values of type `fn(...)`. Generics and `impl Trait` write code once for several types. `-> !` marks functions that never return, `const fn` also runs at compile time, and recursion has no guaranteed TCO.

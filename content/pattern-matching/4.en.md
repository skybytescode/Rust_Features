# Pattern matching — Expert

Cum verifică compilatorul exhaustivitatea, cum traduce pattern-urile în cod, ce reguli noi a adus ediția 2024 și cum interacționează pattern-urile cu tipurile fără valori.

## Algoritmul de exhaustivitate

Verificarea folosește algoritmul de **usefulness** (Maranget). Pentru fiecare ramură, compilatorul întreabă dacă există vreo valoare care se potrivește cu ea și cu niciuna dintre ramurile anterioare:

- dacă nu există, ramura e **inutilă**, iar compilatorul dă warning-ul `unreachable_patterns`;
- la final, întreabă dacă pattern-ul `_` mai e util după toate ramurile. Dacă da, `match`-ul **nu e exhaustiv**, iar mesajul de eroare îți arată o valoare-contraexemplu.

Guard-urile (`if`) sunt ignorate în această analiză, pentru că compilatorul nu poate demonstra ce rezultat dau.

```rust,compile_fail
fn main() {
    let pereche: (bool, Option<u8>) = (true, Some(3));
    match pereche {
        (true, Some(_)) => {}
        (false, None) => {}
        (_, Some(0..=9)) => {}
        // eroare E0004: `(true, None)` și `(false, Some(10_u8..=u8::MAX))` nu sunt acoperite
    }
}
```

## Traducerea în arbore de decizie

În MIR, un `match` devine o serie de teste (`switchInt` pe discriminant, comparații pe valori și intervale) organizate ca **arbore de decizie**. Compilatorul încearcă să nu testeze de două ori același lucru, iar guard-urile se evaluează într-o ordine garantată: de sus în jos, doar dacă pattern-ul s-a potrivit.

Un detaliu de semantică: un guard vede variabilele legate **prin referință**, chiar dacă ramura le mută. Mutarea efectivă are loc abia după ce guard-ul trece:

```rust
fn main() {
    let o = Some(String::from("salut"));
    match o {
        Some(s) if s.len() > 3 => println!("lung: {s}"), // `s` e mutat doar dacă guard-ul trece
        Some(s) => println!("scurt: {s}"),
        None => {}
    }
}
```

## Ediția 2024: reguli mai stricte pentru binding modes

Când compilatorul a intrat automat într-o referință (*default binding mode* `ref`), ediția 2024 interzice să mai scrii explicit `ref`, `ref mut`, `mut` sau `&` în acel pattern. Combinația era confuză, iar regula lasă loc pentru îmbunătățiri viitoare ale match ergonomics:

```rust,compile_fail
fn main() {
    let v = &(1, String::from("a"));
    let (ref a, b) = v; // 2024: eroare „cannot explicitly borrow within an implicitly-borrowing pattern”
    println!("{a} {b}");
}
```

Ai două corecturi posibile: scrii pattern-ul complet explicit, `let &(ref a, ref b) = v;`, sau îl lași complet implicit, `let (a, b) = v;`. `cargo fix --edition` face transformarea automat.

## Tipuri fără valori și exhaustivitate

Un enum fără variante (sau `!`) nu are valori, deci nu trebuie tratat. Din Rust 1.82, ramurile pentru astfel de tipuri pot lipsi atunci când valoarea e citită direct, nu prin referință sau pointer:

```rust
use std::convert::Infallible;

enum Niciodata {}

fn parseaza(text: &str) -> Result<String, Infallible> {
    Ok(text.to_uppercase())
}

fn absurd(n: Niciodata) -> u32 {
    match n {} // match fără ramuri: nu există nicio valoare de tratat
}

fn main() {
    let Ok(s) = parseaza("rust"); // fără ramură Err
    println!("{s}");
    let _ = absurd; // nu poate fi apelată niciodată
}
```

Prin referință (`&Niciodata`), regula nu se aplică încă. Codul `unsafe` poate crea referințe către memorie invalidă, așa că limbajul nu presupune automat că o referință către un tip fără valori nu poate exista.

## Pattern-uri pe constante de tip float

Constantele `f32` / `f64` sunt permise ca pattern-uri, dar `NaN` nu: `NaN != NaN`, deci un astfel de pattern nu s-ar potrivi niciodată. Intervalele de numere reale sunt permise:

```rust
fn clasifica(x: f64) -> &'static str {
    match x {
        f if f.is_nan() => "NaN",
        ..0.0 => "negativ",
        0.0 => "zero",
        0.0..=1.0 => "între 0 și 1",
        _ => "mare",
    }
}

fn main() {
    for x in [-1.0, 0.0, -0.0, 0.5, 7.0, f64::NAN] {
        println!("{x}: {}", clasifica(x));
    }
}
```

`-0.0` se potrivește cu pattern-ul `0.0`, pentru că pattern-urile folosesc comparația IEEE, unde `-0.0 == 0.0`. Intervalul exclusiv `..0.0` e stabil din Rust 1.80.

> **De reținut:** exhaustivitatea se verifică prin „usefulness”, fără guard-uri. Un `match` devine un arbore de decizie în MIR. Ediția 2024 interzice `ref` explicit sub un binding implicit. Tipurile fără valori pot lipsi din `match` când valoarea e citită direct.

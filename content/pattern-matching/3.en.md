# Pattern matching — Advanced

What exactly a pattern does when you apply it to a reference, how patterns work on slices, and where you can use patterns besides `match`.

## Refutable and irrefutable patterns

- An **irrefutable** pattern matches every value of its type: `x`, `(a, b)`, `Point { x, y }`. Only these are allowed in a plain `let`, in function parameters and in `for`.
- A **refutable** pattern can fail: `Some(x)`, `1..=5`. You can use it in `match`, `if let`, `while let` and `let-else`.

```rust,compile_fail
fn main() {
    let o: Option<i32> = Some(5);
    let Some(x) = o; // error E0005: refutable pattern in `let`
    println!("{x}");
}
```

## Patterns in parameters

The parameters of functions and closures are irrefutable patterns:

```rust
fn distance(&(x1, y1): &(f64, f64), &(x2, y2): &(f64, f64)) -> f64 {
    ((x2 - x1).powi(2) + (y2 - y1).powi(2)).sqrt()
}

fn main() {
    println!("{}", distance(&(0.0, 0.0), &(3.0, 4.0)));

    let pairs = vec![("a", 1), ("b", 2)];
    let total: i32 = pairs.iter().map(|&(_, n)| n).sum();
    println!("{total}");
}
```

## Binding modes: what happens when you match on a reference

When you match on `&T` with a pattern that doesn't start with `&`, the compiler automatically "steps into" the reference, and the variables become references. The mechanism is called *default binding modes* or *match ergonomics*:

```rust
fn main() {
    let pair = (String::from("key"), 42);
    let r = &pair;

    let (text, number) = r; // text: &String, number: &i32
    println!("{text} {number}");

    // the same effect, written explicitly:
    let &(ref text2, number2) = r; // number2: i32 (copied)
    println!("{text2} {number2}");
}
```

The same mechanism lets you match on `&Option<String>` without moving the string out of it:

```rust
fn length(o: &Option<String>) -> usize {
    match o {
        Some(s) => s.len(), // s: &String, not String
        None => 0,
    }
}

fn main() {
    let name = Some(String::from("Ana"));
    println!("{}", length(&name));
    println!("{name:?}"); // `name` is still valid
}
```

## Slice patterns

Patterns can break down slices and arrays by length, with `..` for "the rest":

```rust
fn describe(v: &[i32]) -> String {
    match v {
        [] => "empty".into(),
        [x] => format!("one element: {x}"),
        [first, .., last] if first == last => format!("starts and ends with {first}"),
        [first, rest @ ..] => format!("{first}, followed by {} more elements", rest.len()),
    }
}

fn main() {
    for v in [&[][..], &[7], &[1, 2, 1], &[3, 4, 5, 6]] {
        println!("{}", describe(v));
    }
}
```

Combined with recursion, slice patterns give very compact algorithms:

```rust
fn sum(v: &[i32]) -> i32 {
    match v {
        [] => 0,
        [head, tail @ ..] => head + sum(tail),
    }
}

fn main() {
    println!("{}", sum(&[1, 2, 3, 4]));
}
```

## Constants in patterns

You can use constants as patterns, but their type must have "structural" equality, that is `#[derive(PartialEq, Eq)]`:

```rust
#[derive(PartialEq, Eq)]
struct Version(u8, u8);

const STABLE: Version = Version(1, 0);

fn main() {
    let v = Version(1, 0);
    match v {
        STABLE => println!("stable version"),
        Version(0, _) => println!("beta version"),
        Version(major, minor) => println!("{major}.{minor}"),
    }
}
```

Watch out: a lowercase name in a pattern is **not** compared with an existing variable. It binds a new variable that matches any value. The compiler warns you in that case ("unreachable pattern").

> **Key takeaway:** `let` and parameters accept only irrefutable patterns. Matching on references automatically produces bindings by reference. Slices break down with `[a, rest @ ..]`, and constants can be patterns if they derive `PartialEq + Eq`.

# Pattern matching — Avansat

Ce face exact un pattern când îl aplici pe o referință, cum funcționează pattern-urile pe slice-uri și unde poți folosi pattern-uri în afară de `match`.

## Pattern-uri refutabile și irefutabile

- Un pattern **irefutabil** se potrivește cu orice valoare de tipul respectiv: `x`, `(a, b)`, `Punct { x, y }`. Doar acestea sunt permise în `let` simplu, în parametrii funcțiilor și în `for`.
- Un pattern **refutabil** poate eșua: `Some(x)`, `1..=5`. Îl poți folosi în `match`, `if let`, `while let` și `let-else`.

```rust,compile_fail
fn main() {
    let o: Option<i32> = Some(5);
    let Some(x) = o; // eroare E0005: pattern refutabil în `let`
    println!("{x}");
}
```

## Pattern-uri în parametri

Parametrii funcțiilor și ai closure-urilor sunt pattern-uri irefutabile:

```rust
fn distanta(&(x1, y1): &(f64, f64), &(x2, y2): &(f64, f64)) -> f64 {
    ((x2 - x1).powi(2) + (y2 - y1).powi(2)).sqrt()
}

fn main() {
    println!("{}", distanta(&(0.0, 0.0), &(3.0, 4.0)));

    let perechi = vec![("a", 1), ("b", 2)];
    let total: i32 = perechi.iter().map(|&(_, n)| n).sum();
    println!("{total}");
}
```

## Binding modes: ce se întâmplă când faci match pe o referință

Când faci match pe `&T` cu un pattern care nu începe cu `&`, compilatorul „intră” automat prin referință, iar variabilele devin referințe. Mecanismul se numește *default binding modes* sau *match ergonomics*:

```rust
fn main() {
    let pereche = (String::from("cheie"), 42);
    let r = &pereche;

    let (text, numar) = r; // text: &String, numar: &i32
    println!("{text} {numar}");

    // același efect, scris explicit:
    let &(ref text2, numar2) = r; // numar2: i32 (copiat)
    println!("{text2} {numar2}");
}
```

Același mecanism îți permite să faci match pe `&Option<String>` fără să muți string-ul din el:

```rust
fn lungime(o: &Option<String>) -> usize {
    match o {
        Some(s) => s.len(), // s: &String, nu String
        None => 0,
    }
}

fn main() {
    let nume = Some(String::from("Ana"));
    println!("{}", lungime(&nume));
    println!("{nume:?}"); // `nume` e încă valid
}
```

## Pattern-uri pe slice-uri

Pattern-urile pot descompune slice-uri și array-uri după lungime, cu `..` pentru „restul”:

```rust
fn descrie(v: &[i32]) -> String {
    match v {
        [] => "gol".into(),
        [x] => format!("un element: {x}"),
        [primul, .., ultimul] if primul == ultimul => format!("începe și se termină cu {primul}"),
        [primul, rest @ ..] => format!("{primul}, urmat de încă {} elemente", rest.len()),
    }
}

fn main() {
    for v in [&[][..], &[7], &[1, 2, 1], &[3, 4, 5, 6]] {
        println!("{}", descrie(v));
    }
}
```

Combinate cu recursivitatea, pattern-urile pe slice-uri dau algoritmi foarte compacți:

```rust
fn suma(v: &[i32]) -> i32 {
    match v {
        [] => 0,
        [cap, coada @ ..] => cap + suma(coada),
    }
}

fn main() {
    println!("{}", suma(&[1, 2, 3, 4]));
}
```

## Constante în pattern-uri

Poți folosi constante ca pattern-uri, dar tipul lor trebuie să aibă egalitate „structurală”, adică `#[derive(PartialEq, Eq)]`:

```rust
#[derive(PartialEq, Eq)]
struct Versiune(u8, u8);

const STABILA: Versiune = Versiune(1, 0);

fn main() {
    let v = Versiune(1, 0);
    match v {
        STABILA => println!("versiune stabilă"),
        Versiune(0, _) => println!("versiune beta"),
        Versiune(major, minor) => println!("{major}.{minor}"),
    }
}
```

Atenție: un nume scris cu litere mici într-un pattern **nu** e comparat cu o variabilă existentă, ci leagă o variabilă nouă care se potrivește cu orice valoare. Compilatorul te avertizează în acest caz („unreachable pattern”).

> **De reținut:** `let` și parametrii acceptă doar pattern-uri irefutabile. Match-ul pe referințe produce automat legături prin referință. Slice-urile se descompun cu `[a, rest @ ..]`, iar constantele pot fi pattern-uri dacă au `PartialEq + Eq` derivat.

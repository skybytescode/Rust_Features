# Pattern matching — Practitioner

Patterns can destructure nested structures, have extra conditions and bind values to names at the same time.

## Destructuring structs

```rust
struct Point {
    x: i32,
    y: i32,
}

fn main() {
    let p = Point { x: 0, y: 7 };

    let Point { x, y } = p; // the fields become variables
    println!("{x} {y}");

    match p {
        Point { x: 0, y } => println!("on the Y axis, at height {y}"),
        Point { y: 0, .. } => println!("on the X axis"),  // `..` ignores the other fields
        Point { x, y } => println!("({x}, {y})"),
    }
}
```

## Nested enums

Patterns can go to any depth:

```rust
enum Color {
    Rgb(u8, u8, u8),
    Gray(u8),
}

enum Command {
    Draw { shape: String, color: Color },
    Clear,
}

fn main() {
    let commands = [
        Command::Draw { shape: "circle".into(), color: Color::Rgb(255, 0, 0) },
        Command::Draw { shape: "square".into(), color: Color::Gray(128) },
        Command::Clear,
    ];

    for c in &commands {
        match c {
            Command::Draw { shape, color: Color::Rgb(r, g, b) } => {
                println!("{shape} RGB({r}, {g}, {b})")
            }
            Command::Draw { shape, color: Color::Gray(n) } => println!("{shape} gray {n}"),
            Command::Clear => println!("clear everything"),
        }
    }
}
```

## Guards: extra conditions

After the pattern you can add `if condition`. The branch is chosen only if the pattern matches **and** the condition is true:

```rust
fn main() {
    let temperatures = [Some(-5), Some(22), Some(38), None];
    for t in temperatures {
        let message = match t {
            Some(d) if d < 0 => "freezing",
            Some(d) if d > 35 => "heatwave",
            Some(_) => "normal",
            None => "faulty sensor",
        };
        println!("{t:?}: {message}");
    }
}
```

## Binding with `@`

`name @ pattern` checks the pattern and keeps the value in a variable at the same time:

```rust
fn main() {
    let age = 15;
    match age {
        child @ 0..=12 => println!("a child of {child}"),
        teen @ 13..=17 => println!("a teenager of {teen}"),
        adult => println!("an adult of {adult}"),
    }
}
```

## `matches!`: a `match` that returns `bool`

```rust
#[derive(Debug)]
enum Status {
    Active,
    Suspended { days: u32 },
    Deleted,
}

fn main() {
    let statuses = [Status::Active, Status::Suspended { days: 3 }, Status::Deleted];
    let can_return = statuses
        .iter()
        .filter(|s| matches!(s, Status::Active | Status::Suspended { days: 0..=7 }))
        .count();
    println!("{can_return} accounts can come back");
}
```

## `while let` and `let-else`

`while let` repeats as long as the pattern matches, and `let-else` extracts the value or leaves the function:

```rust
fn first_long_word(text: &str) -> &str {
    let Some(word) = text.split_whitespace().find(|w| w.len() > 4) else {
        return "(none)";
    };
    word
}

fn main() {
    let mut queue = vec!["a", "b", "c"];
    while let Some(item) = queue.pop() {
        print!("{item} ");
    }
    println!();
    println!("{}", first_long_word("a short example"));
}
```

## Exhaustiveness helps you refactor

Avoid `_` on your own enums when you don't need it. With `_`, the compiler no longer warns you when you add a new variant. Without it, you get an error at every place that needs updating.

> **Key takeaway:** patterns destructure nested structs and enums. `if` adds conditions, `@` keeps the value, and `matches!` returns a `bool`. Avoid `_` to keep the exhaustiveness check.

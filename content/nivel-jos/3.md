# Rust la nivel jos — Avansat

Ce trebuie să furnizezi singur fără `std`, cum accesezi registrele hardware, primii pași cu assembly inline și cum folosești instrucțiunile SIMD ale procesorului.

## Ce trebuie să definești într-un binar `no_std`

Un program `no_std` care rulează direct pe hardware trebuie să furnizeze ce oferea, de obicei, `std`:

- un **`#[panic_handler]`**: ce se întâmplă la panic (oprire, repornire, un mesaj pe UART);
- un **punct de intrare**, cu `#![no_main]`: codul de pornire al platformei sau un crate ca `cortex-m-rt`;
- un **alocator global**, doar dacă folosești `alloc`;
- un **linker script** care spune unde sunt memoria Flash și RAM-ul.

```rust,ignore
#![no_std]
#![no_main]

use core::panic::PanicInfo;

#[panic_handler]
fn la_panic(_info: &PanicInfo) -> ! {
    // pe hardware real: aprinde un LED de eroare sau resetează cipul
    loop {
        core::hint::spin_loop();
    }
}

#[unsafe(no_mangle)]
pub extern "C" fn _start() -> ! {
    // codul de pornire: inițializează memoria, apoi rulează aplicația
    loop {}
}
```

Fără `std` nu există nici unwinding: profilul trebuie să folosească `panic = "abort"`.

## Registre hardware: accese `volatile`

Perifericele (GPIO, timere, UART) sunt controlate prin **registre mapate în memorie** (*MMIO*): adrese fixe la care citirea sau scrierea are efecte în hardware. Compilatorul nu are voie să elimine, să combine sau să reordoneze aceste accese. De aceea se folosesc `read_volatile` și `write_volatile`:

```rust
use core::ptr;

// Simulăm un registru. Pe hardware real, ar fi o adresă fixă, de exemplu 0x4002_0014
fn main() {
    let mut registru: u32 = 0;
    let adresa: *mut u32 = &mut registru;

    // SAFETY: `adresa` e validă și aliniată, iar nimeni altcineva nu o accesează
    unsafe {
        ptr::write_volatile(adresa, 1 << 5);                 // „aprinde pinul 5”
        let valoare = ptr::read_volatile(adresa);
        ptr::write_volatile(adresa, valoare | (1 << 3));     // și pinul 3
        println!("{:#010b}", ptr::read_volatile(adresa));
    }
}
```

Fără `volatile`, compilatorul ar putea păstra doar ultima scriere, pentru că pentru el valoarea intermediară „nu e citită de nimeni”. În practică, crate-urile PAC generate cu `svd2rust` învelesc aceste accese în API-uri sigure, pentru fiecare registru.

## Assembly inline: `asm!`

Macro-ul `asm!` (stabil din Rust 1.59) inserează instrucțiuni de procesor direct în cod. Compilatorul alocă registrele pentru operanzi:

```rust
#[cfg(target_arch = "x86_64")]
fn aduna_asm(a: u64, b: u64) -> u64 {
    let rezultat: u64;
    // SAFETY: instrucțiunea doar adună două registre, fără efecte asupra memoriei
    unsafe {
        core::arch::asm!(
            "mov {r}, {a}",
            "add {r}, {b}",
            a = in(reg) a,
            b = in(reg) b,
            r = out(reg) rezultat,
        );
    }
    rezultat
}

#[cfg(not(target_arch = "x86_64"))]
fn aduna_asm(a: u64, b: u64) -> u64 { a + b }

fn main() {
    println!("{}", aduna_asm(40, 2));
}
```

`asm!` e necesar pentru instrucțiuni pe care compilatorul nu le generează singur: instrucțiuni privilegiate, întreruperi, schimbarea contextului, bariere speciale. Pentru calcule obișnuite, codul Rust optimizat e la fel de rapid.

## SIMD: o instrucțiune, mai multe date

Procesoarele moderne pot procesa 4, 8 sau 16 valori într-o singură instrucțiune. Cel mai simplu e să lași compilatorul să **vectorizeze automat** buclele simple. Pentru control explicit, folosești intrinsecile din `std::arch`, cu detecție la runtime:

```rust
fn suma_scalar(v: &[f32]) -> f32 {
    v.iter().sum()
}

#[cfg(target_arch = "x86_64")]
fn suma_sse(v: &[f32]) -> f32 {
    use std::arch::x86_64::*;
    let mut acc = [0.0f32; 4];
    let bucati = v.chunks_exact(4);
    let rest: f32 = bucati.remainder().iter().sum();
    // SAFETY: SSE e garantat pe toate procesoarele x86-64
    unsafe {
        let mut suma = _mm_setzero_ps();
        for b in bucati {
            suma = _mm_add_ps(suma, _mm_loadu_ps(b.as_ptr())); // 4 adunări deodată
        }
        _mm_storeu_ps(acc.as_mut_ptr(), suma);
    }
    acc.iter().sum::<f32>() + rest
}

fn main() {
    let v: Vec<f32> = (1..=10).map(|x| x as f32).collect();
    println!("scalar: {}", suma_scalar(&v));
    #[cfg(target_arch = "x86_64")]
    {
        println!("SSE: {}", suma_sse(&v));
        println!("AVX2 disponibil: {}", is_x86_feature_detected!("avx2"));
    }
}
```

`std::simd`, o variantă portabilă care merge pe orice arhitectură, este încă instabilă. Pe stable, crate-uri ca `wide` sau `pulp` oferă abstracții portabile.

## Verifică ce generează compilatorul

La nivel jos, rezultatul real e codul mașină. Îl poți inspecta:

```bash
cargo rustc --release -- --emit=asm      # fișiere .s în target/release/deps
cargo install cargo-show-asm
cargo asm --rust proiect::suma_scalar    # asamblarea unei singure funcții
```

În Rust Playground, butonul „...” → **ASM** face același lucru, iar Compiler Explorer (godbolt.org) acceptă Rust.

> **De reținut:** fără `std` furnizezi singur `#[panic_handler]`, punctul de intrare și, eventual, alocatorul. Registrele hardware se accesează cu `read_volatile` / `write_volatile`. `asm!` inserează instrucțiuni direct, iar `std::arch` dă intrinseci SIMD, de folosit împreună cu `is_x86_feature_detected!`.

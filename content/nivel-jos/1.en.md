# Low-level Rust — Fundamentals

Rust doesn't run only on computers with an operating system. The same language is used on microcontrollers with a few kilobytes of memory, in the Linux kernel, in bootloaders and in the browser, through WebAssembly. The difference is how much of the standard library you can afford.

## The three layers of the standard library

| Layer | Contains | Needs |
|---|---|---|
| `core` | primitive types, `Option`, `Result`, iterators, traits, `mem`, `ptr`, atomics | nothing: works anywhere |
| `alloc` | `Box`, `Vec`, `String`, `Rc`, `BTreeMap` | a memory allocator |
| `std` | files, networking, threads, time, `HashMap`, `println!` | an operating system |

`std` re-exports everything in `core` and in `alloc`. That's why `std::mem::size_of` and `core::mem::size_of` are the same function:

```rust
fn main() {
    // the same items, accessed through different layers
    let a = core::mem::size_of::<u64>();
    let b = std::mem::size_of::<u64>();
    let max = core::cmp::max(3, 7);
    let option: core::option::Option<i32> = Some(1);
    println!("{a} {b} {max} {option:?}");
}
```

## What `no_std` means

A crate marked `#![no_std]` uses only `core` (and, optionally, `alloc`). It can't open files and has no `println!`, but it can run on hardware without an operating system. Many popular libraries (`serde`, `hashbrown`, `heapless`) have `no_std` variants, so they can also be used in embedded.

Code that uses only `core` works the same everywhere:

```rust
// Only items from `core`: this would also compile in a #![no_std] crate
fn crc8(data: &[u8]) -> u8 {
    let mut crc = 0u8;
    for &byte in data {
        crc ^= byte;
        for _ in 0..8 {
            crc = if crc & 0x80 != 0 { (crc << 1) ^ 0x07 } else { crc << 1 };
        }
    }
    crc
}

fn main() {
    println!("{:#04x}", crc8(b"123456789"));
}
```

## Compilation targets

The Rust compiler can generate code for dozens of platforms. Each is identified by a **target triple**:

| Target | For |
|---|---|
| `x86_64-unknown-linux-gnu` | Linux on a PC |
| `aarch64-apple-darwin` | a Mac with an Apple processor |
| `x86_64-pc-windows-msvc` | Windows |
| `thumbv7em-none-eabihf` | ARM Cortex-M4/M7 microcontrollers, without an operating system |
| `riscv32imac-unknown-none-elf` | RISC-V microcontrollers |
| `wasm32-unknown-unknown` | WebAssembly in the browser |

`none` in the name means "no operating system": only `no_std` works there.

```bash
rustup target list --installed          # which targets you have installed
rustup target add wasm32-unknown-unknown
cargo build --target wasm32-unknown-unknown
```

## Where you meet low-level Rust

- **WebAssembly**: this very site is written in Rust and compiled to WebAssembly (`wasm32-unknown-unknown`), with the Leptos framework;
- **embedded**: ARM and RISC-V microcontrollers, with the `embedded-hal`, `embassy` and `probe-rs` ecosystem;
- **operating system kernels**: Linux accepts drivers written in Rust, and projects like Redox and Asterinas are written entirely in Rust;
- **firmware and bootloaders**, where total control over memory is a must.

> **Key takeaway:** the standard library has three layers: `core` (anywhere), `alloc` (with an allocator) and `std` (with an operating system). `#![no_std]` means only `core` and, optionally, `alloc`. A *target triple* picks the platform, and `none` in the name means no operating system.

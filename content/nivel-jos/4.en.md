## The operands and options of `asm!`

An `asm!` block describes to the compiler exactly what it does: which registers it reads, which it modifies and what effects it has. The compiler relies on this description, so a wrong description is **undefined behavior**.

| Operand | Meaning |
|---|---|
| `in(reg) x` | input in a register chosen by the compiler |
| `out(reg) y` | output; the register's initial value is lost |
| `inout(reg) z` | input and output in the same register |
| `lateout(reg) w` | output written after all inputs have been read |
| `in("rdi") x` | a fixed register |
| `out("rax") _` | a clobbered register, with no value used |

| Option | Promise |
|---|---|
| `pure` | no side effects; the result depends only on the inputs |
| `nomem` | doesn't read or write memory |
| `readonly` | reads memory, but doesn't write it |
| `nostack` | doesn't use the stack |
| `preserves_flags` | doesn't modify the processor flags |

```rust
#[cfg(target_arch = "x86_64")]
fn count_bits(x: u64) -> u64 {
    let n: u64;
    // SAFETY: popcnt only reads one register and writes another; it's available on x86-64
    // processors from after 2008, and here we check for it before calling.
    unsafe {
        core::arch::asm!(
            "popcnt {n}, {x}",
            x = in(reg) x,
            n = lateout(reg) n,
            options(pure, nomem, nostack),
        );
    }
    n
}

fn main() {
    #[cfg(target_arch = "x86_64")]
    if is_x86_feature_detected!("popcnt") {
        println!("{} {}", count_bits(0b1011_0110), 0b1011_0110_u64.count_ones());
    }
}
```

With `pure` + `nomem`, the compiler can remove the block if the result isn't used or hoist it out of a loop, as it would an ordinary function.

## Naked functions

A `#[unsafe(naked)]` function (stable since Rust 1.88) has no prologue or epilogue generated by the compiler. Its body is a single `naked_asm!`, which must follow the calling convention on its own. It's used for interrupt vectors, context switches and bootloader entry points:

```rust
#[cfg(all(target_arch = "x86_64", target_os = "linux"))]
#[unsafe(naked)]
extern "sysv64" fn add_naked(a: u64, b: u64) -> u64 {
    // System V: the arguments come in rdi and rsi, and the result is returned in rax
    core::arch::naked_asm!("lea rax, [rdi + rsi]", "ret")
}

fn main() {
    #[cfg(all(target_arch = "x86_64", target_os = "linux"))]
    println!("{}", add_naked(40, 2));
}
```

## `target_feature`: code specialized for a processor

`#[target_feature(enable = "avx2")]` compiles a function with instructions that don't exist on every processor. Since Rust 1.86, the function can be a safe `fn`. Calling it is still `unsafe` from functions that don't have the same feature, because on a processor without AVX2 it would be undefined behavior:

```rust
#[cfg(target_arch = "x86_64")]
#[target_feature(enable = "avx2")]
fn sum_avx2(v: &[i32]) -> i32 {
    v.iter().sum() // the compiler can vectorize with AVX2 instructions
}

fn sum(v: &[i32]) -> i32 {
    #[cfg(target_arch = "x86_64")]
    if is_x86_feature_detected!("avx2") {
        // SAFETY: we checked at runtime that the processor has AVX2
        return unsafe { sum_avx2(v) };
    }
    v.iter().sum()
}

fn main() {
    let v: Vec<i32> = (1..=1000).collect();
    println!("{}", sum(&v));
}
```

The whole-program variant is `RUSTFLAGS="-C target-cpu=native"`, but the resulting binary no longer runs on older processors.

## Atomics and critical sections without an operating system

On a single-core microcontroller there are no threads, but there are **interrupts**, which can occur between any two instructions. Data shared with an interrupt is protected with:

- atomics from `core::sync::atomic`. On some cores (Cortex-M0, RISC-V without the A extension) there are only `load` and `store`, without `fetch_add`. The `portable-atomic` crate fills in the missing operations;
- **critical sections**: you disable interrupts for the duration of the access. The `critical-section` crate offers a common interface across all platforms:

```rust,ignore
use core::cell::RefCell;
use critical_section::Mutex;

static COUNTER: Mutex<RefCell<u32>> = Mutex::new(RefCell::new(0));

fn in_interrupt() {
    critical_section::with(|cs| {
        *COUNTER.borrow(cs).borrow_mut() += 1; // `cs` proves interrupts are disabled
    });
}
```

The `cs` token is a **type-level proof**: `Mutex::borrow` requires it, so you can't access the data outside a critical section.

## WebAssembly: linear memory

A WebAssembly module has a single **linear memory**: a large array of bytes that can only grow, in 64 KiB pages. Rust pointers become `u32` indexes into this array (on `wasm32`), and JavaScript sees the same memory as an `ArrayBuffer`. Consequences:

- `usize` has 32 bits on `wasm32`, so a module can address at most 4 GiB;
- there are no files, threads or sockets unless the environment provides them (WASI, Web Workers);
- a panic becomes an `unreachable` instruction, which stops the module's execution.

```rust
fn main() {
    // On wasm32 this would print 4; on x86-64 it prints 8
    println!("usize: {} bytes on this target", size_of::<usize>());
    println!("wasm page: {} KiB", 65536 / 1024);
}
```

## Rust in the Linux kernel

Since version 6.1, the Linux kernel accepts Rust code for drivers and subsystems. The particulars of the environment:

- there's no `std`, and `alloc` is used with allocations that can fail (`try_new`, `try_push`), because the kernel must not bring the system down when memory runs short;
- safe abstractions (`kernel::sync::Mutex`, `kernel::list`) wrap the kernel's C APIs, and the `unsafe` code lives only in these binding layers;
- panics must be avoided entirely, because a panic in the kernel stops the whole machine.

That's the principle from Unsafe and FFI applied at scale: a small, carefully checked core of `unsafe` code, with safe interfaces on top of it.

> **Key takeaway:** the operands and options of `asm!` are a contract with the compiler. `#[unsafe(naked)]` gives total control over a function, and `target_feature` compiles code for a specific processor, called with `unsafe` after detection. Without an operating system, data shared with interrupts is protected with atomics or critical sections. WebAssembly has a linear memory of at most 4 GiB on `wasm32`.

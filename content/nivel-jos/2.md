# Rust la nivel jos — Practician

Cum scrii o bibliotecă `no_std`, cum folosești `alloc` fără sistem de operare, cum faci cross-compilare și cum arată primii pași în embedded și WebAssembly.

## O bibliotecă `no_std`

Atributul `#![no_std]` se pune la începutul crate-ului. De acolo înainte, ai doar `core`:

```rust,ignore
// src/lib.rs
#![no_std]

/// Medie mobilă pe o fereastră fixă, fără alocări: potrivită pentru un senzor.
pub struct MedieMobila<const N: usize> {
    valori: [i32; N],
    poz: usize,
    plin: bool,
}

impl<const N: usize> MedieMobila<N> {
    pub const fn new() -> Self {
        MedieMobila { valori: [0; N], poz: 0, plin: false }
    }

    pub fn adauga(&mut self, x: i32) -> i32 {
        self.valori[self.poz] = x;
        self.poz = (self.poz + 1) % N;
        if self.poz == 0 {
            self.plin = true;
        }
        let n = if self.plin { N } else { self.poz };
        self.valori[..n].iter().sum::<i32>() / n as i32
    }
}
```

O astfel de bibliotecă merge și într-un program obișnuit, și pe un microcontroler. Testele (`cargo test`) rulează pe calculatorul tău, cu `std`, chiar dacă biblioteca e `no_std`.

## Ce lipsește în `no_std` și cu ce înlocuiești

| Lipsește | Alternativă |
|---|---|
| `Vec`, `String`, `Box` | `alloc`, dacă ai un alocator, sau `heapless::Vec<T, N>` cu capacitate fixă |
| `HashMap` | `hashbrown` (aceeași implementare, fără `std`) sau `BTreeMap` din `alloc` |
| `println!` | `defmt`, logging prin RTT/UART sau `core::fmt::Write` pe un periferic |
| thread-uri, `Mutex` | `critical-section`, atomice din `core`, executori async ca `embassy` |
| `f64::sqrt` și altele | `libm` (funcțiile matematice cer suport din `std` sau din hardware) |

## `alloc` fără sistem de operare

Dacă ai un alocator (unul simplu peste o zonă de RAM sau unul furnizat de platformă), poți folosi colecțiile din `alloc`:

```rust,ignore
#![no_std]
extern crate alloc; // `alloc` trebuie adus explicit

use alloc::string::String;
use alloc::vec::Vec;
use alloc::format;

pub fn raport(valori: &[u32]) -> String {
    let mari: Vec<u32> = valori.iter().copied().filter(|&v| v > 100).collect();
    format!("{} valori peste 100", mari.len())
}
```

Programul final trebuie să declare un `#[global_allocator]`. Crate-uri ca `embedded-alloc` oferă alocatoare gata făcute.

## Cross-compilare

Pentru țintele fără sistem de operare îți trebuie, de obicei, doar ținta Rust și un linker. Cargo se ocupă de rest:

```bash
rustup target add thumbv7em-none-eabihf
cargo build --release --target thumbv7em-none-eabihf

# ținta implicită a proiectului, în .cargo/config.toml:
# [build]
# target = "thumbv7em-none-eabihf"
```

Pentru ținte cu sistem de operare (de exemplu, Linux pe ARM), îți trebuie și biblioteca C a platformei țintă. Unelte ca `cross` (care folosește containere) sau `cargo-zigbuild` simplifică mult procesul.

## Embedded: cum arată un program

În embedded, nu există `main` în sens obișnuit. Un crate de suport pentru placă (*BSP*) sau pentru microcontroler (*PAC/HAL*) definește punctul de intrare:

```rust,ignore
#![no_std]
#![no_main]

use cortex_m_rt::entry;   // punctul de intrare, pentru ARM Cortex-M
use panic_halt as _;      // la panic: oprește procesorul

#[entry]
fn main() -> ! {
    let periferice = stm32f4xx_hal::pac::Peripherals::take().unwrap();
    // ... configurează un pin ca ieșire și aprinde un LED
    loop {
        // un program embedded nu se termină niciodată: tipul `!`
    }
}
```

Ecosistemul `embedded-hal` definește trait-uri comune (`OutputPin`, `SpiBus`, `I2c`), așa că un driver de senzor scris o singură dată merge pe orice microcontroler.

## WebAssembly

Pentru browser, codul Rust se compilează în `wasm32-unknown-unknown`, iar `wasm-bindgen` generează legăturile cu JavaScript:

```rust,ignore
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn fibonacci(n: u32) -> u64 {
    let (mut a, mut b) = (0u64, 1u64);
    for _ in 0..n {
        (a, b) = (b, a + b);
    }
    a
}
// În JavaScript: import { fibonacci } from "./pkg/proiect.js"; fibonacci(50);
```

Unelte: `wasm-pack` pentru biblioteci folosite din JavaScript, `trunk` pentru aplicații întregi (acest site e construit cu `trunk`), iar Leptos, Yew și Dioxus sunt framework-uri pentru interfețe web scrise în Rust.

> **De reținut:** `#![no_std]` + `core` merg oriunde, iar `alloc` aduce colecțiile dacă ai un alocator. `heapless`, `hashbrown` și `libm` înlocuiesc părțile din `std`. Cross-compilarea înseamnă `rustup target add` + `--target`. `embedded-hal` și `wasm-bindgen` sunt punctele de pornire pentru embedded și web.

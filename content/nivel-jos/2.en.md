# Low-level Rust — Practitioner

How to write a `no_std` library, how to use `alloc` without an operating system, how to cross-compile, and what the first steps in embedded and WebAssembly look like.

## A `no_std` library

The `#![no_std]` attribute goes at the top of the crate. From there on, you have only `core`:

```rust,ignore
// src/lib.rs
#![no_std]

/// A moving average over a fixed window, with no allocations: suitable for a sensor.
pub struct MovingAverage<const N: usize> {
    values: [i32; N],
    pos: usize,
    full: bool,
}

impl<const N: usize> MovingAverage<N> {
    pub const fn new() -> Self {
        MovingAverage { values: [0; N], pos: 0, full: false }
    }

    pub fn add(&mut self, x: i32) -> i32 {
        self.values[self.pos] = x;
        self.pos = (self.pos + 1) % N;
        if self.pos == 0 {
            self.full = true;
        }
        let n = if self.full { N } else { self.pos };
        self.values[..n].iter().sum::<i32>() / n as i32
    }
}
```

Such a library works both in an ordinary program and on a microcontroller. Its tests (`cargo test`) run on your computer, with `std`, even though the library is `no_std`.

## What's missing in `no_std` and what replaces it

| Missing | Alternative |
|---|---|
| `Vec`, `String`, `Box` | `alloc`, if you have an allocator, or `heapless::Vec<T, N>` with a fixed capacity |
| `HashMap` | `hashbrown` (the same implementation, without `std`) or `BTreeMap` from `alloc` |
| `println!` | `defmt`, logging over RTT/UART, or `core::fmt::Write` on a peripheral |
| threads, `Mutex` | `critical-section`, atomics from `core`, async executors like `embassy` |
| `f64::sqrt` and friends | `libm` (math functions need support from `std` or from the hardware) |

## `alloc` without an operating system

If you have an allocator (a simple one over a region of RAM, or one provided by the platform), you can use the collections from `alloc`:

```rust,ignore
#![no_std]
extern crate alloc; // `alloc` has to be brought in explicitly

use alloc::string::String;
use alloc::vec::Vec;
use alloc::format;

pub fn report(values: &[u32]) -> String {
    let big: Vec<u32> = values.iter().copied().filter(|&v| v > 100).collect();
    format!("{} values above 100", big.len())
}
```

The final program must declare a `#[global_allocator]`. Crates like `embedded-alloc` provide ready-made allocators.

## Cross-compiling

For targets without an operating system you usually need only the Rust target and a linker. Cargo takes care of the rest:

```bash
rustup target add thumbv7em-none-eabihf
cargo build --release --target thumbv7em-none-eabihf

# the project's default target, in .cargo/config.toml:
# [build]
# target = "thumbv7em-none-eabihf"
```

For targets with an operating system (for example, Linux on ARM), you also need the target platform's C library. Tools like `cross` (which uses containers) or `cargo-zigbuild` simplify the process a lot.

## Embedded: what a program looks like

In embedded, there's no `main` in the usual sense. A board support crate (*BSP*) or a microcontroller crate (*PAC/HAL*) defines the entry point:

```rust,ignore
#![no_std]
#![no_main]

use cortex_m_rt::entry;   // the entry point, for ARM Cortex-M
use panic_halt as _;      // on panic: halt the processor

#[entry]
fn main() -> ! {
    let peripherals = stm32f4xx_hal::pac::Peripherals::take().unwrap();
    // ... configure a pin as an output and turn on an LED
    loop {
        // an embedded program never ends: the `!` type
    }
}
```

The `embedded-hal` ecosystem defines common traits (`OutputPin`, `SpiBus`, `I2c`), so a sensor driver written once works on any microcontroller.

## WebAssembly

For the browser, Rust code is compiled to `wasm32-unknown-unknown`, and `wasm-bindgen` generates the bindings with JavaScript:

```rust,ignore
use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn fibonacci(n: u32) -> u64 {
    let (mut a, mut b) = (0u64, 1u64);
    for _ in 0..n {
        (a, b) = (b, a + b);
    }
    a
}
// In JavaScript: import { fibonacci } from "./pkg/project.js"; fibonacci(50);
```

Tools: `wasm-pack` for libraries used from JavaScript, `trunk` for whole applications (this site is built with `trunk`), and Leptos, Yew and Dioxus are frameworks for web interfaces written in Rust.

> **Key takeaway:** `#![no_std]` + `core` work anywhere, and `alloc` brings the collections if you have an allocator. `heapless`, `hashbrown` and `libm` replace the parts of `std`. Cross-compiling means `rustup target add` + `--target`. `embedded-hal` and `wasm-bindgen` are the starting points for embedded and the web.

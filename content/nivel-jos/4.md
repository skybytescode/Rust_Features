## Operanzii și opțiunile lui `asm!`

Un bloc `asm!` îi descrie compilatorului exact ce face: ce registre citește, ce registre modifică și ce efecte are. Compilatorul se bazează pe această descriere, așa că o descriere greșită e **comportament nedefinit**.

| Operand | Semnificație |
|---|---|
| `in(reg) x` | intrare într-un registru ales de compilator |
| `out(reg) y` | ieșire; valoarea inițială a registrului e pierdută |
| `inout(reg) z` | intrare și ieșire în același registru |
| `lateout(reg) w` | ieșire scrisă după ce toate intrările au fost citite |
| `in("rdi") x` | registru fix |
| `out("rax") _` | registru alterat (*clobber*), fără valoare folosită |

| Opțiune | Promisiune |
|---|---|
| `pure` | fără efecte secundare; rezultatul depinde doar de intrări |
| `nomem` | nu citește și nu scrie memorie |
| `readonly` | citește memorie, dar nu scrie |
| `nostack` | nu folosește stiva |
| `preserves_flags` | nu modifică flag-urile procesorului |

```rust
#[cfg(target_arch = "x86_64")]
fn numar_biti(x: u64) -> u64 {
    let n: u64;
    // SAFETY: popcnt doar citește un registru și scrie altul; e disponibil pe procesoarele
    // x86-64 de după 2008, iar aici îl verificăm înainte de apel.
    unsafe {
        core::arch::asm!(
            "popcnt {n}, {x}",
            x = in(reg) x,
            n = lateout(reg) n,
            options(pure, nomem, nostack),
        );
    }
    n
}

fn main() {
    #[cfg(target_arch = "x86_64")]
    if is_x86_feature_detected!("popcnt") {
        println!("{} {}", numar_biti(0b1011_0110), 0b1011_0110_u64.count_ones());
    }
}
```

Cu `pure` + `nomem`, compilatorul poate elimina blocul dacă rezultatul nu e folosit sau îl poate muta în afara unei bucle, la fel ca pe o funcție obișnuită.

## Funcții naked

O funcție `#[unsafe(naked)]` (stabilă din Rust 1.88) nu are prolog și epilog generate de compilator. Corpul ei e un singur `naked_asm!`, care trebuie să respecte singur convenția de apel. Se folosește la vectori de întreruperi, la schimbări de context și la punctele de intrare din bootloadere:

```rust
#[cfg(all(target_arch = "x86_64", target_os = "linux"))]
#[unsafe(naked)]
extern "sysv64" fn aduna_naked(a: u64, b: u64) -> u64 {
    // System V: argumentele vin în rdi și rsi, iar rezultatul se întoarce în rax
    core::arch::naked_asm!("lea rax, [rdi + rsi]", "ret")
}

fn main() {
    #[cfg(all(target_arch = "x86_64", target_os = "linux"))]
    println!("{}", aduna_naked(40, 2));
}
```

## `target_feature`: cod specializat pentru un procesor

`#[target_feature(enable = "avx2")]` compilează o funcție cu instrucțiuni care nu există pe toate procesoarele. Din Rust 1.86, funcția poate fi `fn` safe. Apelul ei rămâne `unsafe` din funcții care nu au aceeași caracteristică, pentru că pe un procesor fără AVX2 ar fi comportament nedefinit:

```rust
#[cfg(target_arch = "x86_64")]
#[target_feature(enable = "avx2")]
fn suma_avx2(v: &[i32]) -> i32 {
    v.iter().sum() // compilatorul poate vectoriza cu instrucțiuni AVX2
}

fn suma(v: &[i32]) -> i32 {
    #[cfg(target_arch = "x86_64")]
    if is_x86_feature_detected!("avx2") {
        // SAFETY: am verificat la runtime că procesorul are AVX2
        return unsafe { suma_avx2(v) };
    }
    v.iter().sum()
}

fn main() {
    let v: Vec<i32> = (1..=1000).collect();
    println!("{}", suma(&v));
}
```

Varianta pentru tot programul e `RUSTFLAGS="-C target-cpu=native"`, dar binarul rezultat nu mai rulează pe procesoare mai vechi.

## Atomice și secțiuni critice fără sistem de operare

Pe un microcontroler cu un singur nucleu nu există thread-uri, dar există **întreruperi**, care pot apărea între oricare două instrucțiuni. Datele partajate cu o întrerupere se protejează cu:

- atomice din `core::sync::atomic`. Pe unele nuclee (Cortex-M0, RISC-V fără extensia A) există doar `load` și `store`, fără `fetch_add`. Crate-ul `portable-atomic` completează operațiile lipsă;
- **secțiuni critice**: dezactivezi întreruperile pe durata accesului. Crate-ul `critical-section` oferă o interfață comună peste toate platformele:

```rust,ignore
use core::cell::RefCell;
use critical_section::Mutex;

static CONTOR: Mutex<RefCell<u32>> = Mutex::new(RefCell::new(0));

fn in_intrerupere() {
    critical_section::with(|cs| {
        *CONTOR.borrow(cs).borrow_mut() += 1; // `cs` dovedește că întreruperile sunt oprite
    });
}
```

Tokenul `cs` e o **dovadă la nivel de tip**: `Mutex::borrow` îl cere, deci nu poți accesa datele în afara unei secțiuni critice.

## WebAssembly: memorie liniară

Un modul WebAssembly are o singură **memorie liniară**: un array mare de octeți, care poate doar să crească, în pagini de 64 KiB. Pointerii Rust devin indici `u32` în acest array (pe `wasm32`), iar JavaScript vede aceeași memorie ca pe un `ArrayBuffer`. Consecințe:

- `usize` are 32 de biți pe `wasm32`, așa că un modul poate adresa cel mult 4 GiB;
- nu există fișiere, thread-uri sau socket-uri decât dacă mediul le oferă (WASI, Web Workers);
- un panic devine o instrucțiune `unreachable`, care oprește execuția modulului.

```rust
fn main() {
    // Pe wasm32 ar afișa 4; pe x86-64 afișează 8
    println!("usize: {} octeți pe această țintă", size_of::<usize>());
    println!("pagină wasm: {} KiB", 65536 / 1024);
}
```

## Rust în nucleul Linux

Din versiunea 6.1, nucleul Linux acceptă cod Rust pentru drivere și subsisteme. Particularitățile mediului:

- nu există `std`, iar `alloc` e folosit cu alocări care pot eșua (`try_new`, `try_push`), pentru că nucleul nu are voie să oprească sistemul când memoria e insuficientă;
- abstracțiunile sigure (`kernel::sync::Mutex`, `kernel::list`) învelesc API-urile C ale nucleului, iar codul `unsafe` stă doar în aceste straturi de legătură;
- panic-urile trebuie evitate cu totul, pentru că un panic în nucleu oprește întreaga mașină.

Așa arată principiul de la Unsafe și FFI aplicat la scară mare: un nucleu mic de cod `unsafe`, verificat atent, și interfețe sigure peste el.

> **De reținut:** operanzii și opțiunile `asm!` sunt un contract cu compilatorul. `#[unsafe(naked)]` dă controlul total asupra unei funcții, iar `target_feature` compilează cod pentru un procesor anume, cu apel `unsafe` după detecție. Fără sistem de operare, datele partajate cu întreruperile se protejează cu atomice sau secțiuni critice. WebAssembly are o memorie liniară de cel mult 4 GiB pe `wasm32`.

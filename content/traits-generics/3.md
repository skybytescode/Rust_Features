# Traits și generics — Avansat

Dispatch static vs. dinamic, tipuri asociate, regulile de coerență și trait-urile „marker” prin care compilatorul verifică siguranța.

## Static vs. dinamic: generice sau `dyn Trait`

- **Genericele** (`T: Trait`, `impl Trait`) sunt rezolvate la compilare. Fiecare tip primește propria copie a funcției: apelul e direct și poate fi inline-uit.
- **Obiectele trait** (`&dyn Trait`, `Box<dyn Trait>`) sunt rezolvate la runtime, printr-o tabelă de metode (*vtable*). Așa poți pune tipuri **diferite** în aceeași colecție.

```rust
trait Animal {
    fn sunet(&self) -> &'static str;
}

struct Pisica;
struct Vaca;

impl Animal for Pisica { fn sunet(&self) -> &'static str { "miau" } }
impl Animal for Vaca { fn sunet(&self) -> &'static str { "muu" } }

fn static_dispatch<A: Animal>(a: &A) -> &'static str {
    a.sunet() // compilat separat pentru Pisica și pentru Vaca
}

fn main() {
    println!("{} {}", static_dispatch(&Pisica), static_dispatch(&Vaca));

    let ferma: Vec<Box<dyn Animal>> = vec![Box::new(Pisica), Box::new(Vaca), Box::new(Pisica)];
    for a in &ferma {
        print!("{} ", a.sunet()); // apel prin vtable
    }
    println!();
}
```

## Compatibilitatea cu `dyn`

Nu orice trait poate fi folosit ca `dyn Trait`. Un trait e **dyn-compatible** (fostul nume: *object safe*) doar dacă nicio metodă nu:

- returnează `Self` prin valoare (mărimea lui `Self` nu e cunoscută);
- are parametri generici proprii (ar avea nevoie de o vtable infinită);
- e o funcție asociată fără `self`.

Le poți exclude cu `where Self: Sized`, ca trait-ul să rămână utilizabil ca `dyn`:

```rust
trait Forma {
    fn arie(&self) -> f64;

    fn clonat(&self) -> Self
    where
        Self: Sized; // exclusă din vtable
}

#[derive(Clone)]
struct Patrat(f64);

impl Forma for Patrat {
    fn arie(&self) -> f64 { self.0 * self.0 }
    fn clonat(&self) -> Self { self.clone() }
}

fn main() {
    let forme: Vec<Box<dyn Forma>> = vec![Box::new(Patrat(3.0))];
    println!("{}", forme[0].arie());
    println!("{}", Patrat(2.0).clonat().arie());
}
```

## Tipuri asociate vs. parametri generici

`Iterator` are un **tip asociat**, `type Item`: un tip implementează `Iterator` o singură dată, cu un singur `Item`. Un parametru generic, ca în `From<T>`, permite **mai multe** implementări pentru același tip:

```rust
struct Numaratoare {
    curent: u32,
    pana_la: u32,
}

impl Iterator for Numaratoare {
    type Item = u32; // un singur tip de element

    fn next(&mut self) -> Option<u32> {
        if self.curent < self.pana_la {
            self.curent += 1;
            Some(self.curent)
        } else {
            None
        }
    }
}

struct Id(u64);
impl From<u32> for Id { fn from(n: u32) -> Self { Id(n as u64) } }
impl From<&str> for Id { fn from(s: &str) -> Self { Id(s.len() as u64) } } // a doua implementare

fn main() {
    let suma: u32 = Numaratoare { curent: 0, pana_la: 4 }.sum();
    println!("{suma} {} {}", Id::from(7_u32).0, Id::from("abc").0);
}
```

## Coerența și regula orfanului

Poți implementa un trait pentru un tip doar dacă **trait-ul sau tipul** e definit în crate-ul tău. Regula garantează că nu pot exista două implementări conflictuale în crate-uri diferite. Nu poți implementa `Display` pentru `Vec<i32>`, de exemplu, dar îl poți înveli într-un newtype:

```rust
use std::fmt;

struct Lista(Vec<i32>);

impl fmt::Display for Lista {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        let texte: Vec<String> = self.0.iter().map(|x| x.to_string()).collect();
        write!(f, "[{}]", texte.join(" | "))
    }
}

fn main() {
    println!("{}", Lista(vec![1, 2, 3]));
}
```

## Implementări blanket și supertraits

O implementare **blanket** acoperă toate tipurile care îndeplinesc o condiție. Un **supertrait** cere ca un trait să fie implementat înaintea altuia:

```rust
use std::fmt::Display;

trait Eticheta: Display {          // supertrait: cine implementează Eticheta trebuie să aibă Display
    fn eticheta(&self) -> String {
        format!("<{self}>")
    }
}

impl<T: Display> Eticheta for T {} // blanket: orice tip cu Display primește Eticheta

fn main() {
    println!("{} {}", 42.eticheta(), "rust".eticheta());
}
```

Biblioteca standard folosește tehnica peste tot: `impl<T: Display> ToString for T` este motivul pentru care orice tip cu `Display` are `.to_string()`.

## Trait-uri marker: `Send`, `Sync`, `Sized`, `Copy`

Unele trait-uri nu au metode. Ele descriu o **proprietate** a tipului:

| Trait | Înseamnă |
|---|---|
| `Send` | valoarea poate fi mutată în alt thread |
| `Sync` | `&T` poate fi partajat între thread-uri |
| `Sized` | mărimea e cunoscută la compilare (implicit pe orice `T`) |
| `Copy` | se copiază bit cu bit, fără move |

`Send` și `Sync` sunt *auto traits*: compilatorul le implementează automat dacă toate câmpurile le au. `Rc<T>` nu e `Send`, așa că următorul program nu compilează:

```rust,compile_fail
use std::rc::Rc;

fn main() {
    let date = Rc::new(5);
    std::thread::spawn(move || {
        println!("{date}"); // eroare E0277: `Rc<i32>` nu poate fi trimis între thread-uri
    });
}
```

Constrângerea implicită `Sized` poate fi relaxată cu `?Sized`, ca funcția să accepte și `str`, `[T]` sau `dyn Trait` în spatele unei referințe:

```rust
use std::fmt::Debug;

fn arata<T: Debug + ?Sized>(x: &T) {
    println!("{x:?}");
}

fn main() {
    arata("un str");       // T = str, care nu e Sized
    arata(&[1, 2, 3][..]); // T = [i32]
}
```

> **De reținut:** genericele înseamnă dispatch static, iar `dyn` dispatch prin vtable. Un trait folosit ca `dyn` nu poate avea metode generice sau care returnează `Self`. Tipurile asociate permit o singură implementare, iar regula orfanului previne conflictele. `Send` și `Sync` sunt verificate automat.

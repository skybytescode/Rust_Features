# Traits and generics — Practitioner

How to combine constraints, how to implement standard traits for your own types, and how to make your types fit naturally into the language.

## Multiple constraints and `where`

When constraints get long, move them into a `where` clause:

```rust
use std::fmt::{Debug, Display};

fn report<T, U>(label: T, values: &[U]) -> String
where
    T: Display,
    U: Debug + Clone,
{
    format!("{label}: {:?}", values.to_vec())
}

fn main() {
    println!("{}", report("temperatures", &[21.5, 23.0]));
}
```

## Generic structs and implementations

```rust
#[derive(Debug)]
struct Stack<T> {
    items: Vec<T>,
}

impl<T> Stack<T> {
    fn new() -> Self {
        Stack { items: Vec::new() }
    }
    fn push(&mut self, x: T) {
        self.items.push(x);
    }
    fn pop(&mut self) -> Option<T> {
        self.items.pop()
    }
    fn top(&self) -> Option<&T> {
        self.items.last()
    }
}

fn main() {
    let mut s = Stack::new();
    s.push("a");
    s.push("b");
    println!("top: {:?}", s.top());
    println!("popped: {:?}", s.pop());
    println!("{s:?}");
}
```

## `Display`: output for users

`Debug` is for programmers and can be derived. `Display` is for users and must be written by hand:

```rust
use std::fmt;

struct Money {
    cents: u64,
}

impl fmt::Display for Money {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "${}.{:02}", self.cents / 100, self.cents % 100)
    }
}

fn main() {
    let price = Money { cents: 12_345 };
    println!("Total: {price}");
    let text = price.to_string(); // `to_string` comes for free from Display
    println!("{}", text.len());
}
```

## `From` and `Into`: conversions

You implement `From`, and `Into` comes automatically:

```rust
struct Celsius(f64);
struct Fahrenheit(f64);

impl From<Celsius> for Fahrenheit {
    fn from(c: Celsius) -> Self {
        Fahrenheit(c.0 * 9.0 / 5.0 + 32.0)
    }
}

fn main() {
    let f = Fahrenheit::from(Celsius(100.0));
    let g: Fahrenheit = Celsius(0.0).into();
    println!("{} {}", f.0, g.0);
}
```

## Operator overloading

Operators are traits from `std::ops`: `+` is `Add`, `*` is `Mul`, `[]` is `Index`, and `-x` is `Neg`:

```rust
use std::ops::{Add, Mul};

#[derive(Debug, Clone, Copy, PartialEq)]
struct Vector2 {
    x: f64,
    y: f64,
}

impl Add for Vector2 {
    type Output = Vector2;
    fn add(self, other: Vector2) -> Vector2 {
        Vector2 { x: self.x + other.x, y: self.y + other.y }
    }
}

impl Mul<f64> for Vector2 {
    type Output = Vector2;
    fn mul(self, k: f64) -> Vector2 {
        Vector2 { x: self.x * k, y: self.y * k }
    }
}

fn main() {
    let a = Vector2 { x: 1.0, y: 2.0 };
    let b = Vector2 { x: 3.0, y: -1.0 };
    println!("{:?}", a + b);
    println!("{:?}", a * 3.0);
}
```

## `impl Trait` in the return type

When the concrete type is complicated or impossible to write (a closure, a composed iterator), you return `impl Trait`:

```rust
fn multiplier(k: i32) -> impl Fn(i32) -> i32 {
    move |x| x * k
}

fn odd_squares(n: u32) -> impl Iterator<Item = u32> {
    (1..=n).filter(|x| x % 2 == 1).map(|x| x * x)
}

fn main() {
    let triple = multiplier(3);
    println!("{}", triple(7));
    println!("{:?}", odd_squares(9).collect::<Vec<_>>());
}
```

## `Default` and `PartialOrd` by hand

Sometimes the derived behavior isn't what you want, so you implement the trait by hand:

```rust
use std::cmp::Ordering;

#[derive(Debug, PartialEq)]
struct Version {
    major: u32,
    minor: u32,
}

impl Default for Version {
    fn default() -> Self {
        Version { major: 1, minor: 0 } // not 0.0
    }
}

impl PartialOrd for Version {
    fn partial_cmp(&self, other: &Self) -> Option<Ordering> {
        Some(self.major.cmp(&other.major).then(self.minor.cmp(&other.minor)))
    }
}

fn main() {
    let a = Version::default();
    let b = Version { major: 1, minor: 4 };
    println!("{a:?} < {b:?}: {}", a < b);
}
```

> **Key takeaway:** `where` keeps long constraints readable. Implement `Display` for users, `From` for conversions and `std::ops` for operators. `impl Trait` in the return type hides types that are hard to write.

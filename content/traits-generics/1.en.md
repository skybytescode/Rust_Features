# Traits and generics — Fundamentals

A **trait** describes shared behavior: a set of methods that a type promises to have. **Generics** let you write code once for several types.

## Defining a trait

```rust
trait Description {
    fn describe(&self) -> String;
}

struct Dog {
    name: String,
}

struct Car {
    make: String,
    year: u16,
}

impl Description for Dog {
    fn describe(&self) -> String {
        format!("the dog {}", self.name)
    }
}

impl Description for Car {
    fn describe(&self) -> String {
        format!("a {} from {}", self.make, self.year)
    }
}

fn main() {
    let d = Dog { name: "Rex".into() };
    let c = Car { make: "Volvo".into(), year: 2020 };
    println!("{}", d.describe());
    println!("{}", c.describe());
}
```

## Methods with a default implementation

A trait can provide a default implementation, which types can keep or replace:

```rust
trait Greeting {
    fn name(&self) -> String;

    fn greet(&self) -> String {
        format!("Hello, {}!", self.name()) // uses the required method
    }
}

struct Person(String);

impl Greeting for Person {
    fn name(&self) -> String {
        self.0.clone()
    }
    // `greet` comes for free from the trait
}

fn main() {
    println!("{}", Person("Ana".into()).greet());
}
```

## Generic functions

Instead of writing a function for every type, you write a single generic one. `<T>` is a type that will be decided at the call site:

```rust
fn first<T>(list: &[T]) -> Option<&T> {
    list.first()
}

fn main() {
    println!("{:?}", first(&[10, 20, 30]));
    println!("{:?}", first(&["a", "b"]));
    println!("{:?}", first::<f64>(&[]));
}
```

## Constraints: "any type that knows how to…"

To do something with `T`, such as comparing two values, you must require `T` to implement the right trait:

```rust
fn largest<T: PartialOrd>(a: T, b: T) -> T {
    if a > b { a } else { b }
}

fn main() {
    println!("{}", largest(3, 9));
    println!("{}", largest(2.5, -1.0));
    println!("{}", largest("apples", "pears"));
}
```

Without `T: PartialOrd`, the compiler refuses `a > b`, because not every type can be compared:

```rust,compile_fail
fn largest<T>(a: T, b: T) -> T {
    if a > b { a } else { b } // error E0369: `>` isn't defined for every T
}

fn main() {
    println!("{}", largest(1, 2));
}
```

## Traits as parameters

You can accept "any type that implements a trait" with `impl Trait`:

```rust
trait Area {
    fn area(&self) -> f64;
}

struct Square(f64);
struct Circle(f64);

impl Area for Square {
    fn area(&self) -> f64 { self.0 * self.0 }
}

impl Area for Circle {
    fn area(&self) -> f64 { 3.14159 * self.0 * self.0 }
}

fn print_area(shape: &impl Area) {
    println!("area: {:.2}", shape.area());
}

fn main() {
    print_area(&Square(2.0));
    print_area(&Circle(1.0));
}
```

## Traits from the standard library

Many ordinary operations are actually traits: `Display` for printing with `{}`, `Debug` for `{:?}`, `Clone`, `PartialEq` for `==` and others. You can implement them automatically with `#[derive]` or by hand, like any other trait.

> **Key takeaway:** a trait is a set of methods that types implement with `impl Trait for Type`. Generics (`<T>`) write code once, and constraints (`T: Trait`) say what `T` must be able to do.

# Unsafe and FFI — Practitioner

The central principle: **encapsulate** `unsafe` code behind a safe interface. Plus how to pass text and data between Rust and C.

## Safe abstractions over `unsafe` code

`split_at_mut` from the standard library splits a slice into two mutable parts. The borrow checker can't prove on its own that the parts don't overlap, so the implementation uses `unsafe`. The interface, however, stays **completely safe**:

```rust
fn split_mut(s: &mut [i32], middle: usize) -> (&mut [i32], &mut [i32]) {
    let len = s.len();
    assert!(middle <= len); // the check that makes the code below correct
    let p = s.as_mut_ptr();
    // SAFETY: the two ranges [0, middle) and [middle, len) are disjoint
    // and both are within the bounds of the original slice.
    unsafe {
        (
            std::slice::from_raw_parts_mut(p, middle),
            std::slice::from_raw_parts_mut(p.add(middle), len - middle),
        )
    }
}

fn main() {
    let mut v = [1, 2, 3, 4, 5];
    let (a, b) = split_mut(&mut v, 2);
    a[0] = 100;
    b[0] = 300;
    println!("{v:?}");
}
```

Whoever calls `split_mut` can't cause undefined behavior, whatever the arguments: `assert!` stops an invalid `middle`. That's what a correct safe abstraction looks like.

## `unsafe fn` and documenting the conditions

If a function has conditions it can't check itself, you mark it `unsafe fn` and document them in a `# Safety` section:

```rust
/// Returns the element at `i` without bounds checking.
///
/// # Safety
///
/// `i` must be less than `v.len()`.
unsafe fn get_fast(v: &[u64], i: usize) -> u64 {
    // SAFETY: the caller guarantees that `i < v.len()`
    unsafe { *v.get_unchecked(i) }
}

fn main() {
    let v = [5, 6, 7];
    // SAFETY: 2 < 3
    println!("{}", unsafe { get_fast(&v, 2) });
}
```

In the 2024 edition, even inside an `unsafe fn` you must explicitly write `unsafe { ... }` around the unsafe operations (the `unsafe_op_in_unsafe_fn` lint). That makes it clear exactly which lines need attention.

## Text between Rust and C

Rust strings don't end in `\0` and can contain `\0` in the middle. C strings are the opposite. The standard library has dedicated types:

| Rust | C | Role |
|---|---|---|
| `CString` | allocated `char*` | you create a C string from Rust |
| `&CStr` | `const char*` | you borrow a C string |
| `c"text"` | C literal | `&'static CStr`, since Rust 1.77 |

```rust
use std::ffi::{CStr, CString, c_char};

unsafe extern "C" {
    fn strlen(s: *const c_char) -> usize;
}

fn main() {
    let rust = String::from("hello");
    let c = CString::new(rust).expect("contains \\0 in the middle");
    // SAFETY: `c` is a valid, \0-terminated C string that lives for the duration of the call
    let n = unsafe { strlen(c.as_ptr()) };
    println!("C length: {n}");

    let literal: &CStr = c"from a literal";
    println!("{:?} → {}", literal, literal.to_str().unwrap());
}
```

The classic mistake: `CString::new(s).unwrap().as_ptr()` in a single expression. The temporary `CString` is destroyed at the end of the statement, and the pointer is left dangling. Always keep the `CString` in a variable.

## C-compatible structs

For a struct sent to C, use `#[repr(C)]`, so the order and alignment of the fields are those of C:

```rust
#[repr(C)]
#[derive(Debug, Clone, Copy)]
struct Point {
    x: f64,
    y: f64,
}

// A Rust function callable from C
#[unsafe(no_mangle)]
pub extern "C" fn distance(a: Point, b: Point) -> f64 {
    ((a.x - b.x).powi(2) + (a.y - b.y).powi(2)).sqrt()
}

fn main() {
    println!("{}", distance(Point { x: 0.0, y: 0.0 }, Point { x: 3.0, y: 4.0 }));
}
```

## External functions marked `safe`

Since Rust 1.82, in an `unsafe extern` block you can mark as `safe` the functions that have no special conditions. Then you call them without `unsafe`:

```rust
unsafe extern "C" {
    safe fn labs(x: i64) -> i64; // a promise: any value is accepted
}

fn main() {
    println!("{}", labs(-7)); // no unsafe block
}
```

The responsibility moves to the declaration: if you wrongly mark a function as `safe`, you've introduced a safety bug.

> **Key takeaway:** hide `unsafe` behind a safe interface that checks everything it can. Document the conditions in `# Safety` and justify each block with `// SAFETY:`. For text you use `CString` / `CStr` / `c"..."`, and for structs, `#[repr(C)]`.

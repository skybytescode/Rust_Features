# Unsafe și FFI — Expert

Provenance, modelele de aliasing verificate de Miri, unwinding peste FFI, uneltele de generare a legăturilor și parametrii de ieșire cu `MaybeUninit`.

## Provenance: un pointer nu e doar o adresă

Pentru compilator, un pointer are **adresă** și **provenance**: informația despre alocarea din care provine și ce drepturi de acces are. Doi pointeri cu aceeași adresă pot fi diferiți: unul poate accesa memoria, celălalt nu. De aceea conversiile pointer → întreg → pointer sunt delicate.

Din Rust 1.84, API-urile *strict provenance* sunt stabile și fac intenția explicită:

```rust
fn main() {
    let x = [1u16, 2, 3, 4];
    let p = x.as_ptr();

    let adresa: usize = p.addr();                  // doar adresa, fără provenance
    println!("aliniat la 2: {}", adresa % 2 == 0);

    // modificăm adresa păstrând provenance-ul original
    let p3 = p.with_addr(adresa + 2 * size_of::<u16>());
    // SAFETY: p3 indică spre x[2], în interiorul aceleiași alocări
    println!("x[2] = {}", unsafe { *p3 });

    // tag-uri în biții de jos ai unui pointer aliniat (tehnică din structurile lock-free)
    let etichetat = p.map_addr(|a| a | 1);
    let curatat = etichetat.map_addr(|a| a & !1);
    // SAFETY: curatat == p
    println!("{}", unsafe { *curatat });

    // un pointer fără provenance: valid ca valoare, nu poate fi dereferențiat
    let santinela: *const u8 = std::ptr::without_provenance(0x1000);
    println!("{:?}", santinela);
}
```

Pentru codul care chiar trebuie să transforme întregi în pointeri (de exemplu, adrese primite de la hardware), există `expose_provenance` și `with_exposed_provenance`.

## Modelele de aliasing și Miri

Regulile precise ale aliasing-ului pentru cod `unsafe` sunt definite de modele formale: **Stacked Borrows** și **Tree Borrows**, succesorul lui, mai permisiv. Ideea de bază: fiecare referință primește un „tag”, iar crearea unei referințe `&mut` invalidează tag-urile altor referințe către aceeași memorie.

```rust
fn main() {
    let mut x = 0i32;
    let p1 = &mut x as *mut i32;
    let p2 = &mut x as *mut i32; // creează un nou &mut, deci invalidează p1 în Stacked Borrows
    // SAFETY: OK pentru p2, care e cel mai recent
    unsafe { *p2 = 5; }
    // unsafe { *p1 = 7; } // UB în Stacked Borrows: p1 a fost invalidat
    let _ = p1;
    println!("{x}");
}
```

Codul de mai sus compilează și chiar rulează „corect” chiar și cu linia comentată activată. Doar **Miri** detectează problema:

```bash
rustup +nightly component add miri
cargo +nightly miri run
MIRIFLAGS="-Zmiri-tree-borrows" cargo +nightly miri test   # modelul Tree Borrows
```

Miri e un interpretor pentru MIR care verifică, la fiecare operație, aliasing-ul, alinierea, inițializarea, provenance-ul și cursele de date. E lent (de 50–1000 de ori), dar e cea mai bună unealtă pentru testarea codului `unsafe`.

## Unwinding peste FFI

| ABI | Panic din Rust | Excepție din C++ |
|---|---|---|
| `extern "C"` | **abort** (din Rust 1.81) | UB |
| `extern "C-unwind"` | se propagă | se propagă |

Un panic nu are voie să iasă dintr-o funcție `extern "C"`, așa că Rust oprește procesul. Ca să-l transformi într-un cod de eroare, îl prinzi cu `catch_unwind` la graniță:

```rust
use std::panic;

#[unsafe(no_mangle)]
pub extern "C" fn imparte_sigur(a: i32, b: i32, rezultat: *mut i32) -> i32 {
    match panic::catch_unwind(|| a / b) {
        Ok(v) => {
            // SAFETY: apelantul trimite un pointer valid
            unsafe { *rezultat = v };
            0
        }
        Err(_) => -1, // panic prins: cod de eroare în loc de abort
    }
}

fn main() {
    panic::set_hook(Box::new(|_| {})); // ascunde mesajul de panic, pentru exemplu
    let mut r = 0;
    let ok = imparte_sigur(10, 2, &mut r);
    let err = imparte_sigur(1, 0, &mut r);
    println!("{ok} → {r}, apoi {err}");
}
```

## Parametri de ieșire cu `MaybeUninit`

API-urile C scriu adesea rezultatul într-un pointer primit (*out parameter*). Memoria e neinițializată înainte de apel, deci folosești `MaybeUninit`, nu o valoare inventată:

```rust
use std::mem::MaybeUninit;

#[repr(C)]
#[derive(Debug)]
struct Info {
    cod: u32,
    scor: f64,
}

// simulăm o funcție C: int citeste_info(Info* out)
extern "C" fn citeste_info(out: *mut Info) -> i32 {
    // SAFETY: apelantul trimite un pointer valid pentru scriere
    unsafe { out.write(Info { cod: 7, scor: 9.5 }) };
    0
}

fn main() {
    let mut info = MaybeUninit::<Info>::uninit();
    let status = citeste_info(info.as_mut_ptr());
    if status == 0 {
        // SAFETY: funcția a returnat 0, deci a inițializat complet `info`
        let info = unsafe { info.assume_init() };
        println!("{info:?}");
    }
}
```

## Unelte pentru legături

- **bindgen**: generează declarații Rust (`extern "C"`, structuri `repr(C)`) din fișiere header C, de obicei din `build.rs`;
- **cbindgen**: invers, generează un header C din codul Rust `extern "C"`;
- **cxx**: legături sigure între Rust și C++, cu verificare la compilare de ambele părți;
- **PyO3**, **napi-rs**, **jni**: extensii pentru Python, Node.js și Java scrise în Rust.

> **De reținut:** pointerii au adresă **și** provenance, iar API-urile `addr` / `with_addr` / `map_addr` o păstrează explicit. Aliasing-ul e definit de Stacked/Tree Borrows și verificat de Miri. Un panic din `extern "C"` produce abort, așa că îl prinzi cu `catch_unwind`. Pentru parametri de ieșire folosește `MaybeUninit`.

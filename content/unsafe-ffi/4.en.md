# Unsafe and FFI — Expert

Provenance, the aliasing models checked by Miri, unwinding across FFI, binding-generation tools and output parameters with `MaybeUninit`.

## Provenance: a pointer isn't just an address

To the compiler, a pointer has an **address** and **provenance**: information about the allocation it comes from and what access rights it has. Two pointers with the same address can be different: one may access the memory, the other may not. That's why pointer → integer → pointer conversions are delicate.

Since Rust 1.84, the *strict provenance* APIs are stable and make the intent explicit:

```rust
fn main() {
    let x = [1u16, 2, 3, 4];
    let p = x.as_ptr();

    let address: usize = p.addr();                 // just the address, no provenance
    println!("aligned to 2: {}", address % 2 == 0);

    // change the address while keeping the original provenance
    let p3 = p.with_addr(address + 2 * size_of::<u16>());
    // SAFETY: p3 points to x[2], inside the same allocation
    println!("x[2] = {}", unsafe { *p3 });

    // tags in the low bits of an aligned pointer (a technique from lock-free structures)
    let tagged = p.map_addr(|a| a | 1);
    let cleaned = tagged.map_addr(|a| a & !1);
    // SAFETY: cleaned == p
    println!("{}", unsafe { *cleaned });

    // a pointer without provenance: valid as a value, can't be dereferenced
    let sentinel: *const u8 = std::ptr::without_provenance(0x1000);
    println!("{:?}", sentinel);
}
```

For code that really has to turn integers into pointers (for example, addresses received from hardware), there are `expose_provenance` and `with_exposed_provenance`.

## The aliasing models and Miri

The precise aliasing rules for `unsafe` code are defined by formal models: **Stacked Borrows** and its more permissive successor, **Tree Borrows**. The basic idea: each reference gets a "tag", and creating a `&mut` reference invalidates the tags of other references to the same memory.

```rust
fn main() {
    let mut x = 0i32;
    let p1 = &mut x as *mut i32;
    let p2 = &mut x as *mut i32; // creates a new &mut, so it invalidates p1 under Stacked Borrows
    // SAFETY: OK for p2, which is the most recent one
    unsafe { *p2 = 5; }
    // unsafe { *p1 = 7; } // UB under Stacked Borrows: p1 has been invalidated
    let _ = p1;
    println!("{x}");
}
```

The code above compiles and even runs "correctly" with the commented-out line enabled. Only **Miri** detects the problem:

```bash
rustup +nightly component add miri
cargo +nightly miri run
MIRIFLAGS="-Zmiri-tree-borrows" cargo +nightly miri test   # the Tree Borrows model
```

Miri is an interpreter for MIR that checks, on every operation, aliasing, alignment, initialization, provenance and data races. It's slow (50–1000 times), but it's the best tool for testing `unsafe` code.

## Unwinding across FFI

| ABI | Panic from Rust | Exception from C++ |
|---|---|---|
| `extern "C"` | **abort** (since Rust 1.81) | UB |
| `extern "C-unwind"` | propagates | propagates |

A panic must not escape from an `extern "C"` function, so Rust aborts the process. To turn it into an error code, you catch it with `catch_unwind` at the boundary:

```rust
use std::panic;

#[unsafe(no_mangle)]
pub extern "C" fn safe_divide(a: i32, b: i32, result: *mut i32) -> i32 {
    match panic::catch_unwind(|| a / b) {
        Ok(v) => {
            // SAFETY: the caller passes a valid pointer
            unsafe { *result = v };
            0
        }
        Err(_) => -1, // panic caught: an error code instead of an abort
    }
}

fn main() {
    panic::set_hook(Box::new(|_| {})); // hide the panic message, for the example
    let mut r = 0;
    let ok = safe_divide(10, 2, &mut r);
    let err = safe_divide(1, 0, &mut r);
    println!("{ok} → {r}, then {err}");
}
```

## Output parameters with `MaybeUninit`

C APIs often write the result into a pointer they receive (an *out parameter*). The memory is uninitialized before the call, so you use `MaybeUninit`, not an invented value:

```rust
use std::mem::MaybeUninit;

#[repr(C)]
#[derive(Debug)]
struct Info {
    code: u32,
    score: f64,
}

// we simulate a C function: int read_info(Info* out)
extern "C" fn read_info(out: *mut Info) -> i32 {
    // SAFETY: the caller passes a pointer valid for writing
    unsafe { out.write(Info { code: 7, score: 9.5 }) };
    0
}

fn main() {
    let mut info = MaybeUninit::<Info>::uninit();
    let status = read_info(info.as_mut_ptr());
    if status == 0 {
        // SAFETY: the function returned 0, so it fully initialized `info`
        let info = unsafe { info.assume_init() };
        println!("{info:?}");
    }
}
```

## Binding tools

- **bindgen**: generates Rust declarations (`extern "C"`, `repr(C)` structs) from C header files, usually from `build.rs`;
- **cbindgen**: the reverse, generates a C header from `extern "C"` Rust code;
- **cxx**: safe bindings between Rust and C++, checked at compile time on both sides;
- **PyO3**, **napi-rs**, **jni**: extensions for Python, Node.js and Java written in Rust.

> **Key takeaway:** pointers have an address **and** provenance, and the `addr` / `with_addr` / `map_addr` APIs preserve it explicitly. Aliasing is defined by Stacked/Tree Borrows and checked by Miri. A panic from `extern "C"` aborts, so you catch it with `catch_unwind`. For output parameters, use `MaybeUninit`.

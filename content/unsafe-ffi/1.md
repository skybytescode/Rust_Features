# Unsafe și FFI — Fundamente

Compilatorul Rust verifică memoria strict, dar unele operații corecte nu pot fi demonstrate automat ca sigure. Pentru ele există `unsafe`: un bloc în care **tu** garantezi corectitudinea, nu compilatorul.

## Ce înseamnă `unsafe`

`unsafe` **nu** dezactivează verificările. Borrow checker-ul, tipurile și ownership-ul funcționează în continuare. `unsafe` deblochează doar cinci operații în plus:

1. dereferențierea unui **pointer brut** (`*const T`, `*mut T`);
2. apelul unei funcții `unsafe`, inclusiv al funcțiilor din alte limbaje;
3. accesarea sau modificarea unei variabile `static mut`;
4. implementarea unui trait `unsafe`;
5. citirea câmpurilor unui `union`.

## Pointeri bruți

Un pointer brut e ca un pointer din C: poate fi nul, poate indica spre memorie eliberată și nu e verificat de borrow checker. Îl poți **crea** oricând, dar îl poți **folosi** doar în `unsafe`:

```rust
fn main() {
    let mut x = 10;
    let p = &mut x as *mut i32; // crearea e sigură

    unsafe {
        // SAFETY: `p` provine dintr-o referință validă către `x`, care încă trăiește
        *p += 5;
        println!("x = {}", *p);
    }
}
```

Comentariul `// SAFETY:` explică **de ce** operația e corectă. E o convenție puternică în comunitatea Rust.

## Fără `unsafe`, compilatorul refuză

```rust,compile_fail
fn main() {
    let x = 5;
    let p = &x as *const i32;
    println!("{}", *p); // eroare E0133: dereferențierea cere `unsafe`
}
```

## Funcții `unsafe`

O funcție marcată `unsafe fn` are **condiții** pe care apelantul trebuie să le respecte. Biblioteca standard are câteva, de exemplu `get_unchecked`, care sare peste verificarea indexului:

```rust
fn main() {
    let v = vec![10, 20, 30];
    let i = 1;
    if i < v.len() {
        // SAFETY: am verificat mai sus că `i` e în limite
        let x = unsafe { *v.get_unchecked(i) };
        println!("{x}");
    }
}
```

## FFI: apelarea codului C

**FFI** (*Foreign Function Interface*) îți permite să apelezi funcții scrise în C sau în alt limbaj. Le declari într-un bloc `extern "C"`:

```rust
unsafe extern "C" {
    fn abs(x: i32) -> i32; // funcție din biblioteca standard C
}

fn main() {
    // SAFETY: `abs` din libc acceptă orice i32 (cu excepția i32::MIN, pe care nu o trimitem)
    let r = unsafe { abs(-42) };
    println!("{r}");
}
```

Compilatorul nu poate verifica ce face codul C, așa că apelul e `unsafe`.

## Când folosești `unsafe`

Rar. În aproape orice aplicație, codul tău nu are nevoie de `unsafe`. Apare în:

- biblioteci de nivel jos (structuri de date, alocatoare, drivere);
- legături cu biblioteci C;
- optimizări extreme, după ce ai măsurat că sunt necesare.

> **De reținut:** `unsafe` deblochează cinci operații în plus, nu dezactivează verificările. Pointerii bruți se creează liber, dar se folosesc doar în `unsafe`. Scrie de fiecare dată un comentariu `// SAFETY:`. FFI se face prin blocuri `extern "C"`.

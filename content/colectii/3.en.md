# Collections — Advanced

The complexity of the operations, lookups without allocations, custom keys and a few lesser-known techniques.

## Complexity

| Operation | `Vec` | `VecDeque` | `HashMap` | `BTreeMap` |
|---|---|---|---|---|
| access by index / key | O(1) | O(1) | O(1) average | O(log n) |
| append at the end | O(1) amortized | O(1) amortized | O(1) average | O(log n) |
| insert at the front | O(n) | O(1) amortized | — | — |
| insert in the middle | O(n) | O(n) | — | — |
| ordered iteration | — | — | no | yes |

"Amortized" means that even though a reallocation costs O(n), capacity grows geometrically, so the average per operation stays O(1).

## Looking up with `&str` in a `HashMap<String, _>`

You don't need to create a `String` to look something up. `get` accepts any type `Q` for which the key implements `Borrow<Q>`, and `String: Borrow<str>`:

```rust
use std::collections::HashMap;

fn main() {
    let mut capitals: HashMap<String, String> = HashMap::new();
    capitals.insert("France".to_string(), "Paris".to_string());

    let country: &str = "France";
    println!("{:?}", capitals.get(country)); // no allocation
}
```

The `Borrow` contract requires `Hash`, `Eq` and `Ord` to give the same result for `String` and for `str`. That's why `Borrow` exists separately from `AsRef`.

## Custom keys

For a `HashMap`, the key must implement `Hash + Eq`. For a `BTreeMap`, it must implement `Ord`. The simplest way is with `derive`:

```rust
use std::collections::{BTreeMap, HashMap};

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord)]
struct Position {
    row: u8,
    column: u8,
}

fn main() {
    let mut board = HashMap::new();
    board.insert(Position { row: 0, column: 4 }, "king");

    let mut ordered = BTreeMap::new();
    ordered.insert(Position { row: 1, column: 0 }, "pawn");
    ordered.insert(Position { row: 0, column: 7 }, "rook");

    println!("{:?}", board.get(&Position { row: 0, column: 4 }));
    println!("{ordered:?}"); // ordered by `row`, then by `column`
}
```

`derive(PartialOrd, Ord)` compares the fields **in declaration order**.

## Range queries

`BTreeMap` and `BTreeSet` quickly answer questions like "all keys between A and B" or "the nearest key":

```rust
use std::collections::BTreeMap;

fn main() {
    let mut events = BTreeMap::new();
    for (hour, what) in [(9, "meeting"), (12, "lunch"), (14, "demo"), (18, "gym")] {
        events.insert(hour, what);
    }

    let afternoon: Vec<_> = events.range(12..18).collect();
    println!("{afternoon:?}");

    let next = events.range(13..).next();
    println!("after 13:00: {next:?}");
}
```

## Priority queue

`BinaryHeap` always takes out **the largest** element. For a min-heap, wrap the values in `std::cmp::Reverse`:

```rust
use std::cmp::Reverse;
use std::collections::BinaryHeap;

fn main() {
    let mut tasks = BinaryHeap::new();
    tasks.push((2, "write the report"));
    tasks.push((5, "fix the server"));
    tasks.push((1, "coffee"));
    while let Some((priority, task)) = tasks.pop() {
        println!("[{priority}] {task}");
    }

    let mut min = BinaryHeap::from([Reverse(7), Reverse(3), Reverse(9)]);
    println!("smallest: {:?}", min.pop().map(|Reverse(x)| x));
}
```

## `drain`, `split_off` and binary search

```rust
fn main() {
    let mut v: Vec<i32> = (1..=10).collect();

    let first: Vec<_> = v.drain(..3).collect(); // removes and returns a range
    let tail = v.split_off(4);                   // splits the vector in two
    println!("{first:?} {v:?} {tail:?}");

    let sorted = [1, 3, 5, 7, 9];
    println!("{:?}", sorted.binary_search(&7)); // Ok(3): found at index 3
    println!("{:?}", sorted.binary_search(&4)); // Err(2): would be inserted at index 2
}
```

## Sorting by a key

```rust
fn main() {
    let mut people = vec![("Mike", 34), ("Ana", 28), ("Joan", 34)];

    people.sort_by_key(|&(_, age)| age);
    println!("{people:?}"); // stable: Mike stays before Joan

    people.sort_by(|a, b| b.1.cmp(&a.1).then(a.0.cmp(b.0)));
    println!("{people:?}"); // age descending, then name ascending
}
```

`sort` / `sort_by` are **stable**: equal elements keep their relative order. `sort_unstable` is slightly faster and doesn't allocate extra memory.

> **Key takeaway:** choose a collection by its dominant operations. Look up `String` keys with `&str` thanks to `Borrow`. `BTreeMap::range` gives you range queries, and `BinaryHeap` with `Reverse` gives you a min-heap.

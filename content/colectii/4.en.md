# Colecții — Expert

Cum sunt construite colecțiile standard: layout-ul unui `Vec`, strategia de creștere, tabelele hash de tip SwissTable și arborii B.

## Layout-ul unui `Vec<T>`

Un `Vec<T>` are trei cuvinte pe stivă: **pointer** către buffer-ul din heap, **capacitate** și **lungime**. `String` este un `Vec<u8>` cu invariantul că octeții sunt UTF-8 valid. `Box<[T]>` are doar două cuvinte (pointer și lungime), pentru că nu mai poate crește:

```rust
fn main() {
    println!("Vec<u8>:    {}", size_of::<Vec<u8>>());    // 24
    println!("String:     {}", size_of::<String>());     // 24
    println!("Box<[u8]>:  {}", size_of::<Box<[u8]>>());  // 16
    println!("Option<Vec<u8>>: {}", size_of::<Option<Vec<u8>>>()); // 24: pointerul nu e niciodată nul

    let v: Vec<u8> = Vec::new();
    println!("Vec::new() alocă? capacitate = {}", v.capacity()); // 0: nicio alocare
}
```

`Vec::new()` nu alocă nimic. Pointerul este unul „dangling”, aliniat și nenul (`NonNull::dangling()`). Prima alocare are loc la primul `push`.

## Strategia de creștere

Implementarea actuală **dublează** capacitatea la fiecare realocare, pornind de la un minim care depinde de mărimea elementului: 8 pentru elemente de 1 octet, 4 pentru elemente de cel mult 1 KiB, 1 pentru restul. Documentația **nu garantează** valorile exacte, doar că `push` e O(1) amortizat:

```rust
fn main() {
    let mut v: Vec<u64> = Vec::new();
    let mut ultima = v.capacity();
    for i in 0..100 {
        v.push(i);
        if v.capacity() != ultima {
            print!("{} ", v.capacity());
            ultima = v.capacity();
        }
    }
    println!();
}
```

O realocare **mută** toate elementele la o nouă adresă. Din acest motiv borrow checker-ul interzice să păstrezi o referință la un element în timp ce faci `push`.

Pentru tipurile de mărime zero, `Vec` nu alocă niciodată, iar capacitatea raportată este `usize::MAX`:

```rust
fn main() {
    let mut v = Vec::new();
    v.push(());
    v.push(());
    println!("len {}, capacitate {}", v.len(), v.capacity() == usize::MAX);
}
```

## `HashMap`: SwissTable

`std::collections::HashMap` folosește intern implementarea **hashbrown**, un port al tabelei *SwissTable* de la Google:

- elementele stau direct într-un singur array (*open addressing*, fără liste înlănțuite);
- un array separat de **octeți de control** păstrează 7 biți din hash-ul fiecărui slot;
- căutarea compară 16 octeți de control deodată, cu instrucțiuni SIMD, și verifică cheia doar la potrivire.

Funcția de hash implicită este **SipHash-1-3**, cu o cheie aleatoare per proces (`RandomState`). Te protejează de atacuri HashDoS, în care cineva trimite intenționat chei cu același hash, dar e mai lentă decât alternativele. Pentru chei mici și date de încredere, poți schimba hasher-ul:

```rust
use std::collections::HashMap;
use std::hash::{BuildHasherDefault, DefaultHasher};

fn main() {
    // DefaultHasher cu cheie fixă: determinist între rulări, util la teste
    let mut m: HashMap<u32, &str, BuildHasherDefault<DefaultHasher>> = HashMap::default();
    m.insert(1, "unu");
    m.insert(2, "doi");
    println!("{:?}", m.get(&2));
}
```

În practică, crate-uri ca `rustc-hash` (FxHash) sau `ahash` sunt mult mai rapide pentru chei întregi. Compilatorul Rust folosește FxHash intern.

Fiindcă cheia de hash e aleatoare, **ordinea de iterare diferă între rulări**. Nu te baza pe ea, nici măcar în teste.

## `BTreeMap`: arbore B

`BTreeMap` nu e un arbore binar. Fiecare nod conține până la 11 chei (în implementare, B = 6), stocate contiguu. Mai multe chei per nod înseamnă mai puține salturi prin memorie și o utilizare mai bună a cache-ului decât un arbore roșu-negru.

## Invalidarea iteratorilor nu poate apărea

În C++, modificarea unui `std::vector` în timp ce îl parcurgi e comportament nedefinit. În Rust, aceeași greșeală e o eroare de compilare, pentru că iteratorul ține un împrumut asupra colecției:

```rust,compile_fail
fn main() {
    let mut v = vec![1, 2, 3];
    for x in &v {
        if *x == 2 {
            v.push(4); // eroare E0502: `v` e deja împrumutat de iterator
        }
    }
}
```

Soluțiile idiomatice: colectezi modificările într-un vector separat și le aplici după buclă, folosești `retain` sau `extend`, ori parcurgi cu indecși dacă algoritmul chiar cere asta.

## `shrink_to_fit` și `into_boxed_slice`

După ce ai terminat de construit o colecție mare, poți elibera capacitatea nefolosită:

```rust
fn main() {
    let mut v = Vec::with_capacity(1000);
    v.extend(0..10);
    v.shrink_to_fit();
    println!("capacitate după shrink: {}", v.capacity()); // 10
    let fix: Box<[i32]> = v.into_boxed_slice(); // lungime fixă, 16 octeți pe stivă
    println!("{}", fix.len());
}
```

> **De reținut:** `Vec` = (pointer, capacitate, lungime), cu creștere geometrică, iar valorile exacte nu sunt garantate. `HashMap` este un SwissTable cu SipHash și ordine de iterare aleatoare. `BTreeMap` e un arbore B cu noduri late. Borrow checker-ul face imposibilă invalidarea iteratorilor.

# Collections — Practitioner

The operations you'll use every day, and how to choose the right collection.

## Common operations on `Vec`

```rust
fn main() {
    let mut v = vec![5, 3, 8, 3, 1, 8];

    v.sort();                    // [1, 3, 3, 5, 8, 8]
    v.dedup();                   // removes consecutive duplicates: [1, 3, 5, 8]
    v.retain(|&x| x != 5);       // keeps only what meets the condition: [1, 3, 8]
    v.insert(1, 2);              // inserts at position 1: [1, 2, 3, 8]
    let removed = v.remove(0);   // removes from position 0
    v.extend([9, 10]);           // appends several elements

    println!("{v:?}, removed: {removed}");
    println!("contains 8? {}", v.contains(&8));
    println!("first two: {:?}", &v[..2]); // slice
}
```

`insert` and `remove` shift every element after the position, so they are O(n). If order doesn't matter, `swap_remove` is O(1).

## Capacity

A `Vec` reserves more space than it uses, so it doesn't reallocate on every `push`. If you know in advance how many elements there will be, reserve from the start:

```rust
fn main() {
    let mut v = Vec::with_capacity(1000);
    for i in 0..1000 {
        v.push(i); // no reallocation
    }
    println!("len {}, capacity {}", v.len(), v.capacity());
}
```

## `String` and `&str`

| | `String` | `&str` |
|---|---|---|
| Owns the data | yes | no, it's a borrow |
| Can be modified | yes (`push_str`, `clear`…) | no |
| Used for | new results, fields in structs | parameters, literals |

Text is stored as UTF-8, so a letter can take several bytes. That's why you can't index a `String` directly. You go through the characters with `.chars()`:

```rust
fn main() {
    let s = String::from("Zürich");
    println!("{} bytes, {} characters", s.len(), s.chars().count());

    let first_three: String = s.chars().take(3).collect();
    println!("{first_three}");

    for (i, c) in s.char_indices() {
        print!("{i}:{c} ");
    }
    println!();

    println!("{}", s.to_uppercase());
    println!("{:?}", "a,b,,c".split(',').collect::<Vec<_>>());
}
```

## The entry API for `HashMap`

`entry` avoids two lookups (one for "does it exist?" and one for "insert"):

```rust
use std::collections::HashMap;

fn main() {
    let students = [("Ana", 9), ("Mike", 7), ("Ana", 10), ("Joan", 8), ("Mike", 6)];

    let mut grades: HashMap<&str, Vec<u32>> = HashMap::new();
    for (name, grade) in students {
        grades.entry(name).or_default().push(grade);
    }

    let mut names: Vec<_> = grades.keys().collect();
    names.sort();
    for n in names {
        let list = &grades[n];
        let mean = list.iter().sum::<u32>() as f64 / list.len() as f64;
        println!("{n}: {list:?}, mean {mean:.2}");
    }
}
```

## Other standard collections

| Collection | When to use it |
|---|---|
| `Vec<T>` | the default, for almost any list |
| `VecDeque<T>` | you add and remove at both ends (queues) |
| `HashMap<K, V>` | fast lookup by key |
| `BTreeMap<K, V>` | you need sorted keys or range lookups |
| `HashSet<T>` / `BTreeSet<T>` | unique values, without associations |
| `BinaryHeap<T>` | always take out the largest element (priority queues) |

```rust
use std::collections::{BTreeMap, HashSet, VecDeque};

fn main() {
    let mut queue = VecDeque::new();
    queue.push_back("customer 1");
    queue.push_back("customer 2");
    queue.push_front("urgent");
    println!("{:?}", queue.pop_front());

    let visited: HashSet<&str> = ["Paris", "Rome", "Paris"].into_iter().collect();
    println!("{} unique cities", visited.len());

    let mut ranking = BTreeMap::new();
    ranking.insert(3, "bronze");
    ranking.insert(1, "gold");
    ranking.insert(2, "silver");
    println!("{ranking:?}"); // always sorted by key
}
```

> **Key takeaway:** `sort`, `dedup`, `retain` and `extend` cover most needs. Use `with_capacity` when you know the size. Text is traversed with `chars()`, not by indexing, and `entry` inserts or updates in a single lookup.

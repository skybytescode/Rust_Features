# Error handling — Practitioner

In real code, errors travel from the function that produces them to the place where they can be handled. The `?` operator does this without ceremony.

## The `?` operator

`?` after a `Result` returns the value inside `Ok`. If it finds an `Err`, it **leaves the function immediately** and returns the error:

```rust
use std::num::ParseIntError;

fn sum_texts(a: &str, b: &str) -> Result<i32, ParseIntError> {
    let x: i32 = a.trim().parse()?; // on error, the function returns Err here
    let y: i32 = b.trim().parse()?;
    Ok(x + y)
}

fn main() {
    println!("{:?}", sum_texts("2", " 40 "));
    println!("{:?}", sum_texts("2", "x"));
}
```

`?` also works with `Option`, in a function that returns `Option`.

## `main` can return `Result`

If `main` returns an error, the program prints it and exits with a non-zero code:

```rust
use std::error::Error;

fn main() -> Result<(), Box<dyn Error>> {
    let n: u32 = "12".parse()?;
    let m: f64 = "3.5".parse()?;
    println!("{}", n as f64 * m);
    Ok(())
}
```

`Box<dyn Error>` accepts any error type. It's the convenient choice for applications and prototypes.

## Your own error type

In a library or an important module, an `enum` describes exactly what can go wrong. You implement `Display` for the message and `Error` to make it an "official" error:

```rust
use std::fmt;

#[derive(Debug)]
enum ConfigError {
    Missing(String),
    Invalid { key: String, value: String },
}

impl fmt::Display for ConfigError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            ConfigError::Missing(key) => write!(f, "key `{key}` is missing"),
            ConfigError::Invalid { key, value } => {
                write!(f, "invalid value for `{key}`: {value}")
            }
        }
    }
}

impl std::error::Error for ConfigError {}

fn read_port(config: &[(&str, &str)]) -> Result<u16, ConfigError> {
    let (_, value) = config
        .iter()
        .find(|(k, _)| *k == "port")
        .ok_or_else(|| ConfigError::Missing("port".into()))?;
    value.parse().map_err(|_| ConfigError::Invalid {
        key: "port".into(),
        value: value.to_string(),
    })
}

fn main() {
    println!("{:?}", read_port(&[("port", "8080")]));
    for config in [&[][..], &[("port", "abc")]] {
        if let Err(e) = read_port(config) {
            println!("error: {e}");
        }
    }
}
```

## Automatic conversion with `From`

If you implement `From<OtherError>` for your type, `?` does the conversion on its own:

```rust
use std::num::ParseIntError;

#[derive(Debug)]
enum AppError {
    Number(ParseIntError),
    Negative(i64),
}

impl From<ParseIntError> for AppError {
    fn from(e: ParseIntError) -> Self {
        AppError::Number(e)
    }
}

fn age(text: &str) -> Result<u32, AppError> {
    let n: i64 = text.parse()?; // ParseIntError → AppError, automatically
    if n < 0 {
        return Err(AppError::Negative(n));
    }
    Ok(n as u32)
}

fn main() {
    println!("{:?}", age("30"));
    println!("{:?}", age("-2"));
    println!("{:?}", age("x"));
}
```

## Useful methods

```rust
fn main() {
    let r: Result<i32, String> = Err("failure".into());
    println!("{}", r.clone().unwrap_or(0));                       // default value
    println!("{}", r.clone().unwrap_or_else(|e| e.len() as i32)); // computed from the error
    println!("{:?}", r.clone().map(|n| n * 2));                   // transform Ok
    println!("{:?}", r.clone().map_err(|e| e.to_uppercase()));    // transform Err
    println!("{:?}", r.ok());                                     // Result → Option

    let o: Option<u8> = None;
    println!("{:?}", o.ok_or("missing"));                         // Option → Result
}
```

> **Key takeaway:** `?` propagates errors to the caller. `main` can return `Result`. For precise errors, define an `enum` with `Display` and `Error`, and implementing `From` lets `?` do the conversion for you.

# Error handling — Fundamentals

Rust splits errors into two categories:

- **unrecoverable errors**, that is bugs: the program stops with `panic!`;
- **recoverable errors**, such as a missing file or text that isn't a number: the function returns a `Result`, and the caller decides what to do.

Rust has no exceptions.

## `panic!`: stop the program

```rust,should_panic
fn main() {
    let v = vec![1, 2, 3];
    println!("start");
    let x = v[10]; // index out of bounds: panic
    println!("{x}");
}
```

The program prints the error message and stops. You can trigger a panic yourself with `panic!("message")`, for situations that "should never happen".

## `Result`: success or error

`Result<T, E>` is an enum with two variants:

- `Ok(value)`: the operation succeeded, and `value` has type `T`;
- `Err(error)`: the operation failed, and `error` has type `E`.

```rust
fn main() {
    let texts = ["42", "abc"];
    for t in texts {
        match t.parse::<i32>() {
            Ok(n) => println!("{t} → number: {n}"),
            Err(e) => println!("{t} → error: {e}"),
        }
    }
}
```

The compiler forces you to handle the `Result`: you can't use a `Result<i32, _>` directly as an `i32`.

## Your own functions that can fail

```rust
fn divide(a: i32, b: i32) -> Result<i32, String> {
    if b == 0 {
        Err(String::from("division by zero"))
    } else {
        Ok(a / b)
    }
}

fn main() {
    match divide(10, 2) {
        Ok(r) => println!("result: {r}"),
        Err(e) => println!("error: {e}"),
    }
    match divide(1, 0) {
        Ok(r) => println!("result: {r}"),
        Err(e) => println!("error: {e}"),
    }
}
```

## `Option` for "might be missing"

When a missing result isn't really an error (for example, searching for an element), use `Option`:

```rust
fn main() {
    let names = ["Ana", "Mike", "Joan"];
    match names.iter().position(|&n| n == "Mike") {
        Some(i) => println!("found at position {i}"),
        None => println!("not there"),
    }
}
```

## `unwrap` and `expect`

`unwrap()` takes the value out of an `Ok` or `Some` and **panics** if it finds an error. `expect("message")` does the same, but with a message of your choosing:

```rust
fn main() {
    let port: u16 = "8080".parse().unwrap();
    let timeout: u32 = "30".parse().expect("the timeout must be a number");
    println!("{port} {timeout}");
}
```

Use them in examples, in tests, or when you are **sure** the error can't happen. Otherwise, handle the error.

> **Key takeaway:** `panic!` is for bugs, `Result` for errors you expect, and `Option` for values that might be missing. `unwrap` and `expect` turn an error into a panic.

# Error handling — Advanced

When to choose `panic` and when `Result`, how to build error chains, and what the ecosystem offers.

## Panic or `Result`?

| Situation | Choose |
|---|---|
| The data comes from outside (user, file, network) | `Result` |
| Failure is a normal outcome (missing file, wrong password) | `Result` |
| An internal invariant was broken, so it's a bug | `panic!` |
| Prototype, example, test | `unwrap` / `expect` is fine |
| Continuing would be dangerous (corrupted data) | `panic!` |

A good rule for libraries: **don't panic on input data**. Let the caller decide. If a function can panic, document it in a `# Panics` section.

## Error chains: `source()`

A high-level error can keep the error that caused it. `Error::source()` lets you walk the whole chain:

```rust
use std::error::Error;
use std::fmt;

#[derive(Debug)]
struct LoadError {
    file: String,
    cause: std::num::ParseIntError,
}

impl fmt::Display for LoadError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "could not load `{}`", self.file)
    }
}

impl Error for LoadError {
    fn source(&self) -> Option<&(dyn Error + 'static)> {
        Some(&self.cause)
    }
}

fn load() -> Result<u32, LoadError> {
    "abc".parse().map_err(|cause| LoadError { file: "config.txt".into(), cause })
}

fn main() {
    if let Err(e) = load() {
        println!("error: {e}");
        let mut cause = e.source();
        while let Some(c) = cause {
            println!("  caused by: {c}");
            cause = c.source();
        }
    }
}
```

## `thiserror` and `anyhow`

In practice, two crates remove almost all the boilerplate:

- **`thiserror`** (for libraries): `#[derive(Error)]` generates `Display`, `Error`, `source()` and `From` from attributes.
- **`anyhow`** (for applications): `anyhow::Result<T>` accepts any error, and `.context("message")` adds explanations along the way.

```rust
// Cargo.toml: thiserror = "2", anyhow = "1"
use anyhow::Context;

#[allow(dead_code)]
#[derive(Debug, thiserror::Error)]
enum DbError {
    #[error("connection failed")]
    Connection(#[from] std::io::Error),
    #[error("user {0} does not exist")]
    NotFound(u64),
}

fn read_config() -> anyhow::Result<String> {
    std::fs::read_to_string("config.toml").context("could not read the configuration")
}

fn main() {
    println!("{}", DbError::NotFound(7));
    if let Err(e) = read_config() {
        println!("{e:#}"); // `{:#}` prints the whole chain: context + cause
    }
}
```

## Collecting errors from iterators

`collect()` can turn an iterator of `Result`s into a `Result` of a collection. It stops at the **first** error:

```rust
fn main() {
    let good = ["1", "2", "3"];
    let bad = ["1", "x", "3"];

    let a: Result<Vec<i32>, _> = good.iter().map(|s| s.parse::<i32>()).collect();
    let b: Result<Vec<i32>, _> = bad.iter().map(|s| s.parse::<i32>()).collect();
    println!("{a:?}");
    println!("{b:?}");

    // To keep all the good values and skip the bad ones:
    let only_good: Vec<i32> = bad.iter().filter_map(|s| s.parse().ok()).collect();
    println!("{only_good:?}");
}
```

## `and_then`: chaining operations that can fail

```rust
fn parse(s: &str) -> Option<i32> {
    s.parse().ok()
}

fn square_root(n: i32) -> Option<f64> {
    if n >= 0 { Some((n as f64).sqrt()) } else { None }
}

fn main() {
    println!("{:?}", parse("16").and_then(square_root)); // Some(4.0)
    println!("{:?}", parse("-4").and_then(square_root)); // None
    println!("{:?}", parse("x").and_then(square_root));  // None
}
```

## Catching a panic

`std::panic::catch_unwind` stops a panic from going further up. It is **not** an exception mechanism: use it only at boundaries, for example so a whole server doesn't crash because of one request, or at an FFI boundary.

```rust
use std::panic;

fn main() {
    panic::set_hook(Box::new(|_| {})); // hide the default message, for the example
    let result = panic::catch_unwind(|| {
        let v: Vec<i32> = Vec::new();
        v[0]
    });
    let _ = panic::take_hook();
    println!("panic caught: {}", result.is_err());
}
```

> **Key takeaway:** use `Result` for external data and `panic` for bugs. Expose causes through `source()`. Choose `thiserror` for libraries and `anyhow` for applications. `collect()` gathers results into a `Result<Vec<_>, _>`.

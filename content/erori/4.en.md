# Error handling — Expert

How `?` is implemented, what exactly happens during a panic, and what errors cost at runtime.

## How `?` is translated

`expr?` uses the `Try` trait (still unstable). Roughly, it becomes:

```rust,ignore
match Try::branch(expr) {
    ControlFlow::Continue(value) => value,
    ControlFlow::Break(residual) => return FromResidual::from_residual(residual),
}
```

For `Result<T, E>`, the "residual" is `Result<Infallible, E>`. The `FromResidual` implementation for `Result<U, F>` calls `From::from(e)`. That's where the automatic error conversion comes from. On stable, you can write the equivalent directly:

```rust
use std::num::ParseIntError;

#[derive(Debug)]
struct MyError(ParseIntError);

impl From<ParseIntError> for MyError {
    fn from(e: ParseIntError) -> Self { MyError(e) }
}

fn with_operator(s: &str) -> Result<i32, MyError> {
    Ok(s.parse::<i32>()? * 2)
}

fn without_operator(s: &str) -> Result<i32, MyError> {
    let n = match s.parse::<i32>() {
        Ok(n) => n,
        Err(e) => return Err(From::from(e)),
    };
    Ok(n * 2)
}

fn main() {
    println!("{:?} {:?}", with_operator("21"), without_operator("21"));
    println!("{:?}", with_operator("x").is_err() && without_operator("x").is_err());
}
```

The same mechanism makes `?` work on `Option` and on `ControlFlow`. You can't mix `Option` and `Result` in the same function without an explicit conversion (`ok_or`), though.

## The runtime cost of errors

A `Result` is an ordinary value: an enum returned in registers or through memory, like any other enum. There are no exception tables or stack unwinding on the error path. The cost of an error is the cost of an `if`.

Size does matter, though: a `Result<T, E>` takes at least as much as the larger of the two variants. A large error type (for example, an enum with `String`s and context) makes every `Result` larger, even on the success path. A common technique is to put the error in a `Box`:

```rust
#[allow(dead_code)]
struct BigError {
    message: String,
    details: [u8; 120],
}

fn main() {
    println!("Result<u32, BigError>:      {}", size_of::<Result<u32, BigError>>());
    println!("Result<u32, Box<BigError>>: {}", size_of::<Result<u32, Box<BigError>>>());
}
```

## What happens during a panic

1. A message and a location are built (`#[track_caller]` decides which location is reported).
2. The **panic hook** is called. The default hook prints the message and, with `RUST_BACKTRACE=1`, the backtrace.
3. Then one of two strategies follows, chosen at compile time:
   - **unwind** (the default): the stack is unwound frame by frame, and `drop` runs for every variable. The thread stops, and if it's the main thread, the process exits with code 101.
   - **abort** (`panic = "abort"` in `Cargo.toml`): the process stops immediately, without destructors. The binary is smaller and the code slightly faster.

You can replace the hook to send panics to a logging system:

```rust,should_panic
use std::panic;

fn main() {
    panic::set_hook(Box::new(|info| {
        let location = info.location().map(|l| format!("{}:{}", l.file(), l.line()));
        let message = info.payload_as_str().unwrap_or("(no message)");
        eprintln!("[LOG] panic at {location:?}: {message}");
    }));

    let v: Vec<u8> = Vec::new();
    let _ = v[3];
}
```

## Programmatic backtraces

`std::backtrace::Backtrace::capture()` respects the `RUST_BACKTRACE` environment variable and is cheap when capturing is disabled. `force_capture()` always captures. Error crates use this to keep the backtrace from where the error happened, not from where it is printed:

```rust
use std::backtrace::{Backtrace, BacktraceStatus};

fn main() {
    let bt = Backtrace::capture();
    println!("capture enabled: {}", bt.status() == BacktraceStatus::Captured);
    let forced = Backtrace::force_capture();
    println!("frames captured when forced: {}", forced.to_string().lines().count() > 0);
}
```

## Panics and FFI

A panic must not cross an `extern "C"` boundary. If it happens, Rust aborts the process. For code that **must** propagate unwinding between languages (for example, C++ throwing exceptions through Rust), there is the `extern "C-unwind"` ABI.

## `Box<dyn Error + Send + Sync>` and downcasting

For an error to cross threads, it needs `Send + Sync`. The concrete type can be recovered with `downcast_ref`:

```rust
use std::error::Error;
use std::num::ParseIntError;

type GenericError = Box<dyn Error + Send + Sync + 'static>;

fn operation() -> Result<i32, GenericError> {
    Ok("not a number".parse::<i32>()?)
}

fn main() {
    let e = operation().unwrap_err();
    if let Some(pe) = e.downcast_ref::<ParseIntError>() {
        println!("it's a parse error: {pe}");
    }
    let thread = std::thread::spawn(move || format!("in another thread: {e}"));
    println!("{}", thread.join().unwrap());
}
```

> **Key takeaway:** `?` = `match` + `return Err(From::from(e))`, through the `Try` trait. A `Result` costs as much as an `if`, but a large error makes every `Result` larger. A panic either unwinds or aborts, and `C-unwind` is the only legal way to unwind through FFI.

# Gestionarea erorilor — Expert

Cum e implementat `?`, ce se întâmplă exact la un panic și cât costă erorile la runtime.

## Cum e tradus `?`

`expr?` folosește trait-ul `Try` (încă instabil). Aproximativ, devine:

```rust,ignore
match Try::branch(expr) {
    ControlFlow::Continue(valoare) => valoare,
    ControlFlow::Break(rezidual) => return FromResidual::from_residual(rezidual),
}
```

Pentru `Result<T, E>`, „reziduul” este `Result<Infallible, E>`. Implementarea `FromResidual` pentru `Result<U, F>` apelează `From::from(e)`. De aici vine conversia automată a erorilor. Pe stable, poți scrie echivalentul direct:

```rust
use std::num::ParseIntError;

#[derive(Debug)]
struct EroareMea(ParseIntError);

impl From<ParseIntError> for EroareMea {
    fn from(e: ParseIntError) -> Self { EroareMea(e) }
}

fn cu_operator(s: &str) -> Result<i32, EroareMea> {
    Ok(s.parse::<i32>()? * 2)
}

fn fara_operator(s: &str) -> Result<i32, EroareMea> {
    let n = match s.parse::<i32>() {
        Ok(n) => n,
        Err(e) => return Err(From::from(e)),
    };
    Ok(n * 2)
}

fn main() {
    println!("{:?} {:?}", cu_operator("21"), fara_operator("21"));
    println!("{:?}", cu_operator("x").is_err() && fara_operator("x").is_err());
}
```

Același mecanism face ca `?` să funcționeze pe `Option` și pe `ControlFlow`. Nu poți amesteca însă `Option` și `Result` în aceeași funcție fără conversie explicită (`ok_or`).

## Costul erorilor la runtime

Un `Result` este o valoare obișnuită: un enum returnat prin registre sau prin memorie, ca orice alt enum. Nu există tabele de excepții sau stack unwinding pe calea de eroare. Costul unei erori este cel al unui `if`.

Mărimea contează însă: un `Result<T, E>` ocupă cel puțin cât cea mai mare dintre variante. Un tip de eroare mare (de exemplu, un enum cu `String`-uri și context) face fiecare `Result` mai mare, chiar și pe calea de succes. O tehnică frecventă e să pui eroarea într-un `Box`:

```rust
#[allow(dead_code)]
struct EroareMare {
    mesaj: String,
    detalii: [u8; 120],
}

fn main() {
    println!("Result<u32, EroareMare>:      {}", size_of::<Result<u32, EroareMare>>());
    println!("Result<u32, Box<EroareMare>>: {}", size_of::<Result<u32, Box<EroareMare>>>());
}
```

## Ce se întâmplă la un panic

1. Se construiește un mesaj și o locație (`#[track_caller]` decide ce locație e raportată).
2. Se apelează **panic hook-ul**. Hook-ul implicit afișează mesajul și, cu `RUST_BACKTRACE=1`, backtrace-ul.
3. Apoi urmează una dintre două strategii, aleasă la compilare:
   - **unwind** (implicit): stiva e desfăcută cadru cu cadru, iar pentru fiecare variabilă se rulează `drop`. Thread-ul se oprește, iar dacă e thread-ul principal, procesul iese cu codul 101.
   - **abort** (`panic = "abort"` în `Cargo.toml`): procesul se oprește imediat, fără destructori. Binarul e mai mic, iar codul puțin mai rapid.

Poți înlocui hook-ul ca să trimiți panic-urile într-un sistem de logging:

```rust,should_panic
use std::panic;

fn main() {
    panic::set_hook(Box::new(|info| {
        let locatie = info.location().map(|l| format!("{}:{}", l.file(), l.line()));
        let mesaj = info.payload_as_str().unwrap_or("(fără mesaj)");
        eprintln!("[LOG] panic la {locatie:?}: {mesaj}");
    }));

    let v: Vec<u8> = Vec::new();
    let _ = v[3];
}
```

## Backtrace-uri programatice

`std::backtrace::Backtrace::capture()` respectă variabila de mediu `RUST_BACKTRACE` și e ieftin când captura e dezactivată. `force_capture()` captează întotdeauna. Crate-urile de erori păstrează astfel backtrace-ul din locul unde a apărut eroarea, nu din locul unde e afișată:

```rust
use std::backtrace::{Backtrace, BacktraceStatus};

fn main() {
    let bt = Backtrace::capture();
    println!("captură activă: {}", bt.status() == BacktraceStatus::Captured);
    let fortat = Backtrace::force_capture();
    println!("cadre capturate forțat: {}", fortat.to_string().lines().count() > 0);
}
```

## Panic-uri și FFI

Un panic nu are voie să traverseze o graniță `extern "C"`. Dacă se întâmplă, Rust oprește procesul (abort). Pentru cod care **trebuie** să propage unwinding-ul între limbaje (de exemplu, C++ care aruncă excepții prin Rust), există ABI-ul `extern "C-unwind"`.

## `Box<dyn Error + Send + Sync>` și downcast

Ca să treacă eroarea între thread-uri, ai nevoie de `Send + Sync`. Tipul concret poate fi recuperat cu `downcast_ref`:

```rust
use std::error::Error;
use std::num::ParseIntError;

type EroareGenerica = Box<dyn Error + Send + Sync + 'static>;

fn operatie() -> Result<i32, EroareGenerica> {
    Ok("nu e număr".parse::<i32>()?)
}

fn main() {
    let e = operatie().unwrap_err();
    if let Some(pe) = e.downcast_ref::<ParseIntError>() {
        println!("e o eroare de parsare: {pe}");
    }
    let thread = std::thread::spawn(move || format!("în alt thread: {e}"));
    println!("{}", thread.join().unwrap());
}
```

> **De reținut:** `?` = `match` + `return Err(From::from(e))`, prin trait-ul `Try`. Un `Result` costă cât un `if`, dar o eroare mare face fiecare `Result` mai mare. Un panic face fie unwind, fie abort, iar `C-unwind` e singura cale legală pentru unwinding prin FFI.

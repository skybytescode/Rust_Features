# Smart pointers — Expert

The layout of `Rc`, the role of `UnsafeCell` as the only legal gateway to interior mutability, a hand-written `RefCell` and a custom global allocator.

## The layout of `Rc<T>` and `Box<T>`

`Box<T>` is a single pointer, with **unique** owner semantics. The compiler treats it specially: you can move the value out of it with `*b`, and `rustc` attaches aliasing attributes to it similar to those of `&mut`.

`Rc<T>` is also a single pointer, but to a heap block that holds **two counters** in front of the value:

```text
Rc<T> ──► ┌──────────────┐
          │ strong: usize│
          │ weak:   usize│   (+1 implicitly while strong > 0)
          │ value:  T    │
          └──────────────┘
```

```rust
use std::rc::Rc;

fn main() {
    println!("Rc<u64>: {} bytes on the stack", size_of::<Rc<u64>>()); // 8
    println!("Rc<str>: {} bytes on the stack", size_of::<Rc<str>>()); // 16: fat pointer

    let a = Rc::new(7u64);
    let w = Rc::downgrade(&a);
    drop(a); // strong = 0: the value is destroyed, but the block stays while a Weak exists
    println!("upgrade after drop: {:?}", w.upgrade());
}
```

When `strong` reaches 0, the value is destroyed (`drop_in_place`). The block's memory is freed only when `weak` also reaches 0. All strong `Rc`s together count implicitly as one weak, so there's no race during destruction.

`Rc<str>` and `Rc<[T]>` are fat pointers, and `Rc::from("text")` copies the data once, into an allocation with the counters in front. They are more compact than `Rc<String>`, which goes through two indirections.

## `UnsafeCell`: the only legal way to modify through `&`

The compiler assumes that the data behind a `&T` **doesn't change** while the reference is alive, and LLVM receives this information (`readonly`, `noalias`). Modifying data through `&T`, even with `unsafe` and raw pointers, is **undefined behavior**, with one exception: data inside an `UnsafeCell<T>`.

`Cell`, `RefCell`, `Mutex`, `OnceCell` and the atomics are all built on top of `UnsafeCell`. That also makes them `!Sync`, except for those that explicitly synchronize access.

## A simplified `RefCell`

```rust
use std::cell::{Cell, UnsafeCell};
use std::ops::{Deref, DerefMut};

pub struct MiniRefCell<T> {
    value: UnsafeCell<T>,
    state: Cell<isize>, // 0 = free, >0 = n readers, -1 = one writer
}

pub struct Ref<'a, T> { cell: &'a MiniRefCell<T> }
pub struct RefMut<'a, T> { cell: &'a MiniRefCell<T> }

impl<T> MiniRefCell<T> {
    pub fn new(v: T) -> Self {
        MiniRefCell { value: UnsafeCell::new(v), state: Cell::new(0) }
    }

    pub fn borrow(&self) -> Ref<'_, T> {
        let s = self.state.get();
        assert!(s >= 0, "already mutably borrowed");
        self.state.set(s + 1);
        Ref { cell: self }
    }

    pub fn borrow_mut(&self) -> RefMut<'_, T> {
        assert!(self.state.get() == 0, "already borrowed");
        self.state.set(-1);
        RefMut { cell: self }
    }
}

impl<T> Deref for Ref<'_, T> {
    type Target = T;
    // SAFETY: state > 0 guarantees there's no active RefMut
    fn deref(&self) -> &T { unsafe { &*self.cell.value.get() } }
}

impl<T> Drop for Ref<'_, T> {
    fn drop(&mut self) { self.cell.state.set(self.cell.state.get() - 1); }
}

impl<T> Deref for RefMut<'_, T> {
    type Target = T;
    // SAFETY: state == -1 guarantees exclusive access
    fn deref(&self) -> &T { unsafe { &*self.cell.value.get() } }
}

impl<T> DerefMut for RefMut<'_, T> {
    // SAFETY: likewise, exclusive access
    fn deref_mut(&mut self) -> &mut T { unsafe { &mut *self.cell.value.get() } }
}

impl<T> Drop for RefMut<'_, T> {
    fn drop(&mut self) { self.cell.state.set(0); }
}

fn main() {
    let c = MiniRefCell::new(vec![1, 2]);
    c.borrow_mut().push(3);
    {
        let a = c.borrow();
        let b = c.borrow(); // two readers at once: OK
        println!("{:?} {:?}", *a, *b);
    }
    c.borrow_mut().push(4);
    println!("{:?}", *c.borrow());
}
```

`MiniRefCell` is automatically `!Sync`, because `UnsafeCell` and `Cell` are `!Sync`. The compiler won't let you share it between threads, where the non-atomic counter would cause a race.

## The global allocator

Every `Box`, `Vec` or `String` allocates through the **global allocator**. You can replace it with `#[global_allocator]`, for example with an allocator that counts allocations:

```rust
use std::alloc::{GlobalAlloc, Layout, System};
use std::sync::atomic::{AtomicUsize, Ordering};

struct Counter;

static ALLOCATIONS: AtomicUsize = AtomicUsize::new(0);

unsafe impl GlobalAlloc for Counter {
    unsafe fn alloc(&self, layout: Layout) -> *mut u8 {
        ALLOCATIONS.fetch_add(1, Ordering::Relaxed);
        // SAFETY: we delegate to the system allocator with the same layout
        unsafe { System.alloc(layout) }
    }
    unsafe fn dealloc(&self, ptr: *mut u8, layout: Layout) {
        // SAFETY: ptr was allocated by System.alloc with the same layout
        unsafe { System.dealloc(ptr, layout) }
    }
}

#[global_allocator]
static GLOBAL: Counter = Counter;

fn main() {
    let before = ALLOCATIONS.load(Ordering::Relaxed);
    let v: Vec<u32> = (0..100).collect();         // one allocation: the size is known in advance
    let s = format!("{} elements", v.len());      // one or more: the String can grow
    let b = Box::new(5);                           // one more
    let after = ALLOCATIONS.load(Ordering::Relaxed);
    println!("{s}, {b}, allocations: {}", after - before);
}
```

Allocators like `mimalloc` or `jemalloc` are installed the same way and can noticeably speed up programs that allocate heavily.

> **Key takeaway:** `Box` is a unique pointer, and `Rc` is a pointer to (strong, weak, value). All interior mutability goes through `UnsafeCell`, and modifying through `&` any other way is UB. A `RefCell` is just a counter plus an `UnsafeCell`, and `#[global_allocator]` lets you replace the allocator.

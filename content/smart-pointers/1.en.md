# Smart pointers — Fundamentals

A **smart pointer** is a type that behaves like a reference but also has extra data and behavior. It usually **owns** the value it points to. `String` and `Vec` are already smart pointers. Here you meet the most used ones: `Box`, `Rc` and `RefCell`.

## `Box<T>`: a value on the heap

`Box::new(x)` moves the value `x` to the heap. Only a pointer stays on the stack. When the `Box` goes out of scope, the memory is freed automatically:

```rust
fn main() {
    let b = Box::new(5);
    println!("b = {b}"); // you use it like the value itself
    let sum = *b + 1;    // `*` accesses the value
    println!("{sum}");
}
```

## Why you need `Box`: recursive types

A type can't contain itself directly, because it would have infinite size:

```rust,compile_fail
enum List {
    Node(i32, List), // error E0072: recursive type has infinite size
    Empty,
}

fn main() {}
```

With `Box`, the next element is only a pointer, so the type has a fixed size:

```rust
#[derive(Debug)]
enum List {
    Node(i32, Box<List>),
    Empty,
}

use List::{Empty, Node};

fn main() {
    let list = Node(1, Box::new(Node(2, Box::new(Node(3, Box::new(Empty))))));
    println!("{list:?}");
}
```

The same principle applies to trees: each node keeps its children in a `Box` or a `Vec`.

## `Rc<T>`: several owners

Sometimes a value needs **several** owners. `Rc` (*reference counted*) counts how many owners exist and frees the value when the last one goes away:

```rust
use std::rc::Rc;

fn main() {
    let settings = Rc::new(String::from("dark mode"));

    let window1 = Rc::clone(&settings); // doesn't copy the string, only bumps the counter
    let window2 = Rc::clone(&settings);

    println!("{window1} / {window2}");
    println!("owners: {}", Rc::strong_count(&settings)); // 3
}
```

`Rc::clone` is cheap: it increments a number. `Rc` allows only **reading**, and the data can't be modified through it.

## `RefCell<T>`: modification through a shared reference

`RefCell` lets you modify a value even when you only have a `&` reference to it. The borrowing rules are checked **at runtime** instead of at compile time:

```rust
use std::cell::RefCell;

fn main() {
    let log = RefCell::new(Vec::new());

    log.borrow_mut().push("started");   // mutable borrow
    log.borrow_mut().push("processed");

    println!("{:?}", log.borrow());     // shared borrow
}
```

## `Rc<RefCell<T>>`: shared and modifiable

This combination shows up often: several owners, any of whom can modify:

```rust
use std::cell::RefCell;
use std::rc::Rc;

fn main() {
    let cart = Rc::new(RefCell::new(Vec::new()));

    let ana = Rc::clone(&cart);
    let mike = Rc::clone(&cart);

    ana.borrow_mut().push("apples");
    mike.borrow_mut().push("bread");

    println!("shared cart: {:?}", cart.borrow());
}
```

> **Key takeaway:** `Box` puts a value on the heap and makes recursive types possible. `Rc` allows several owners, with read-only access. `RefCell` allows modification through `&`, checked at runtime. For shared, modifiable data you use `Rc<RefCell<T>>`.

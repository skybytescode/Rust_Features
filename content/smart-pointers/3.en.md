# Smart pointers — Advanced

How to choose the right pointer, how to avoid needless copies with `Cow`, and what `Pin` guarantees.

## A selection table

| You need | Use |
|---|---|
| a value on the heap, a single owner | `Box<T>` |
| several owners, same thread | `Rc<T>` |
| several owners, multiple threads | `Arc<T>` |
| modification through `&`, same thread | `Cell<T>` / `RefCell<T>` |
| modification through `&`, multiple threads | `Mutex<T>` / `RwLock<T>` / atomics |
| one-time initialization | `OnceCell<T>` / `OnceLock<T>` |
| "borrow or own", depending on the case | `Cow<'a, T>` |
| a value that never moves in memory again | `Pin<Box<T>>` |

## `Rc` vs. `Arc`

`Arc` (*atomically reference counted*) does the same as `Rc`, but with atomic operations on the counter, so it's safe across threads. The atomic cost is small, but real. Use `Rc` when you don't need threads, and the compiler will tell you if you got it wrong (`Rc` isn't `Send`).

```rust
use std::sync::Arc;
use std::thread;

fn main() {
    let data = Arc::new(vec![1, 2, 3]);
    let mut threads = Vec::new();
    for i in 0..3 {
        let d = Arc::clone(&data);
        threads.push(thread::spawn(move || d[i] * 10));
    }
    let results: Vec<i32> = threads.into_iter().map(|h| h.join().unwrap()).collect();
    println!("{results:?}");
}
```

## `Rc::make_mut` and clone-on-write

`Rc::make_mut` gives you `&mut T` if you're the **only** owner. If you're not, it first clones the value. That gets you cheap persistent data structures:

```rust
use std::rc::Rc;

fn main() {
    let original = Rc::new(vec![1, 2, 3]);
    let mut copy = Rc::clone(&original);

    Rc::make_mut(&mut copy).push(4); // there are 2 owners, so it clones

    println!("{original:?} {copy:?}");

    let mut unique = Rc::new(vec![9]);
    Rc::make_mut(&mut unique).push(10); // sole owner, modifies in place
    println!("{unique:?}");
}
```

## `Cow`: borrow when you can, copy when you must

`Cow<'a, str>` (*clone on write*) can be either a borrowed `&'a str` or an owned `String`. It's ideal for functions that **usually** don't modify the data:

```rust
use std::borrow::Cow;

fn normalize(text: &str) -> Cow<'_, str> {
    if text.contains('\t') {
        Cow::Owned(text.replace('\t', "    ")) // allocates only if needed
    } else {
        Cow::Borrowed(text) // no allocation
    }
}

fn main() {
    for t in ["no tabs", "with\ttab"] {
        let n = normalize(t);
        let kind = match n {
            Cow::Borrowed(_) => "borrowed",
            Cow::Owned(_) => "allocated",
        };
        println!("{n:?} ({kind})");
    }
}
```

## `OnceCell` and `LazyLock`

```rust
use std::cell::OnceCell;
use std::sync::LazyLock;

static TABLE: LazyLock<Vec<u64>> = LazyLock::new(|| {
    (0..10).map(|n| n * n).collect() // computed on first use
});

struct Report {
    summary: OnceCell<String>,
}

impl Report {
    fn summary(&self) -> &str {
        self.summary.get_or_init(|| {
            println!("(computing the summary just once)");
            "all is well".to_string()
        })
    }
}

fn main() {
    println!("{}", TABLE[7]);
    let r = Report { summary: OnceCell::new() };
    println!("{}", r.summary());
    println!("{}", r.summary());
}
```

## `Pin`: values that no longer move

Some values contain pointers **to themselves** (*self-referential*). If they were moved in memory, those pointers would become invalid. `Pin<P>` guarantees that the value `P` points to **will not be moved again**, except for `Unpin` types, which are safe to move anyway.

In practice, you meet `Pin` almost only with **async**: the futures generated by `async fn` can be self-referential, which is why `Future::poll` takes `Pin<&mut Self>`.

```rust
use std::pin::Pin;

fn main() {
    let future = async { 42 };
    let pinned: Pin<Box<_>> = Box::pin(future); // put on the heap and pinned there
    println!("{}", std::mem::size_of_val(&pinned)); // just a pointer
    // for most ordinary types (which are Unpin), Pin restricts nothing:
    let mut x = 5;
    let p = Pin::new(&mut x);
    *Pin::into_inner(p) += 1;
    println!("{x}");
}
```

> **Key takeaway:** `Arc` = atomic `Rc`, for threads. `make_mut` and `Cow` copy only when needed. `OnceCell` and `LazyLock` initialize lazily. `Pin` guarantees the value won't move again and is needed mostly for async.

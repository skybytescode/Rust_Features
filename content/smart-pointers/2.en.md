# Smart pointers — Practitioner

What makes a type a "smart pointer" (`Deref` and `Drop`), how to avoid cycles with `Weak`, and when to choose `Cell` instead of `RefCell`.

## `Deref`: reference-like behavior

A type that implements `Deref` can be used with `*` and gets **deref coercion**: `&YourType` converts automatically into `&Target` where needed:

```rust
use std::ops::Deref;

struct Name(String);

impl Deref for Name {
    type Target = String;
    fn deref(&self) -> &String {
        &self.0
    }
}

fn length(s: &str) -> usize {
    s.len()
}

fn main() {
    let n = Name(String::from("Joan"));
    println!("{}", n.to_uppercase()); // String's methods, through Deref
    println!("{}", length(&n));       // &Name → &String → &str, automatically
}
```

Use `Deref` only for types that really are "pointers to" something. It isn't an inheritance mechanism.

## `Drop`: code run on destruction

`Drop` lets you release resources when a value goes out of scope: files, connections, locks:

```rust
struct Connection {
    address: String,
}

impl Drop for Connection {
    fn drop(&mut self) {
        println!("closing the connection to {}", self.address);
    }
}

fn main() {
    let _a = Connection { address: "db:5432".into() };
    {
        let _b = Connection { address: "cache:6379".into() };
        println!("working with both");
    } // _b is closed here
    let c = Connection { address: "api:443".into() };
    drop(c); // explicit close, before the end of the scope
    println!("end");
} // _a is closed here
```

You can't call `x.drop()` directly. You use `drop(x)` (or `std::mem::drop`), which moves the value and destroys it.

## Cycles and `Weak`

Two `Rc`s that point to each other never reach a count of 0, so the memory is never freed (*memory leak*). `Weak` is a reference that does **not** keep the value alive. For parent–child relationships, children hold a `Weak` to their parent:

```rust
use std::cell::RefCell;
use std::rc::{Rc, Weak};

struct Node {
    name: String,
    parent: RefCell<Weak<Node>>,
    children: RefCell<Vec<Rc<Node>>>,
}

fn main() {
    let root = Rc::new(Node { name: "root".into(), parent: RefCell::new(Weak::new()), children: RefCell::new(vec![]) });
    let leaf = Rc::new(Node { name: "leaf".into(), parent: RefCell::new(Weak::new()), children: RefCell::new(vec![]) });

    *leaf.parent.borrow_mut() = Rc::downgrade(&root);
    root.children.borrow_mut().push(Rc::clone(&leaf));

    if let Some(p) = leaf.parent.borrow().upgrade() {
        println!("the leaf's parent: {}", p.name);
    }
    println!("children: {}", root.children.borrow().len());
    println!("root strong: {}, root weak: {}", Rc::strong_count(&root), Rc::weak_count(&root));
}
```

`upgrade()` returns an `Option<Rc<T>>`: `None` if the value has already been freed.

## `Cell` vs. `RefCell`

| | `Cell<T>` | `RefCell<T>` |
|---|---|---|
| Access | you copy the value in / out (`get`, `set`) | you borrow (`borrow`, `borrow_mut`) |
| Cost | zero | a counter checked on every borrow |
| Can panic | no | yes, on conflicting borrows |
| Suited for | counters, flags, small `Copy` types | larger structures (`Vec`, `String`) |

```rust
use std::cell::Cell;

struct Page {
    views: Cell<u32>,
}

impl Page {
    fn show(&self) { // only &self, yet we can increment
        self.views.set(self.views.get() + 1);
    }
}

fn main() {
    let p = Page { views: Cell::new(0) };
    p.show();
    p.show();
    println!("views: {}", p.views.get());
}
```

## Runtime panic with `RefCell`

If you break the borrowing rules, `RefCell` panics:

```rust,should_panic
use std::cell::RefCell;

fn main() {
    let data = RefCell::new(vec![1, 2, 3]);
    let reader = data.borrow();
    data.borrow_mut().push(4); // panic: already borrowed
    println!("{reader:?}");
}
```

`try_borrow_mut()` returns a `Result` instead of panicking, so you can handle the situation.

> **Key takeaway:** `Deref` gives reference-like behavior and automatic coercion, and `Drop` releases resources. `Weak` breaks cycles between `Rc`s. Choose `Cell` for small `Copy` values and `RefCell` for the rest, knowing it can panic.

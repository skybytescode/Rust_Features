# Smart pointers — Expert

Layout-ul lui `Rc`, rolul lui `UnsafeCell` ca singură poartă legală spre interior mutability, un `RefCell` scris de mână și un alocator global propriu.

## Layout-ul lui `Rc<T>` și `Box<T>`

`Box<T>` este un singur pointer, cu semantică de proprietar **unic**. Compilatorul îl tratează special: poți muta valoarea din el cu `*b`, iar `rustc` îi atașează atribute de aliasing similare cu cele ale lui `&mut`.

`Rc<T>` este tot un singur pointer, dar spre un bloc din heap care conține **două contoare** înaintea valorii:

```text
Rc<T> ──► ┌──────────────┐
          │ strong: usize│
          │ weak:   usize│   (+1 implicit cât timp strong > 0)
          │ valoare: T   │
          └──────────────┘
```

```rust
use std::rc::Rc;

fn main() {
    println!("Rc<u64>: {} octeți pe stivă", size_of::<Rc<u64>>()); // 8
    println!("Rc<str>: {} octeți pe stivă", size_of::<Rc<str>>()); // 16: fat pointer

    let a = Rc::new(7u64);
    let w = Rc::downgrade(&a);
    drop(a); // strong = 0: valoarea e distrusă, dar blocul rămâne cât timp există Weak
    println!("upgrade după drop: {:?}", w.upgrade());
}
```

Când `strong` ajunge la 0, valoarea e distrusă (`drop_in_place`). Memoria blocului e eliberată abia când și `weak` ajunge la 0. Toate `Rc`-urile tari contează împreună, implicit, ca un singur weak, ca să nu existe o cursă în timpul distrugerii.

`Rc<str>` și `Rc<[T]>` sunt pointeri fat, iar `Rc::from("text")` copiază datele o singură dată, într-o alocare cu contoarele în față. Sunt mai compacte decât `Rc<String>`, care face două indirectări.

## `UnsafeCell`: singura cale legală de a modifica prin `&`

Compilatorul presupune că datele din spatele unui `&T` **nu se schimbă** cât timp referința e vie, iar LLVM primește această informație (`readonly`, `noalias`). Să modifici date prin `&T`, chiar și cu `unsafe` și pointeri bruți, este **comportament nedefinit**, cu o singură excepție: datele aflate într-un `UnsafeCell<T>`.

`Cell`, `RefCell`, `Mutex`, `OnceCell` și atomicele sunt toate construite peste `UnsafeCell`. Acest lucru le face și `!Sync`, cu excepția celor care sincronizează explicit accesul.

## Un `RefCell` simplificat

```rust
use std::cell::{Cell, UnsafeCell};
use std::ops::{Deref, DerefMut};

pub struct MiniRefCell<T> {
    valoare: UnsafeCell<T>,
    stare: Cell<isize>, // 0 = liber, >0 = n cititori, -1 = un scriitor
}

pub struct Ref<'a, T> { celula: &'a MiniRefCell<T> }
pub struct RefMut<'a, T> { celula: &'a MiniRefCell<T> }

impl<T> MiniRefCell<T> {
    pub fn new(v: T) -> Self {
        MiniRefCell { valoare: UnsafeCell::new(v), stare: Cell::new(0) }
    }

    pub fn borrow(&self) -> Ref<'_, T> {
        let s = self.stare.get();
        assert!(s >= 0, "deja împrumutat mutabil");
        self.stare.set(s + 1);
        Ref { celula: self }
    }

    pub fn borrow_mut(&self) -> RefMut<'_, T> {
        assert!(self.stare.get() == 0, "deja împrumutat");
        self.stare.set(-1);
        RefMut { celula: self }
    }
}

impl<T> Deref for Ref<'_, T> {
    type Target = T;
    // SAFETY: stare > 0 garantează că nu există niciun RefMut activ
    fn deref(&self) -> &T { unsafe { &*self.celula.valoare.get() } }
}

impl<T> Drop for Ref<'_, T> {
    fn drop(&mut self) { self.celula.stare.set(self.celula.stare.get() - 1); }
}

impl<T> Deref for RefMut<'_, T> {
    type Target = T;
    // SAFETY: stare == -1 garantează acces exclusiv
    fn deref(&self) -> &T { unsafe { &*self.celula.valoare.get() } }
}

impl<T> DerefMut for RefMut<'_, T> {
    // SAFETY: la fel, acces exclusiv
    fn deref_mut(&mut self) -> &mut T { unsafe { &mut *self.celula.valoare.get() } }
}

impl<T> Drop for RefMut<'_, T> {
    fn drop(&mut self) { self.celula.stare.set(0); }
}

fn main() {
    let c = MiniRefCell::new(vec![1, 2]);
    c.borrow_mut().push(3);
    {
        let a = c.borrow();
        let b = c.borrow(); // doi cititori simultan: OK
        println!("{:?} {:?}", *a, *b);
    }
    c.borrow_mut().push(4);
    println!("{:?}", *c.borrow());
}
```

`MiniRefCell` e automat `!Sync`, pentru că `UnsafeCell` și `Cell` sunt `!Sync`. Compilatorul nu te lasă să-l partajezi între thread-uri, unde contorul neatomic ar produce o cursă.

## Alocatorul global

Orice `Box`, `Vec` sau `String` alocă prin **alocatorul global**. Îl poți înlocui cu `#[global_allocator]`, de exemplu cu un alocator care numără alocările:

```rust
use std::alloc::{GlobalAlloc, Layout, System};
use std::sync::atomic::{AtomicUsize, Ordering};

struct Numarator;

static ALOCARI: AtomicUsize = AtomicUsize::new(0);

unsafe impl GlobalAlloc for Numarator {
    unsafe fn alloc(&self, layout: Layout) -> *mut u8 {
        ALOCARI.fetch_add(1, Ordering::Relaxed);
        // SAFETY: delegăm la alocatorul sistemului cu același layout
        unsafe { System.alloc(layout) }
    }
    unsafe fn dealloc(&self, ptr: *mut u8, layout: Layout) {
        // SAFETY: ptr a fost alocat de System.alloc cu același layout
        unsafe { System.dealloc(ptr, layout) }
    }
}

#[global_allocator]
static GLOBAL: Numarator = Numarator;

fn main() {
    let inainte = ALOCARI.load(Ordering::Relaxed);
    let v: Vec<u32> = (0..100).collect();       // o alocare: mărimea e cunoscută dinainte
    let s = format!("{} elemente", v.len());     // una sau mai multe: String-ul poate crește
    let b = Box::new(5);                          // încă una
    let dupa = ALOCARI.load(Ordering::Relaxed);
    println!("{s}, {b}, alocări: {}", dupa - inainte);
}
```

Alocatoare ca `mimalloc` sau `jemalloc` se instalează la fel și pot accelera vizibil programele care alocă intens.

> **De reținut:** `Box` este un pointer unic, iar `Rc` un pointer spre (strong, weak, valoare). Orice interior mutability trece prin `UnsafeCell`, iar a modifica prin `&` în alt mod este UB. Un `RefCell` e doar un contor plus `UnsafeCell`, iar `#[global_allocator]` îți permite să înlocuiești alocatorul.

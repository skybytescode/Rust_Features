# Advanced generics — Advanced

The current limits of const generics, design techniques for libraries (sealed traits, extension traits), and associated types with constraints.

## What const generics accept today

On stable, a `const` parameter can only have the type of an integer, `bool` or `char`. Expressions that depend on the parameter can **not** appear in types:

```rust,compile_fail
fn double<const N: usize>(a: [u8; N]) -> [u8; N * 2] { // error: N * 2 isn't allowed here
    let mut r = [0; N * 2];
    r[..N].copy_from_slice(&a);
    r[N..].copy_from_slice(&a);
    r
}

fn main() {}
```

The feature is called `generic_const_exprs` and is still unstable. On stable you have two options: ask the caller for the size of the result as a separate parameter, or compute in the function body, where expressions are allowed:

```rust
fn double<const N: usize, const M: usize>(a: [u8; N]) -> [u8; M] {
    assert!(M == 2 * N, "M must be 2 * N"); // a runtime check (or compile-time, with const)
    let mut r = [0; M];
    r[..N].copy_from_slice(&a);
    r[N..].copy_from_slice(&a);
    r
}

struct Buffer<const N: usize>;

impl<const N: usize> Buffer<N> {
    const BYTES: usize = N * 8; // expressions are allowed in associated constants
}

fn main() {
    let d: [u8; 4] = double([1, 2]);
    println!("{d:?} {}", Buffer::<16>::BYTES);
}
```

A `const` value used as an argument must be wrapped in braces if it isn't a literal or a simple name: `Matrix::<{ 2 + 1 }, 3>`.

## Const parameters with default values

Since Rust 1.59, a `const` parameter can have a default value. It must come after the parameters without defaults:

```rust
#[derive(Debug)]
struct History<T, const MAX: usize = 4> {
    items: Vec<T>,
}

impl<T, const MAX: usize> History<T, MAX> {
    fn new() -> Self {
        History { items: Vec::with_capacity(MAX) }
    }

    fn add(&mut self, x: T) {
        if self.items.len() == MAX {
            self.items.remove(0);
        }
        self.items.push(x);
    }
}

fn main() {
    let mut default: History<i32> = History::new(); // MAX = 4
    let mut short: History<i32, 2> = History::new();
    for i in 1..=6 {
        default.add(i);
        short.add(i);
    }
    println!("{:?} {:?}", default.items, short.items);
}
```

## Sealed traits: traits nobody else can implement

Sometimes you want a public trait to be **usable** from outside the crate, but not **implementable**. That way you can later add new methods without a breaking change. The technique relies on a private supertrait:

```rust
mod formats {
    mod private {
        pub trait Sealed {} // a public trait, but in a private module: unreachable from outside
    }

    pub trait Format: private::Sealed {
        fn extension(&self) -> &'static str;
    }

    pub struct Json;
    pub struct Csv;

    impl private::Sealed for Json {}
    impl private::Sealed for Csv {}

    impl Format for Json { fn extension(&self) -> &'static str { "json" } }
    impl Format for Csv { fn extension(&self) -> &'static str { "csv" } }
}

use formats::Format;

fn main() {
    let list: [&dyn Format; 2] = [&formats::Json, &formats::Csv];
    for f in list {
        println!("{}", f.extension());
    }
    // Outside the `formats` module, `impl Format for MyType` doesn't compile:
    // the `Sealed` trait can't be named, so it can't be implemented either.
}
```

## Extension traits: new methods on foreign types

You can't add inherent methods to a type from another crate, but you can define a new trait and implement it for that type:

```rust
trait TextExt {
    fn count_vowels(&self) -> usize;
    fn title_case(&self) -> String;
}

impl TextExt for str {
    fn count_vowels(&self) -> usize {
        self.chars().filter(|c| "aeiouAEIOU".contains(*c)).count()
    }

    fn title_case(&self) -> String {
        self.split_whitespace()
            .map(|w| {
                let mut letters = w.chars();
                match letters.next() {
                    Some(first) => first.to_uppercase().chain(letters).collect::<String>(),
                    None => String::new(),
                }
            })
            .collect::<Vec<_>>()
            .join(" ")
    }
}

fn main() {
    println!("{}", "programming in rust".count_vowels());
    println!("{}", "programming in rust".title_case());
}
```

The naming convention is `NameExt`. The ecosystem uses it everywhere: `itertools::Itertools`, `futures::StreamExt` and others.

## Associated types with constraints

An associated type can have its own constraints, and whoever uses the trait can rely on them:

```rust
use std::fmt::Display;

trait Source {
    type Item: Display + Clone;
    fn next_item(&mut self) -> Option<Self::Item>;
}

struct Numbers(u32);

impl Source for Numbers {
    type Item = u32;
    fn next_item(&mut self) -> Option<u32> {
        self.0 += 1;
        (self.0 <= 3).then_some(self.0)
    }
}

fn show_all<S: Source>(mut s: S) {
    while let Some(e) = s.next_item() {
        print!("{e} "); // Display is guaranteed by the trait
    }
    println!();
}

fn main() {
    show_all(Numbers(0));
}
```

You can also constrain an associated type at the point of use: `fn f<I: Iterator<Item = u8>>(...)` or `where I::Item: Debug`.

> **Key takeaway:** expressions on const parameters (`N * 2`) aren't yet allowed in types, but they are allowed in bodies and in associated constants. Const parameters can have default values. Sealed traits block external implementations, and extension traits add methods to foreign types.

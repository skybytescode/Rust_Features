# Concurrency — Practitioner

How to share data between threads safely: `Arc`, `Mutex`, `RwLock` and scoped threads.

## `Arc<Mutex<T>>`: shared, modifiable data

- `Arc` allows several owners across threads;
- `Mutex` (*mutual exclusion*) allows only one thread at a time to access the data.

```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0));
    let mut threads = Vec::new();

    for _ in 0..8 {
        let counter = Arc::clone(&counter);
        threads.push(thread::spawn(move || {
            for _ in 0..1000 {
                *counter.lock().unwrap() += 1;
            }
        }));
    }
    for t in threads {
        t.join().unwrap();
    }
    println!("total: {}", *counter.lock().unwrap()); // always 8000
}
```

`lock()` returns a *guard*. While the guard exists, the mutex is locked, and when the guard is destroyed the mutex is released automatically. There's no `unlock()` for you to forget.

## Hold the lock as briefly as possible

A guard held for a long time blocks the other threads. Take what you need, release the lock, then work:

```rust
use std::sync::Mutex;

fn main() {
    let queue = Mutex::new(vec![3, 1, 2]);

    let task = {
        let mut q = queue.lock().unwrap();
        q.pop()
    }; // the lock is released here

    if let Some(t) = task {
        println!("processing {t} without holding the lock");
    }
}
```

## Scoped threads: borrowing without `Arc`

`thread::scope` guarantees that every thread started inside it finishes **before** leaving the block. That's why they can borrow local variables, without `move` and without `Arc`:

```rust
use std::thread;

fn main() {
    let data = vec![1, 2, 3, 4, 5, 6, 7, 8];
    let (left, right) = data.split_at(data.len() / 2);

    let (s1, s2) = thread::scope(|s| {
        let a = s.spawn(|| left.iter().sum::<i32>());
        let b = s.spawn(|| right.iter().sum::<i32>());
        (a.join().unwrap(), b.join().unwrap())
    });

    println!("{s1} + {s2} = {}", s1 + s2);
    println!("the data is still ours: {data:?}");
}
```

Writing in parallel works too, if each thread gets a distinct chunk:

```rust
use std::thread;

fn main() {
    let mut pixels = vec![0u8; 12];
    thread::scope(|s| {
        for (i, chunk) in pixels.chunks_mut(4).enumerate() {
            s.spawn(move || {
                for p in chunk {
                    *p = i as u8 * 10;
                }
            });
        }
    });
    println!("{pixels:?}");
}
```

## `RwLock`: many readers or one writer

When data is read often and modified rarely, `RwLock` allows **several** readers at the same time:

```rust
use std::sync::{Arc, RwLock};
use std::thread;

fn main() {
    let config = Arc::new(RwLock::new(String::from("v1")));

    let readers: Vec<_> = (0..3)
        .map(|i| {
            let c = Arc::clone(&config);
            thread::spawn(move || format!("reader {i}: {}", c.read().unwrap()))
        })
        .collect();
    for r in readers {
        println!("{}", r.join().unwrap());
    }

    *config.write().unwrap() = String::from("v2");
    println!("now: {}", config.read().unwrap());
}
```

## Deadlock: how to avoid it

A *deadlock* happens when two threads each wait for a lock held by the other. The golden rule: **always take locks in the same order**, and don't hold a lock while you wait for something else (a channel, another lock, I/O). Rust prevents data races, but it does **not** prevent deadlocks.

> **Key takeaway:** `Arc<Mutex<T>>` is the basic recipe for shared state. Hold the guard as briefly as possible. `thread::scope` lets you borrow local data without `Arc`. `RwLock` suits frequent reads. Deadlocks remain your responsibility.

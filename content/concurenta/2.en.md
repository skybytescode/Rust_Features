# Concurență — Practician

Cum partajezi date între thread-uri în siguranță: `Arc`, `Mutex`, `RwLock` și thread-urile cu scope.

## `Arc<Mutex<T>>`: date partajate și modificabile

- `Arc` permite mai mulți proprietari între thread-uri;
- `Mutex` (*mutual exclusion*) permite unui singur thread odată să acceseze datele.

```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let contor = Arc::new(Mutex::new(0));
    let mut fire = Vec::new();

    for _ in 0..8 {
        let contor = Arc::clone(&contor);
        fire.push(thread::spawn(move || {
            for _ in 0..1000 {
                *contor.lock().unwrap() += 1;
            }
        }));
    }
    for f in fire {
        f.join().unwrap();
    }
    println!("total: {}", *contor.lock().unwrap()); // întotdeauna 8000
}
```

`lock()` returnează un *guard*. Cât timp guard-ul există, mutex-ul e blocat, iar la distrugerea guard-ului e eliberat automat. Nu există `unlock()` pe care să-l poți uita.

## Ține lacătul cât mai puțin

Un guard ținut mult blochează celelalte thread-uri. Ia ce îți trebuie, eliberează lacătul, apoi lucrează:

```rust
use std::sync::Mutex;

fn main() {
    let coada = Mutex::new(vec![3, 1, 2]);

    let sarcina = {
        let mut c = coada.lock().unwrap();
        c.pop()
    }; // lacătul e eliberat aici

    if let Some(s) = sarcina {
        println!("procesez {s} fără să țin lacătul");
    }
}
```

## Thread-uri cu scope: împrumut fără `Arc`

`thread::scope` garantează că toate thread-urile pornite în interior se termină **înainte** de ieșirea din bloc. De aceea pot împrumuta variabile locale, fără `move` și fără `Arc`:

```rust
use std::thread;

fn main() {
    let date = vec![1, 2, 3, 4, 5, 6, 7, 8];
    let (stanga, dreapta) = date.split_at(date.len() / 2);

    let (s1, s2) = thread::scope(|s| {
        let a = s.spawn(|| stanga.iter().sum::<i32>());
        let b = s.spawn(|| dreapta.iter().sum::<i32>());
        (a.join().unwrap(), b.join().unwrap())
    });

    println!("{s1} + {s2} = {}", s1 + s2);
    println!("datele sunt încă ale noastre: {date:?}");
}
```

Și scrierea în paralel funcționează, dacă fiecare thread primește o bucată distinctă:

```rust
use std::thread;

fn main() {
    let mut pixeli = vec![0u8; 12];
    thread::scope(|s| {
        for (i, bucata) in pixeli.chunks_mut(4).enumerate() {
            s.spawn(move || {
                for p in bucata {
                    *p = i as u8 * 10;
                }
            });
        }
    });
    println!("{pixeli:?}");
}
```

## `RwLock`: mulți cititori sau un scriitor

Când datele sunt citite des și modificate rar, `RwLock` permite **mai mulți** cititori simultan:

```rust
use std::sync::{Arc, RwLock};
use std::thread;

fn main() {
    let config = Arc::new(RwLock::new(String::from("v1")));

    let cititori: Vec<_> = (0..3)
        .map(|i| {
            let c = Arc::clone(&config);
            thread::spawn(move || format!("cititor {i}: {}", c.read().unwrap()))
        })
        .collect();
    for c in cititori {
        println!("{}", c.join().unwrap());
    }

    *config.write().unwrap() = String::from("v2");
    println!("acum: {}", config.read().unwrap());
}
```

## Deadlock: cum îl eviți

Un *deadlock* apare când două thread-uri așteaptă fiecare un lacăt ținut de celălalt. Regula de aur: **ia lacătele mereu în aceeași ordine** și nu ține un lacăt cât aștepți altceva (un canal, un alt lacăt, I/O). Rust previne cursele de date (*data races*), dar **nu** previne deadlock-urile.

> **De reținut:** `Arc<Mutex<T>>` este rețeta de bază pentru stare partajată. Ține guard-ul cât mai puțin. `thread::scope` îți permite să împrumuți date locale fără `Arc`. `RwLock` e potrivit pentru citiri dese. Deadlock-urile rămân responsabilitatea ta.

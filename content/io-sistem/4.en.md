# I/O and the system — Expert

What happens under the I/O API: system calls, buffering strategies, copy optimizations, the operating system's text types and I/O safety for file descriptors.

## Every `read` and `write` is a system call

`File::read` and `File::write` call the operating system directly (`read(2)`, `write(2)` on Linux). A system call usually costs hundreds of nanoseconds. Reading a file byte by byte means millions of such calls. Buffering groups them:

| Type | Strategy |
|---|---|
| `File` | no buffer |
| `BufReader<R>` | reads in chunks of 8 KiB (by default) |
| `BufWriter<W>` | gathers up to 8 KiB, then writes |
| `LineWriter<W>` | flushes on every `\n` |
| `Stdout` | an internal `LineWriter`, always |
| `Stderr` | no buffer |

```rust
use std::io::{BufReader, BufWriter};

fn main() {
    let r = BufReader::with_capacity(64 * 1024, std::io::empty()); // a 64 KiB buffer
    let w = BufWriter::with_capacity(1 << 20, std::io::sink());    // 1 MiB
    println!("{} {}", r.capacity(), w.capacity());
}
```

## `write` may write less than you gave it

`Write::write` returns **how many bytes** it actually wrote, and this number can be smaller than the buffer's length, for example on full sockets or pipes. `write_all` repeats the call until everything is sent. Likewise, `read` may read less than you ask for, and `read_exact` repeats until it fills the buffer:

```rust
use std::io::{self, Write};

// a Write that accepts at most 3 bytes per call, like an almost-full pipe
struct Narrow(Vec<u8>);

impl Write for Narrow {
    fn write(&mut self, buf: &[u8]) -> io::Result<usize> {
        let n = buf.len().min(3);
        self.0.extend_from_slice(&buf[..n]);
        Ok(n)
    }
    fn flush(&mut self) -> io::Result<()> { Ok(()) }
}

fn main() -> io::Result<()> {
    let mut a = Narrow(Vec::new());
    let written = a.write(b"greetings")?;   // writes only part of it
    println!("write: {written} bytes");

    let mut b = Narrow(Vec::new());
    b.write_all(b"greetings")?;              // repeats until the end
    println!("write_all: {:?}", String::from_utf8_lossy(&b.0));
    Ok(())
}
```

A `write` without checking its result is a classic bug. Clippy flags it (`unused_io_amount`).

## `io::copy` and copying in the kernel

`io::copy(&mut source, &mut dest)` copies until the end of the source. On Linux, when both ends are files, pipes or sockets, the standard library automatically uses `copy_file_range`, `sendfile` or `splice`: the data doesn't pass through your process's memory at all.

```rust
use std::io;

fn main() -> io::Result<()> {
    let mut source: &[u8] = b"data to copy";
    let mut dest = Vec::new();
    let n = io::copy(&mut source, &mut dest)?; // here: an ordinary intermediate buffer
    println!("{n} bytes: {}", String::from_utf8_lossy(&dest));
    Ok(())
}
```

## `OsString`: the operating system's text

Operating systems don't guarantee UTF-8 in file names, arguments or environment variables:

- on Unix, they are **arbitrary bytes**, without `\0`;
- on Windows, they are **possibly invalid UTF-16** (unpaired surrogates).

`OsString` / `OsStr` represent exactly these values. On Windows, they're encoded internally as WTF-8, an extension of UTF-8 that can represent unpaired surrogates. Converting to `str` can fail, so it's explicit:

```rust
use std::ffi::OsStr;

fn main() {
    let ok = OsStr::new("report.txt");
    println!("{:?}", ok.to_str());               // Some("report.txt")

    #[cfg(unix)]
    {
        use std::os::unix::ffi::OsStrExt;
        let invalid = OsStr::from_bytes(b"name\xff.txt"); // a valid file name on Linux
        println!("{:?}", invalid.to_str());              // None: not UTF-8
        println!("{}", invalid.to_string_lossy());       // replaces with �
    }

    for arg in std::env::args_os().take(1) {
        println!("native argument: {} bytes", arg.len());
    }
}
```

A program that uses `env::args()` (with `String`) **panics** on an argument that isn't UTF-8. System tools should use `args_os()`.

## I/O safety: file descriptors as types

On Unix, an open file is an integer (a *file descriptor*). As a number, it can be copied, closed twice or used after being closed. Since Rust 1.63, the standard library models them with ownership:

| Type | Equivalent | Meaning |
|---|---|---|
| `OwnedFd` | `Box<T>` | owns the descriptor and closes it on `drop` |
| `BorrowedFd<'a>` | `&'a T` | borrows it for `'a`, without closing it |
| `RawFd` | `*const T` | a plain number; using it requires `unsafe` |

```rust
#[cfg(unix)]
fn main() -> std::io::Result<()> {
    use std::os::fd::{AsFd, AsRawFd, OwnedFd};

    let f = std::fs::File::open("/dev/null")?;
    let borrowed = f.as_fd();                    // BorrowedFd, tied to the life of `f`
    println!("descriptor: {}", borrowed.as_raw_fd());

    let owned: OwnedFd = f.into();               // ownership moves to OwnedFd
    let back = std::fs::File::from(owned);       // and back, without unsafe
    println!("{:?}", back.metadata()?.is_file());
    Ok(())
}

#[cfg(not(unix))]
fn main() {}
```

## Exiting the process and destructors

`std::process::exit(code)` stops the process **immediately**: the variables' destructors no longer run, and unsaved buffers are lost. Returning an `ExitCode` from `main` runs every destructor before exiting:

```rust
use std::io::Write;

struct Save;
impl Drop for Save {
    fn drop(&mut self) {
        println!("drop: saving the state");
    }
}

fn main() -> std::process::ExitCode {
    let _s = Save;
    let mut out = std::io::BufWriter::new(std::io::stdout());
    writeln!(out, "written to the buffer").unwrap();
    // std::process::exit(0); // would lose both the "drop" and the line in the BufWriter
    std::process::ExitCode::SUCCESS // destructors run: the buffer is flushed, Save is destroyed
}
```

The `Termination` trait decides what the value returned by `main` means. It's implemented for `()`, `ExitCode` and `Result<T, E>` with `E: Debug`.

> **Key takeaway:** every `read` / `write` on a `File` is a system call, which is why buffers exist. Stdout is flushed on every line, and stderr has no buffer. `write` can write partially, so use `write_all`. `OsString` represents the operating system's native text. `OwnedFd` / `BorrowedFd` bring ownership to descriptors. `process::exit` skips destructors.

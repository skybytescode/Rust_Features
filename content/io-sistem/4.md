# I/O și sistem — Expert

Ce se întâmplă sub API-ul de I/O: apeluri de sistem, strategiile de buffering, optimizările pentru copiere, tipurile de text ale sistemului de operare și I/O safety pentru descriptori de fișier.

## Fiecare `read` și `write` e un apel de sistem

`File::read` și `File::write` apelează direct sistemul de operare (`read(2)`, `write(2)` pe Linux). Un apel de sistem costă, de obicei, sute de nanosecunde. Citirea unui fișier octet cu octet înseamnă milioane de astfel de apeluri. Buffering-ul le grupează:

| Tip | Strategie |
|---|---|
| `File` | fără buffer |
| `BufReader<R>` | citește în bucăți de 8 KiB (implicit) |
| `BufWriter<W>` | adună până la 8 KiB, apoi scrie |
| `LineWriter<W>` | golește la fiecare `\n` |
| `Stdout` | `LineWriter` intern, întotdeauna |
| `Stderr` | fără buffer |

```rust
use std::io::{BufReader, BufWriter};

fn main() {
    let r = BufReader::with_capacity(64 * 1024, std::io::empty()); // buffer de 64 KiB
    let w = BufWriter::with_capacity(1 << 20, std::io::sink());    // 1 MiB
    println!("{} {}", r.capacity(), w.capacity());
}
```

## `write` poate scrie mai puțin decât i-ai dat

`Write::write` returnează **câți octeți** a scris efectiv, iar acest număr poate fi mai mic decât lungimea buffer-ului, de exemplu la socket-uri sau pipe-uri pline. `write_all` repetă apelul până trimite tot. La fel, `read` poate citi mai puțin decât îi ceri, iar `read_exact` repetă până umple buffer-ul:

```rust
use std::io::{self, Write};

// un Write care acceptă cel mult 3 octeți pe apel, ca un pipe aproape plin
struct Ingust(Vec<u8>);

impl Write for Ingust {
    fn write(&mut self, buf: &[u8]) -> io::Result<usize> {
        let n = buf.len().min(3);
        self.0.extend_from_slice(&buf[..n]);
        Ok(n)
    }
    fn flush(&mut self) -> io::Result<()> { Ok(()) }
}

fn main() -> io::Result<()> {
    let mut a = Ingust(Vec::new());
    let scris = a.write(b"salutare")?;     // scrie doar o parte
    println!("write: {scris} octeți");

    let mut b = Ingust(Vec::new());
    b.write_all(b"salutare")?;             // repetă până la final
    println!("write_all: {:?}", String::from_utf8_lossy(&b.0));
    Ok(())
}
```

Un `write` fără verificarea rezultatului e un bug clasic. Clippy îl semnalează (`unused_io_amount`).

## `io::copy` și copierea în kernel

`io::copy(&mut sursa, &mut dest)` copiază până la sfârșitul sursei. Pe Linux, când ambele capete sunt fișiere, pipe-uri sau socket-uri, biblioteca standard folosește automat `copy_file_range`, `sendfile` sau `splice`: datele nu mai trec deloc prin memoria procesului tău.

```rust
use std::io;

fn main() -> io::Result<()> {
    let mut sursa: &[u8] = b"date de copiat";
    let mut dest = Vec::new();
    let n = io::copy(&mut sursa, &mut dest)?; // aici: buffer intermediar obișnuit
    println!("{n} octeți: {}", String::from_utf8_lossy(&dest));
    Ok(())
}
```

## `OsString`: textul sistemului de operare

Sistemele de operare nu garantează UTF-8 în nume de fișiere, argumente sau variabile de mediu:

- pe Unix, ele sunt **octeți arbitrari**, fără `\0`;
- pe Windows, sunt **UTF-16 posibil invalid** (surogați nepereche).

`OsString` / `OsStr` reprezintă exact aceste valori. Pe Windows, intern sunt codificate WTF-8, o extensie a UTF-8 care poate reprezenta surogații nepereche. Conversia spre `str` poate eșua, deci e explicită:

```rust
use std::ffi::OsStr;

fn main() {
    let ok = OsStr::new("raport.txt");
    println!("{:?}", ok.to_str());               // Some("raport.txt")

    #[cfg(unix)]
    {
        use std::os::unix::ffi::OsStrExt;
        let invalid = OsStr::from_bytes(b"nume\xff.txt"); // nume de fișier valid pe Linux
        println!("{:?}", invalid.to_str());              // None: nu e UTF-8
        println!("{}", invalid.to_string_lossy());       // înlocuiește cu �
    }

    for arg in std::env::args_os().take(1) {
        println!("argument nativ: {} octeți", arg.len());
    }
}
```

Un program care folosește `env::args()` (cu `String`) **dă panic** la un argument care nu e UTF-8. Uneltele de sistem ar trebui să folosească `args_os()`.

## I/O safety: descriptori de fișier ca tipuri

Pe Unix, un fișier deschis e un număr întreg (*file descriptor*). Ca număr, poate fi copiat, închis de două ori sau folosit după închidere. Din Rust 1.63, biblioteca standard le modelează cu ownership:

| Tip | Echivalent | Semnificație |
|---|---|---|
| `OwnedFd` | `Box<T>` | deține descriptorul și îl închide la `drop` |
| `BorrowedFd<'a>` | `&'a T` | îl împrumută pentru `'a`, fără să-l închidă |
| `RawFd` | `*const T` | număr simplu; folosirea lui cere `unsafe` |

```rust
#[cfg(unix)]
fn main() -> std::io::Result<()> {
    use std::os::fd::{AsFd, AsRawFd, OwnedFd};

    let f = std::fs::File::open("/dev/null")?;
    let imprumut = f.as_fd();                    // BorrowedFd, legat de viața lui `f`
    println!("descriptor: {}", imprumut.as_raw_fd());

    let detinut: OwnedFd = f.into();             // ownership-ul trece la OwnedFd
    let inapoi = std::fs::File::from(detinut);   // și înapoi, fără unsafe
    println!("{:?}", inapoi.metadata()?.is_file());
    Ok(())
}

#[cfg(not(unix))]
fn main() {}
```

## Ieșirea din proces și destructorii

`std::process::exit(cod)` oprește procesul **imediat**: destructorii variabilelor nu mai rulează, iar buffer-ele nesalvate se pierd. Returnarea unui `ExitCode` din `main` rulează toți destructorii înainte de ieșire:

```rust
use std::io::Write;

struct Salvare;
impl Drop for Salvare {
    fn drop(&mut self) {
        println!("drop: salvez starea");
    }
}

fn main() -> std::process::ExitCode {
    let _s = Salvare;
    let mut out = std::io::BufWriter::new(std::io::stdout());
    writeln!(out, "scris în buffer").unwrap();
    // std::process::exit(0); // ar pierde și „drop”, și linia din BufWriter
    std::process::ExitCode::SUCCESS // destructorii rulează: buffer-ul e golit, Salvare e distrus
}
```

Trait-ul `Termination` decide ce înseamnă valoarea returnată de `main`. E implementat pentru `()`, `ExitCode` și `Result<T, E>` cu `E: Debug`.

> **De reținut:** fiecare `read` / `write` pe `File` e un apel de sistem, de aceea există bufferele. Stdout e golit la fiecare linie, iar stderr nu are buffer. `write` poate scrie parțial, deci folosește `write_all`. `OsString` reprezintă textul nativ al sistemului de operare. `OwnedFd` / `BorrowedFd` aduc ownership peste descriptori. `process::exit` sare peste destructori.

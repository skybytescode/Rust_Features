# Closures și iteratori — Avansat

Cum îți scrii propriii iteratori, cum îi faci compatibili cu `for` și cum păstrezi closures de tipuri diferite în aceeași colecție.

## Propriul iterator

Implementezi `Iterator` cu o singură metodă, `next`. Toate celelalte (peste 70: `map`, `filter`, `sum`…) vin gratuit:

```rust
struct Fibonacci {
    a: u64,
    b: u64,
}

impl Iterator for Fibonacci {
    type Item = u64;

    fn next(&mut self) -> Option<u64> {
        let rezultat = self.a;
        (self.a, self.b) = (self.b, self.a.checked_add(self.b)?); // se oprește la overflow
        Some(rezultat)
    }
}

fn fibonacci() -> Fibonacci {
    Fibonacci { a: 0, b: 1 }
}

fn main() {
    let primele: Vec<u64> = fibonacci().take(10).collect();
    let suma_pare: u64 = fibonacci().take_while(|&x| x < 4_000_000).filter(|x| x % 2 == 0).sum();
    println!("{primele:?}\n{suma_pare}");
    println!("elemente produse până la primul overflow: {}", fibonacci().count());
}
```

## `IntoIterator`: compatibilitate cu `for`

Ca `for x in &colectia_ta` să funcționeze, implementezi `IntoIterator` pentru `&ColectiaTa`:

```rust
struct Playlist {
    melodii: Vec<String>,
}

impl<'a> IntoIterator for &'a Playlist {
    type Item = &'a String;
    type IntoIter = std::slice::Iter<'a, String>;

    fn into_iter(self) -> Self::IntoIter {
        self.melodii.iter()
    }
}

fn main() {
    let p = Playlist { melodii: vec!["Intro".into(), "Refren".into()] };
    for m in &p {
        println!("♪ {m}");
    }
}
```

## Iteratori din closures

Pentru cazuri simple nu trebuie să definești un struct. Poți construi iteratorul direct dintr-un closure:

```rust
use std::iter;

fn main() {
    let puteri: Vec<u32> = iter::successors(Some(1u32), |&x| x.checked_mul(3)).take(6).collect();
    println!("{puteri:?}");

    let mut stare = 1;
    let dubluri = iter::from_fn(|| {
        stare *= 2;
        (stare < 100).then_some(stare)
    });
    println!("{:?}", dubluri.collect::<Vec<_>>());

    let repetat: String = iter::repeat("ab").take(3).collect();
    println!("{repetat}");
}
```

## Trait-uri suplimentare

| Trait | Îți dă |
|---|---|
| `DoubleEndedIterator` | `rev()`, `next_back()`: parcurgere de la coadă |
| `ExactSizeIterator` | `len()`: numărul exact de elemente rămase |
| `FusedIterator` | garantează că după primul `None` urmează doar `None` |

`peekable()` îți permite să te uiți la următorul element fără să-l consumi. E util în parsere:

```rust
fn grupeaza(v: &[i32]) -> Vec<(i32, usize)> {
    let mut rezultat = Vec::new();
    let mut it = v.iter().peekable();
    while let Some(&x) = it.next() {
        let mut n = 1;
        while it.peek() == Some(&&x) {
            it.next();
            n += 1;
        }
        rezultat.push((x, n));
    }
    rezultat
}

fn main() {
    println!("{:?}", grupeaza(&[1, 1, 2, 3, 3, 3, 1]));
}
```

## Closures de tipuri diferite în aceeași colecție

Fiecare closure are un tip unic. Ca să le pui în același `Vec`, le transformi în obiecte trait cu `Box<dyn Fn>`:

```rust
fn main() {
    let operatii: Vec<(&str, Box<dyn Fn(f64) -> f64>)> = vec![
        ("dublu", Box::new(|x| x * 2.0)),
        ("pătrat", Box::new(|x| x * x)),
        ("plus offset", {
            let offset = 0.5;
            Box::new(move |x| x + offset)
        }),
    ];
    for (nume, op) in &operatii {
        println!("{nume}(3) = {}", op(3.0));
    }
}
```

## Captură disjunctă (ediția 2021+)

Un closure capturează doar **câmpurile** de care are nevoie, nu întreaga structură. Poți modifica un câmp în timp ce un closure îl folosește pe altul:

```rust
struct Joc {
    scor: u32,
    jucatori: Vec<String>,
}

fn main() {
    let mut joc = Joc { scor: 0, jucatori: vec!["Ana".into()] };
    let afiseaza = || println!("jucători: {:?}", joc.jucatori); // capturează doar `joc.jucatori`
    joc.scor += 10; // permis
    afiseaza();
    println!("scor: {}", joc.scor);
}
```

## Iteratorii nu sunt mai lenți decât buclele

Un lanț ca `v.iter().filter(...).map(...).sum()` este compilat la aceeași buclă pe care ai scrie-o manual, uneori chiar mai bună, pentru că lipsesc verificările de limite. E una dintre cele mai citate **abstracțiuni cu cost zero** din Rust.

> **De reținut:** implementezi doar `next` și primești toată familia de metode. `IntoIterator` pentru `&T` face tipul compatibil cu `for`. `from_fn` și `successors` creează iteratori fără struct, iar `Box<dyn Fn>` pune closures diferite în aceeași colecție.

# Closures și iteratori — Expert

Ce generează compilatorul pentru un closure, cum devine un lanț de iteratori o singură buclă și ce optimizări specializate există în biblioteca standard.

## Un closure este un struct anonim

Pentru fiecare closure, compilatorul generează un tip anonim. Variabilele capturate devin câmpurile lui, iar trait-urile `Fn*` sunt implementate pe el. Mărimea closure-ului este mărimea capturilor:

```rust
fn main() {
    let a = 5u8;
    let b = [0u64; 4];
    let s = String::from("x");

    let nimic = || 1;
    let prin_ref = || a + 1;             // capturează &u8
    let prin_valoare = move || b.len();  // capturează [u64; 4]
    let cu_string = move || s.len();     // capturează String

    println!("{}", size_of_val(&nimic));        // 0
    println!("{}", size_of_val(&prin_ref));     // 8: o referință
    println!("{}", size_of_val(&prin_valoare)); // 32
    println!("{}", size_of_val(&cu_string));    // 24
    let _ = (nimic(), prin_ref(), prin_valoare(), cu_string());
}
```

Echivalentul scris manual pentru `prin_ref` arată aproximativ așa. Pe stable nu poți implementa singur trait-urile `Fn*`, dar poți scrie o metodă echivalentă:

```rust
struct ClosurePrinRef<'a> {
    a: &'a u8,
}

impl ClosurePrinRef<'_> {
    // compilatorul ar genera `impl Fn<()> for ...` cu `call(&self)`
    fn call(&self) -> u8 {
        *self.a + 1
    }
}

fn main() {
    let a = 5u8;
    let c = ClosurePrinRef { a: &a };
    println!("{}", c.call());
}
```

Ierarhia este `Fn: FnMut: FnOnce`. Orice `Fn` poate fi apelat și acolo unde se cere `FnMut` sau `FnOnce`.

## Coerciția la pointer de funcție

Un closure **fără capturi** are mărimea zero și poate fi convertit în `fn`. Cu capturi, conversia nu e posibilă, pentru că un pointer de funcție nu are unde să păstreze datele:

```rust
fn main() {
    let f: fn(i32) -> i32 = |x| x + 1; // OK: nicio captură
    println!("{}", f(1));
}
```

```rust,compile_fail
fn main() {
    let k = 10;
    let f: fn(i32) -> i32 = |x| x + k; // eroare E0308: closure-ul capturează `k`
    println!("{}", f(1));
}
```

## Cum devine un lanț de iteratori o buclă

`v.iter().map(f).filter(g).sum()` construiește un tip imbricat, de forma `Filter<Map<slice::Iter<T>, F>, G>`, în care closures sunt câmpuri cu tipuri cunoscute. Fiecare `next()` apelează `next()` pe stratul interior. Cum tipurile sunt concrete, LLVM inline-uiește totul într-o singură buclă, fără apeluri de funcții.

Mai mult, multe adaptoare suprascriu `fold` / `try_fold`. Metodele consumatoare (`sum`, `for_each`, `count`) folosesc **iterarea internă**, prin `fold`, în locul apelurilor repetate la `next()`. `Chain`, de exemplu, poate parcurge cele două jumătăți cu două bucle separate, fără să verifice la fiecare pas în care se află.

## `TrustedLen` și `collect`

Când știe exact câte elemente va produce un iterator, `collect::<Vec<_>>()` alocă **o singură dată** și scrie direct, fără verificări de capacitate. Informația vine de la `size_hint()` și de la trait-ul intern `TrustedLen`:

```rust
fn main() {
    let it = (0..1000).map(|x| x * 2);
    println!("{:?}", it.size_hint()); // (1000, Some(1000)): exact

    let v: Vec<i32> = it.collect();
    println!("len {}, capacitate {}", v.len(), v.capacity()); // fără realocări

    let filtrat = (0..1000).filter(|x| x % 3 == 0);
    println!("{:?}", filtrat.size_hint()); // (0, Some(1000)): doar o limită superioară
}
```

## Colectare în loc (*in-place iteration*)

`v.into_iter().map(...).collect::<Vec<_>>()` poate **refolosi** alocarea vectorului original dacă tipul rezultat încape în același spațiu. Optimizarea e internă și nu e garantată, dar o poți observa:

```rust
fn main() {
    let v: Vec<u32> = (0..1000).collect();
    let ptr_inainte = v.as_ptr() as usize;

    let w: Vec<u32> = v.into_iter().map(|x| x * 2).filter(|x| x % 4 == 0).collect();
    let ptr_dupa = w.as_ptr() as usize;

    println!("aceeași alocare: {}", ptr_inainte == ptr_dupa);
    println!("{}", w.len());
}
```

## Closures `async` și capturare în ediția 2024

Din Rust 1.85, closures pot fi `async`: `async || { ... }`. Implementează trait-urile `AsyncFn`, `AsyncFnMut` și `AsyncFnOnce`, iar viitorul returnat poate împrumuta din capturile closure-ului. Cu `|| async { ... }`, asta nu era posibil. Detalii în capitolul Async/await.

> **De reținut:** un closure e un struct anonim cu capturile drept câmpuri, iar mărimea lui e mărimea capturilor. Doar closures fără capturi devin `fn`. Lanțurile de iteratori se compun din tipuri concrete, deci LLVM le inline-uiește într-o buclă. `TrustedLen` și colectarea în loc elimină alocările inutile.

# Closures and iterators — Advanced

How to write your own iterators, how to make them work with `for`, and how to keep closures of different types in the same collection.

## Your own iterator

You implement `Iterator` with a single method, `next`. All the others (more than 70: `map`, `filter`, `sum`…) come for free:

```rust
struct Fibonacci {
    a: u64,
    b: u64,
}

impl Iterator for Fibonacci {
    type Item = u64;

    fn next(&mut self) -> Option<u64> {
        let result = self.a;
        (self.a, self.b) = (self.b, self.a.checked_add(self.b)?); // stops on overflow
        Some(result)
    }
}

fn fibonacci() -> Fibonacci {
    Fibonacci { a: 0, b: 1 }
}

fn main() {
    let first: Vec<u64> = fibonacci().take(10).collect();
    let even_sum: u64 = fibonacci().take_while(|&x| x < 4_000_000).filter(|x| x % 2 == 0).sum();
    println!("{first:?}\n{even_sum}");
    println!("elements produced before the first overflow: {}", fibonacci().count());
}
```

## `IntoIterator`: working with `for`

For `for x in &your_collection` to work, you implement `IntoIterator` for `&YourCollection`:

```rust
struct Playlist {
    songs: Vec<String>,
}

impl<'a> IntoIterator for &'a Playlist {
    type Item = &'a String;
    type IntoIter = std::slice::Iter<'a, String>;

    fn into_iter(self) -> Self::IntoIter {
        self.songs.iter()
    }
}

fn main() {
    let p = Playlist { songs: vec!["Intro".into(), "Chorus".into()] };
    for s in &p {
        println!("♪ {s}");
    }
}
```

## Iterators from closures

For simple cases you don't need to define a struct. You can build the iterator directly from a closure:

```rust
use std::iter;

fn main() {
    let powers: Vec<u32> = iter::successors(Some(1u32), |&x| x.checked_mul(3)).take(6).collect();
    println!("{powers:?}");

    let mut state = 1;
    let doublings = iter::from_fn(|| {
        state *= 2;
        (state < 100).then_some(state)
    });
    println!("{:?}", doublings.collect::<Vec<_>>());

    let repeated: String = iter::repeat("ab").take(3).collect();
    println!("{repeated}");
}
```

## Extra traits

| Trait | Gives you |
|---|---|
| `DoubleEndedIterator` | `rev()`, `next_back()`: iteration from the back |
| `ExactSizeIterator` | `len()`: the exact number of remaining elements |
| `FusedIterator` | guarantees that after the first `None` only `None` follows |

`peekable()` lets you look at the next element without consuming it. It's useful in parsers:

```rust
fn group(v: &[i32]) -> Vec<(i32, usize)> {
    let mut result = Vec::new();
    let mut it = v.iter().peekable();
    while let Some(&x) = it.next() {
        let mut n = 1;
        while it.peek() == Some(&&x) {
            it.next();
            n += 1;
        }
        result.push((x, n));
    }
    result
}

fn main() {
    println!("{:?}", group(&[1, 1, 2, 3, 3, 3, 1]));
}
```

## Closures of different types in the same collection

Each closure has a unique type. To put them in the same `Vec`, you turn them into trait objects with `Box<dyn Fn>`:

```rust
fn main() {
    let operations: Vec<(&str, Box<dyn Fn(f64) -> f64>)> = vec![
        ("double", Box::new(|x| x * 2.0)),
        ("square", Box::new(|x| x * x)),
        ("plus offset", {
            let offset = 0.5;
            Box::new(move |x| x + offset)
        }),
    ];
    for (name, op) in &operations {
        println!("{name}(3) = {}", op(3.0));
    }
}
```

## Disjoint capture (2021 edition+)

A closure captures only the **fields** it needs, not the whole struct. You can modify one field while a closure uses another:

```rust
struct Game {
    score: u32,
    players: Vec<String>,
}

fn main() {
    let mut game = Game { score: 0, players: vec!["Ana".into()] };
    let show = || println!("players: {:?}", game.players); // captures only `game.players`
    game.score += 10; // allowed
    show();
    println!("score: {}", game.score);
}
```

## Iterators aren't slower than loops

A chain like `v.iter().filter(...).map(...).sum()` compiles to the same loop you'd write by hand, sometimes even a better one, because the bounds checks are gone. It's one of the most quoted **zero-cost abstractions** in Rust.

> **Key takeaway:** you implement only `next` and get the whole family of methods. `IntoIterator` for `&T` makes the type work with `for`. `from_fn` and `successors` create iterators without a struct, and `Box<dyn Fn>` puts different closures in the same collection.
